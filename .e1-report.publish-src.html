微调做了什么

与 baseline 的唯一变量 = 梯度是否回流到特征侧
骨干facebook/dinov2-giant（ViT-g/14，hidden 1536，40 层），原始预训练权重冷启动，整体冻结并转 fp16
LoRAr = 16 / α = 16 / scaling = 1.0；注入 q、k、v、output.dense，共 160 个投影；B 置零、A kaiming 初始化
可训练量10.82M（LoRA 7.86M + 时序头 ≈2.96M），占 1.1B 主干的 <1%；其余全部 requires_grad=False
数值精度主干 fp16 autocast；LoRA 与时序头保持 fp32 主权重（fp16 前向、fp32 更新）
时序头Phase6 bridge transformer：1 层 / 6 头 / 双向注意力，输入 3072 = CLS 1536 + Δdiff 1536
窗口 / 批window 64 帧 / stride 16（2 窗口每视频）；batch 2
优化器AdamW，lr 1e-4 / weight_decay 0.01，梯度裁剪 1.0
损失逐帧三元交叉熵 + 逆频类权重 [1.318, 1.545, 0.137]（按全 80 帧统计，非窗口重叠计数）
轮数3 epochs（28,800 步 / 42.3h）；--early_stop_patience 0 跑满，按 val 选 best
数据全量 train 9,600 视频（seed 42 打散；2,000 ⊂ 6,000 ⊂ 9,600 嵌套）
评估全量 test 1,200 视频 / 230,400 帧；主结果 = val-selected best

04

实行的优化清单

执行 16 项 · 明确未做 3 项

① 工程手段

7 项 · 让 9,600 端到端跑得起来
  • 梯度 checkpointing：128 帧/步，不开必 OOM实做
  • 混合精度：主干 fp16 + LoRA/头 fp32 主权重实做
  • Δdiff 帧间差分特征（承接 baseline）实做
  • 逆频类权重（全 80 帧统计）实做
  • 紧凑 checkpoint：MB 级，可 resume 续训实做
  • mp4 现解码 + 16 workers：免 96GB 磁盘缓存实做
  • torch.compile：与 DINOv2 + 梯度 checkpointing 不兼容，首个前向 TypeError否决

② 替代方案验证 A–H

8 项 · 为省 E1-full 成本
  • A 冻头换更好的头证伪 · 天花板 0.63
  • B 帧级扩数据 2,000 → 9,600证伪 · 下游近零
  • C RuleV2 事件后处理证伪 · 近冗余
  • D 课程采样砍窗口否决 · 删 normal = 删精度保护
  • E 小骨干 dinov2-base 端到端证伪 · 0.630 < 0.645
  • F E3 权重热启动否决 · 对必要性零信息
  • G 蒸馏软标签喂冻头证伪 · 0.608 < 0.632
  • H E1@6000 数据轨迹绿 · 立项条件满足
八个替代解释逐一关闭 → 唯一没被证伪的增益来源 = 端到端范式 × 更多数据。

③ 零训练诊断（原 E2）

1 项 · 秩截断探针
  • SVD 截断 r=16 → 8 → 4：砍掉 75% 可训练参数，全部指标变动落在 ±0.042 内，fall_prec 反而单调 +0.042实做
秩大幅过剩、容量从未构成瓶颈 → r=32 一端关闭；"全量微调不升级"由间接推断升级为实测支撑。

④ 明确未做

3 项 · 均有判定理由
  • dropout / lr 消融：单 seed 噪声地板高于效应量未做
  • 全量微调：触发条件"容量不足"未满足；代码中从未实现该路径未做
  • 特征锚定正则：规划过，代码中从未写入；实际 loss 只有 CE + 类权重未做

计数口径：①中 torch.compile 计入"执行"（起了、按闸门判死），故执行项 = 7 + 8 + 1 = 16；其中 8 项被否决或证伪（compile + A–G），8 项成立（6 工程 + H + 秩截断诊断）。

05

诚实边界

写论文必须一并写进去的部分
结论边界 · 5 条
  • "全面新最优"不成立：立项时定的 3 条成功判据只通过 1 条 —— fallen_prec 0.7551 PASS（贴线）｜fall_rec 0.8305 FAIL（差 0.02）｜raw 事件 F1 0.8269 FAIL（差 0.003）。
  • 静态轴未超自己更早的检查点：fallen_prec 0.7551 < E1@6000 的 0.795 —— 同一数据轨迹内，6,000 视频的 best 在静态轴上反而更高。
  • 数据红利在 6,000 附近见顶：6,000 → 9,600 只剩 +0.012 avg_f1，事件轴与召回已饱和；且红利有轴依赖性，不是所有轴一起涨。
  • 主对比不是单变量对照：baseline 配方与 E1 不同（stride 8 vs 16、lr 1e-3 vs 1e-4、49 轮 vs 3 轮、batch 32 vs 2），本页读数是"范式 + 配方"的整体差异；其中 stride 的影响已单独实测 ≤ 0.005。
  • val 不可用于跨 checkpoint 选静态轴：val 只测每视频头窗前 64 帧（27% 的 fallen 帧落在从不被覆盖的尾部），且 val→test 的 fallen_rec gap 在不同 ckpt 间从 0.13 摆到 0.36。主结果取 val-selected best，但该选择对静态轴不可靠。
06

E3 的定位

辅证 · 不参与主对比

E3 回答"为什么必须做 E1"，E1 回答"做了值多少"

辅证

E3 是什么：它是给 baseline 换特征提取器的两阶段帧级 LoRA —— 把 baseline 用的"原始冻结 DINOv2-giant"换成"帧级 LoRA 微调过的 DINOv2-giant"，下游的 Δdiff 与 Phase6 bridge 头逐项不动。 一句话：E3 只动了 baseline 的特征侧，而且是"逐帧"（单帧、无时序）动的。

微调对象baseline 的特征提取器本身：原始冻结的 DINOv2-giant → 帧级 LoRA 微调后的 DINOv2-giant
Stage1冻结主干 + LoRA(rank 16, q/k/v/o, 7.86M) + Linear(1536→3) 头；逐帧（单帧输入、不带任何时序）三元 CE + 类权重；batch 16 / 5 epochs / lr 1e-4
微调数据2,000 训练视频 × 10 帧 = 20,000 帧（按类打散采样，非窗口）
Stage2用微调骨干重抽 12,000 视频的逐帧 CLS → 新 NPZ，再走与 baseline 逐项相同的 Δdiff + Phase6 bridge 头（训练集 9,600，与 E1 同量）

① 它把瓶颈定位到静态轴：动态轴帧级可学（fall_rec 0.792 → 0.842，+0.050），静态轴单帧不可学（fallen_prec 0.627 → 0.619，噪声级且方向为负）。 结论是"静态 lying-vs-fallen 只在时间序列里有前因可循"→ 时序整合是唯一出路，E1 正是据此立项的。

② 它与 E1 的唯一变量就是训练范式：E3 在帧级改特征（每帧独立，没有时序、没有前因），E1 在窗口级端到端改特征（梯度穿过 64 帧窗口一路反传）—— 这一条正是 E1 的设计依据，也是两者可直接对照的原因。

③ A–H 中的 B / E / G 也是"用便宜手段替代端到端"的尝试（帧级扩数据、小骨干、蒸馏），逐一被证伪 —— 从反面支撑了 E1 的必要性。

④ 等数据参照（仅为辅证）：同为 9,600 训练数据时，E1 相对 E3-full 静态轴 +0.136、avg_f1 +0.058；而在 2,000 数据上两者只差 +0.013。 差距随数据放大，说明端到端能把更多数据转成静态轴精度，两阶段不能。

本节数值不进入主对比表，也不用于 E1 的结论判读 —— E3 是 E1 立项理由的存档，不是 E1 的成绩单。
