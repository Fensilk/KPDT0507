# 0712 实验第五阶段规划：损失函数权重调优

## 1. 背景

Phase 4（DINOv2 + Transformer）全部实验使用默认权重 `(w_cls=1.0, w_fall=0.5, w_fallen=0.5)`，未做过任何权重调优。Phase 3 在 TCN 上扫了 16 组权重，没有一组击败默认值——但 Transformer 架构不同，结论不一定可迁移。本阶段通过 6 组单变量对照实验，确认标量权重对 fall/fallen 指标是否有 **≥3%** 的实质影响。

## 2. 基线

| 实验 | 模型 | w_cls | w_fall | w_fallen | fall_f1 | fallen_f1 | avg_f1 |
|------|------|-------|--------|----------|---------|-----------|--------|
| p4a_dino_baseline | ViT-L, T=32 | 1.0 | 0.5 | 0.5 | 0.660 | 0.591 | 0.626 |

## 3. 实验矩阵

**原则**: 每次只动一个系数，其余保持默认值。共 6 组新实验。

| # | 实验名 | w_cls | w_fall | w_fallen | 测试假设 |
|---|--------|-------|--------|----------|---------|
| 0 | baseline | 1.0 | 0.5 | 0.5 | H0: 默认最优（已完成） |
| 1 | **cls_down** | **0.3** | 0.5 | 0.5 | H1: 降 cls 占比，释放 fall/fallen 梯度 |
| 2 | **cls_up** | **2.0** | 0.5 | 0.5 | H1 反向: cls 信号被低估 |
| 3 | **fall_down** | 1.0 | **0.2** | 0.5 | H2: 压低 fall 误报 → Precision↑ |
| 4 | **fall_up** | 1.0 | **1.0** | 0.5 | H2 反向: 增强 fall 召回 → Recall↑ |
| 5 | **fallen_down** | 1.0 | 0.5 | **0.2** | H3: 压低 fallen 误报 → Precision↑ |
| 6 | **fallen_up** | 1.0 | 0.5 | **1.0** | H3 反向: 增强 fallen 召回 → Recall↑ |

### 待验证假设

| 假设 | 描述 | Phase 3 相关证据 |
|------|------|-----------------|
| H0 | 默认 `(1.0, 0.5, 0.5)` 在局部最优，任何改动 ↓ | 16 组无一超越 |
| H1 | `L_cls` 占总量 ~80%，压住了 fall/fallen 信号 | p3d_cls05 跌 5.5pp |
| H2 | fall 瓶颈是 Precision 低 (0.60)，降权重可抑制假阳 | p3d_fall07 跌 6.4pp |
| H3 | fallen 瓶颈是 Precision 低 (0.54)，同 H2 逻辑 | p3d_fallen07 跌 8.6pp |

### 有效权重参考

BCEWithLogitsLoss 内部 `pos_weight ≈ 25x`，乘以任务权重后的有效正样本放大倍数：

| 实验 | w_fall × pos_weight | w_fallen × pos_weight |
|------|--------------------|-----------------------|
| 默认 | 0.5 × 25 = **12.5x** | 0.5 × 25 = **12.5x** |
| *_down | 0.2 × 25 = **5.0x** | — |
| *_up | 1.0 × 25 = **25.0x** | — |

## 4. 固定配置

与 Phase 4 完全一致：

| 参数 | 值 |
|------|-----|
| 特征 | DINOv2 ViT-L/14, 1024-dim, fp16, 完全冻结 |
| 序列长度 | T=32 (~1.28s @25fps) |
| 滑窗步长 | stride=8 (75% overlap) |
| 训练窗口 | ~67,200 (9600 视频 × 7 窗口) |
| 模型 | Transformer 1L/384d/6head, drop=0.3, Pre-LN |
| 参数量 | ~2.2M |
| 类别数 | 16（不 remap rare） |
| 优化器 | AdamW, lr=1e-3, weight_decay=1e-4 |
| 调度器 | ReduceLROnPlateau, patience=6, factor=0.5 |
| 早停 | val fall_f1, patience=15 |
| FP16 | torch.cuda.amp.autocast |
| 梯度裁剪 | clip_grad_norm = 1.0 |
| 损失公式 | `L = w_cls * L_cls + w_fall * L_fall + w_fallen * L_fallen` |
| 采样器 | WeightedRandomSampler（默认开启） |
| 种子 | 42 |
| GPU | NVIDIA RTX 3090 (24GB) |

## 5. 判定逻辑

| 结果 | 结论 | 后续行动 |
|------|------|---------|
| 任一组 fall_f1 ≥ **0.680** (+3%) | 权重调优对 Transformer 有效 | 以优势方向为中心扩大网格搜索 |
| 某方向呈单调趋势（如降 w_fall → fall_f1↑） | 存在可优化的方向 | 沿该方向追加极端值实验 |
| 全部 < 基线，但在 ±1% 内 | 权重不敏感 | 关闭标量权重方向 |
| 全部显著低于基线 (>2pp) | 默认值恰好是局部最优 | 关闭并记录为负结果，Phase 3 结论跨架构成立 |

## 8. Phase 5b: 模块消融 — 特征提取器 × 时序模型 贡献拆分

### 背景

Phase 4 确立了 DINOv2 + Transformer 的最优组合，但缺少 DINOv2+TCN 这一关键对照组——无法拆分特征提取器 (DINOv2 vs ResNet18) 和时序模型 (Transformer vs TCN) 各自的贡献。

### 2×3 消融矩阵

| | TCN (T=32, h=256) | Transformer (T=32, h=384) |
|---|---|---|
| ResNet18 (512) | **p5b_rn18_tcn** ← 待跑 | p4a_rn18 (0.545) |
| DINOv2 ViT-L (1024) | **p5b_dino_tcn** ← 待跑 | p4a_dino (0.660) |
| DINOv2 ViT-g (1536) | **p5b_dinog_tcn** ← 待跑 | p4d_vitg (0.657) |

3 组新实验。能回答的四个问题：

1. **特征贡献**: DINOv2 vs ResNet18，固定 TCN → 纵向比较
2. **架构贡献**: TCN vs Transformer，固定特征 → 横向比较
3. **ViT-g 增益来源**: 依赖 Transformer attention 还是特征本身？
4. **交互效应**: 强特征 + 强架构是否有超线性收益？

### 固定配置

| 参数 | 值 |
|------|-----|
| 序列长度 | T=32，stride=8（与 Phase 4 一致） |
| TCN hidden_dim | 256（~2.2M 参数，与 Transformer 对齐） |
| 损失权重 | 默认 (1.0, 0.5, 0.5) |
| 优化器 | AdamW, lr=1e-3, weight_decay=1e-4 |
| 调度器 | ReduceLROnPlateau, patience=6, factor=0.5 |
| 早停 | val fall_f1, patience=15 |
| Batch size | 32 |
| 种子 | 42 |

### TCN 对 T=32 的自动适配

TCNModel 根据 `window_size=32` 自动计算膨胀卷积 `[1,2,4,8,16]`，感受野 63，覆盖完整序列。

### Bug 修复

`train_tcn.py:453` 原本硬编码 `input_dim=512`，导致 DINOv2 (1024/1536-dim) 特征无法传入。已改为 `train_loader.dataset.feature_dim` 动态获取。
