# 第九阶段 E1 端到端小结（2026-09-04）

> 承接 docs/0902实验第九阶段总结.md（E3 分解诊断）。本文件记录 E1 端到端实验及其
> **受控对照 E3@2000** 的最终结果：在**同批 2,000 训练视频**下比较"端到端 LoRA 反传"与
> "两阶段·冻特征"，回答 E3 留下的问题——端到端时序反传能否解锁静态轴。

---

## 1. 背景与要回答的问题

- 三元分类 **fall（正在倒）/ fallen（倒后倒地）/ normal（含故意躺下 lying）**。
- 最难的是 **fallen vs lying（静态轴）**：单帧上看，倒在地上与故意躺下无法区分；
  唯一差异是**历史**——fallen 的"前因"是一次 fall。该信息只在时间序列里存在。
- E3（帧级两阶段）结论：动态轴帧级可学（fall_rec 0.842），静态轴单帧不可学
  （fallen_prec 0.619 不升）→ 时序整合是唯一出路 → 做 E1。

**E1 假设**：把 LoRA 微调的 ViT-g 与时序头**端到端联合训练**，让特征在 64 帧窗口内
学会携带"跌倒前因"，从而把静止的 fallen 和 lying 分开（fallen_prec 突破 0.619）。

## 2. 实验设计

| 维度 | E1 | E3@2000（新增受控） | E3 全量（参考） |
|---|---|---|---|
| 特征 | dinov2-giant 原始 + **LoRA r16 q/k/v/o** | E3 stage1 微调特征（冻结） | E3 stage1 微调特征（冻结） |
| 训练 | **端到端**（LoRA+头联合反传） | 头在冻特征上训（两阶段） | 头在冻特征上训 |
| 训练视频 | 2,000（seed42，同 E3 stage1 批） | **同一 2,000** | ~9,600（全量 train） |
| 时序头 | Phase6 transformer bridge（1层/6头/Δdiff 3072） | 同左 | 同左 |
| 训练窗口 | 64 / **stride 16**（2 窗口/视频） | 64 / **stride 16**（对齐 E1） | 64 / stride 8 |
| test 评估 | 64 / **stride 8**（230,400 帧实例） | 64 / **stride 8**（同口径） | 64 / stride 8 |
| 损失 | 逐帧 CE + 逆频类权重 | Phase6 CE/加权采样 | 同左 |
| 轮数 | 5 epochs（无早停，best 按 val 峰值） | 100 cap / patience 15 | 100 cap / patience 15 |

> 设计要点：E1 vs E3@2000 的**唯一变量 = 训练范式**（端到端 vs 冻特征），数据、窗口、
> 评估口径全部对齐。为此给 train_phase6.py 加了 `--eval_stride`（训 16 / 测 8 解耦），
> 给 E3@2000 造了与 E1 完全相同的 2,000 训练 split。

**为什么补 E3@2000**：原 E3 参考数字（fall_rec 0.842 / fallen_prec 0.619）其时序头是在
全量 ~9,600 视频上训的，而 E1 只有 2,000 → 直接用 E1@2000 比 E3 全量**数据量不对称**，
无法干净归因"范式"。补一个同数据的 E3@2000 才能拆开这个变量。

## 3. 结果（全量 test，230,400 帧实例，同口径）

| 指标 | baseline | E3 全量 | **E3@2000** | **E1@2000(5ep)** |
|---|---|---|---|---|
| fall_precision | 0.592 | 0.594 | 0.572 | **0.680** |
| fall_recall | 0.792 | 0.842 | 0.714 | 0.709 |
| fall_f1 | 0.678 | 0.696 | 0.635 | 0.694 |
| fallen_precision | 0.627 | 0.619 | 0.632 | **0.645** |
| fallen_recall | 0.698 | 0.701 | 0.617 | 0.630 |
| fallen_f1 | 0.661 | 0.658 | 0.624 | 0.637 |
| avg_f1 | 0.764 | 0.769 | 0.737 | **0.763** |
| ternary_acc | 0.908 | 0.907 | 0.901 | **0.915** |

**受控对比（唯一变量 = 范式）：E1 vs E3@2000**

| | E3@2000 | E1@2000(5ep) | Δ |
|---|---|---|---|
| **fallen_prec**（静态轴） | 0.632 | **0.645** | **+0.013** |
| fall_prec | 0.572 | **0.680** | **+0.108** |
| fall_rec | 0.714 | 0.709 | −0.005（持平） |
| avg_f1 | 0.737 | **0.763** | **+0.026** |
| ternary_acc | 0.901 | **0.915** | **+0.014** |

**E1 收敛要点**（monitor，val 为 150-video 头窗子集口径）：
- best = step 6,000（epoch 3 末）：val_avg_f1 **0.866**、val_fallen_prec **0.859**。
- epoch 4 后 val 未再刷新 best（precision↔recall 摆荡，fallen_rec 在 0.53-0.82 间波动）。
- 全程 5 epochs / 10,000 步 / ~14.7h 跑满（非早停）。

## 4. 结论

1. **静态轴假设成立（受控）**：同数据下 E1 fallen_prec 0.645 全面占优
   ——高于 E3@2000(0.632)、E3 全量(0.619)、baseline(0.627)。端到端在同等数据下
   确实比两阶段更会区分 fallen/lying，且 fall_prec(+0.108) 与整体(avg_f1 +0.026)同步改善。

2. **fall_rec ≥ 0.82 的目标在 2,000 数据下对任何范式都不现实**：E1(0.709) 与 E3@2000
   (0.714) 都够不到——0.82 是按 E3 全量(9,600 视频)定的。**这是纯数据量效应，不是范式问题。**

3. **真正瓶颈是训练数据量，不是训练范式**：同等 2,000 下，端到端 ≥ 两阶段且多数指标更好；
   但要追平 E3 全量的 fall_rec 0.84 / avg_f1 0.77，缺的是另外 ~7,600 个视频，而不是换方法。

## 5. 过程教训（影响结论可信度的关键点，务必写入最终报告）

- **数据量不对称**：E1@2000 直接对比 E3 全量（9,600 训的时序头）不公平 → 补 E3@2000 后
  才得到干净范式结论。任何"范式 vs 数据量"的归因都必须数据同量。
- **早停造成的假象**：E1 第一轮用 patience=2 早停，在 ~1.5 epoch 被掐断，全量 test
  fallen_prec 仅 0.506、fall_rec 0.612——**欠训练的废数字**。跑满 5 epoch 后 fallen_prec
  升到 0.645。教训：结论必须基于跑满/收敛的模型（train_p9e1 现已支持
  `--early_stop_patience 0`）。
- **val 监控口径偏乐观**：E1 的 val 监控只用每视频前 64 帧（stride80 单窗口），从不测
  尾部 64-79 帧；而 27% 的 fallen 帧在尾部、其中 94.9% 的 fall 前因落在 [0,15]（唯一覆盖
  尾部的窗口 [16,80] 不含前因）→ val fallen_prec 高估。test 全 80 帧评估才是真值。
  教训：监控口径与评估口径必须一致。
- **训练步长与评估步长耦合**：E1 训 16 / 测 8 靠两个脚本解耦；train_phase6 原一个
  `--stride` 训测绑死。已加 `--eval_stride` 解耦。
- **E1 训练窗口 stride16 是"加速史"产物**（从 8 提到 16 省 1/3），非科学主动选择；
  它让每轮样本更少、中段帧冗余更低，对 2,000 数据上的过拟合是雪上加霜。

## 7. 后续可选方向

- **数据量轴（E4 方向）**：结果强烈指向数据量为主瓶颈。若资源允许，E1 全量
  （~9,600 视频端到端，估 ~70h）或 E3@2000 与 E3 全量之间的中间数据量，是决定性一步。
- E1 可加 epoch/正则（dropout/lr）看摆荡与过拟合。
- RuleV2 等后处理规则未在 E1 上重测；事件级指标（event_f1）可另算。
