# 0706 实验第四阶段规划：DINOv2 特征提取 + Transformer 时序模型

## 1. 背景与目标

### 1.1 当前第三阶段最优方案

```
特征: RGB(ResNet18, 512-dim) + Δclip(512-dim) + Pose(99-dim) → 拼接后 TCN 时序建模
数据层级: Clip 级 (每视频 5 clips, 80 帧 → 5 × 16帧聚合)
时序: TCN (因果膨胀卷积, 感受野=7)
性能: seg_acc=0.539, fall_f1=0.598, fallen_f1=0.597, avg_f1=0.598 (p3a_diff_pose)
瓶颈: ResNet18 的语义表征能力受限于 ImageNet 监督预训练; TCN 感受野固定, 无法自适应建模长程依赖
```

### 1.2 第四阶段要做什么

用 **DINOv2**（自监督 ViT）替代 ResNet18 做空间特征提取，用 **FeatureTransformer**（袭用 `modelX.py` 的 Transformer 架构）替代 TCN 做时序建模。

**关键架构决策：从 Clip 级切换到帧级**。DINOv2 是逐帧特征提取器，保留完整的 80 帧/视频序列，通过滑窗生成训练样本。这保留了帧间细粒度时序信息，让 Transformer 在真正的帧序列上建模。

| 组件 | 第三阶段 (Clip 级) | 第四阶段主线 (帧级) | 第四阶段可选 |
|------|-------------------|--------------------|-------------|
| 空间特征提取 | ResNet18 (512-dim) | **DINOv2 ViT-L/14 (1024-dim)** | ViT-g/14 (1536-dim) |
| 特征层级 | Clip (5/video) | **Frame (80/video) → 滑窗** | — |
| 时序模型 | TCN (因果卷积) | **Transformer (1层, 384-dim)** | Transformer (2-4层, 768-dim) |
| 辅助特征 | Δclip + Pose | 逐步消融添加 | Δclip + Pose 全量 |
| 序列长度 | T=5 (clips) | **T=32 (frames, ~1.28s)** | T=16 |

### 1.3 为什么这样做

- **DINOv2 的优势**: 自监督在 142M 张图上预训练，语义表征泛化性远强于 ResNet18 的 ImageNet 监督特征；ViT 的 patch-level 特征保留了更丰富的空间信息
- **帧级特征的優勢**: DINOv2 天然逐帧工作，保留 80 帧的完整时序信息；滑窗灵活控制 T 和 stride，不受固定 clip 边界约束；帧间差分 (Δframe) 捕获更精细的运动信号
- **Transformer 的优势**: Self-Attention 在 T=32 上充分发挥长程建模能力（32×32 attention 矩阵，覆盖中位 fall 事件 1.12s）；逐帧预测时进行全局上下文建模
- **窗口长度依据**: 帧级分析显示 fall 中位持续 28 帧 (1.12s)，T=32 可完整覆盖 57% 的 fall 事件，显著优于 T=16 的 21%
- **保守架构优先**: 数据集规模中等（~9600 训练视频，滑窗后 ~67K 训练窗口），先从参数量最小的保守配置起步，验证核心假设后再扩展

### 1.4 过拟合风险评估

| 配置 | 参数量 | 训练窗口数 (T=32, stride=8) | 样本/参数比 | 过拟合风险 |
|------|--------|---------------------------|------------|-----------|
| TCN 当前 (clip 级基线) | ~0.9M | 48,000 | 53:1 | 低 |
| **Transformer 保守 (主线)** | **~4M** | **67,200** | **17:1** | **低** 🟢 |
| Transformer 中等 (2L/768d) | ~16M | 67,200 | 4.2:1 | 中-低 🟡 |
| Transformer 激进 (4L/768d + ViT-g) | ~30M | 67,200 | 2.2:1 | 中-高 🔴 |

> **策略**: 主线实验全部使用 🟢 保守配置。帧级滑窗 (T=32, stride=8) 比 clip 级多了 40% 的训练样本，缓解了部分过拟合压力。主线通过后再用可选实验（Phase 4d）探索高风险配置的边际收益。

## 2. 技术路线

### 2.1 总体流水线

```
每个视频 (80 帧, H×W×3)
    │
    ▼  Stage A: 冻结 DINOv2 ViT-L/14, 逐帧提取 (预处理, 离线)
┌──────────────────────────────┐
│  for each frame in 80 frames:│
│    DINOv2 ViT-L/14 → [1024]  │  ← 冻结, fp16 加速
│  → 每视频: [80, 1024]        │
│  → 全量:  [960000, 1024]     │
└──────────────────────────────┘
    │
    ▼  保存为 data/omnifall_dinov2_frame.npz
    │  (对齐现有 omnifall_frame_preprocessed.npz 结构)
    │
    ▼  Stage B: 滑窗 + FeatureTransformer 时序建模 (训练)
┌──────────────────────────────┐
│  LongSequenceDataset:        │
│    滑窗 T=32, stride=8       │
│    → 每视频 7 个窗口          │
│    → 每个窗口 [32, 1024]     │
│                              │
│  RGB DINOv2:   [32, 1024]    │──→ Linear(1024→384)            ← 主线: 仅 RGB
│  Δframe diff:  [32, 1024]    │──→ Linear(1024→384)  (可选)     ← Phase 4b
│  Pose:         [32, P]       │──→ Linear(P→384)     (可选)     ← Phase 4b
│                              │
│  → 拼接 → [32, 384×N]        │
│  → PositionalEncoding        │
│  → TransformerEncoder (1层)  │   ← 主线: 1层, 384-dim
│  → 不池化, 逐帧输出 (T=32)   │
│  → 3 Heads: cls(16) + fall(1) + fallen(1)  │
└──────────────────────────────┘
```

> **与 Phase 3 的层级差异**: Phase 3 在 clip 级 (T=5) 操作，每个 clip 是 16 帧的聚合；Phase 4 直接在帧级 (T=32) 操作，每个 token 是单帧的 DINOv2 特征。T=32 覆盖 1.28s 窗口，可完整包含中位 fall 事件 (1.12s)。

### 2.2 模型实现

新建 `models/transformer_model.py`（不复用 `modelX.py` 的 Wrapper，但袭用其 `PositionalEncoding` 和 Pre-LN Transformer 架构范式）：

```python
# models/transformer_model.py (新建)
class MultimodalFeatureTransformer(nn.Module):
    """
    DINOv2 + 可选辅助特征 → Transformer → 多任务逐帧预测
    
    主线配置: hidden_dim=384, num_layers=1, num_heads=6, dropout=0.3
    输入: features [B, T, D_total]  (主线: T=32, D_total=1024)
    输出: (logits_cls [B,T,16], logits_fall [B,T,1], logits_fallen [B,T,1])
    
    接口对齐 TCNModel((B,T,D) → (cls,fall,fallen))，训练脚本改动最小。
    """
    
    def __init__(self, input_dim, hidden_dim=384, num_layers=1, 
                 num_heads=6, dropout=0.3, mlp_ratio=4.0, max_len=100):
        self.input_proj = nn.Linear(input_dim, hidden_dim)
        self.input_norm = nn.LayerNorm(hidden_dim)
        self.pos_encoder = PositionalEncoding(hidden_dim, max_len=max_len)
        encoder_layer = TransformerEncoderLayer(
            d_model=hidden_dim, nhead=num_heads,
            dim_feedforward=int(hidden_dim * mlp_ratio),
            dropout=dropout, batch_first=True, norm_first=True
        )
        self.transformer = TransformerEncoder(encoder_layer, num_layers)
        self.head_cls = nn.Linear(hidden_dim, 16)
        self.head_fall = nn.Linear(hidden_dim, 1)
        self.head_fallen = nn.Linear(hidden_dim, 1)
    
    def forward(self, features):  # features: [B, T, D_total]
        x = self.input_norm(self.input_proj(features))
        x = self.pos_encoder(x)
        x = self.transformer(x)          # [B, T, hidden_dim]
        return (self.head_cls(x),        # [B, T, 16]
                self.head_fall(x),       # [B, T, 1]
                self.head_fallen(x))     # [B, T, 1]
```

| 参数 | 主线默认值 | 说明 |
|------|-----------|------|
| `input_dim` | 自动获取 | 1024 (仅 DINOv2) 或更大 (加 diff/pose) |
| `hidden_dim` | **384** | 保守选择，每头 64-dim |
| `num_layers` | **1** | 单层在 T=32 上已能捕获帧间依赖，过深易过拟合 |
| `num_heads` | **6** | 384 / 64 = 6 heads (标准配置) |
| `dropout` | **0.3** | 强正则化，对抗过拟合 |
| `mlp_ratio` | 4.0 | FFN = 1536-dim |
| `max_len` | 100 | 支持 T ≤ 100 (覆盖 80 帧全序列) |

> **设计决策**: 新建文件而非改 modelX.py。接口对齐 TCNModel（`(B,T,D) → (cls,fall,fallen)`），训练脚本改动最小。

### 2.3 Pose 帧级 NPZ 生成（预处理脚本）

**改动极简**——step5 已经存储了每视频的帧级 `.pt` 文件 (`(80, 99)`/video)，只需一个新的聚合脚本跳过 clip 池化：

## 3. 实验设计

### 3.1 实验矩阵

分四个子阶段。主线为 4a → 4b → 4c（保守配置），4d 为可选的高风险探索。

**共享设定**: 所有主线实验使用帧级 NPZ + `LongSequenceDataset`，默认 `window_size=32, stride=8`。

#### Phase 4a: 特征提取器验证（固定保守 Transformer）

> **目的**: 单独验证 DINOv2 ViT-L vs ResNet18 的特征质量差异。使用最简配置，排除所有辅助特征干扰。

| 实验 ID | 特征 | NPZ | 时序模型 | Diff | Pose |
|---------|------|-----|---------|------|------|
| `p4a_rn18_baseline` | ResNet18 (512) | `omnifall_frame_preprocessed.npz` | Transformer (1L/384d) | ✗ | ✗ |
| `p4a_dino_baseline` | **DINOv2 ViT-L (1024)** | `omnifall_dinov2_frame.npz` | Transformer (1L/384d) | ✗ | ✗ |

> **核心对比**: `p4a_rn18_baseline` vs `p4a_dino_baseline`。在完全相同的 Transformer 架构和帧级数据上，DINOv2 比 ResNet18 好多少？这是整个 Phase 4 最关键的 A/B 实验。
>
> **成功标准**: `p4a_dino_baseline` 的 **fall_f1 ≥ 0.65**（P3 最优 = 0.598，目标 +5.2pp）。若 4a 达不到 0.65，说明单纯的 DINOv2 替换不足以带来显著收益，需要依赖 4b 的辅助特征或 4c 的架构精调来补足。
>
> 与 Phase 3 (clip 级, avg_f1=0.598) 的对比是**非严格公平**的（层级不同），但可以作为参考。严格对比留到 Phase 4d 做全量配置 vs P3 最优。

#### Phase 4b: 辅助特征消融（固定 DINOv2 ViT-L + 保守 Transformer）

> **目的**: 验证帧间差分 (Δframe) 和 Pose 在 DINOv2 特征空间中的增量价值。

| 实验 ID | 特征 | Diff | Pose | 输入维度 | 参数量 |
|---------|------|------|------|---------|--------|
| `p4b_dino` (同 4a) | DINOv2 ViT-L (1024) | ✗ | ✗ | 1024 | ~4.0M |
| `p4b_dino_diff` | DINOv2 ViT-L (1024) | ✓ Δframe (1024) | ✗ | 2048 | ~4.4M |
| `p4b_dino_pose` | DINOv2 ViT-L (1024) | ✗ | ✓ (99d) | 1123 | ~4.0M |
| `p4b_dino_diff_pose` | DINOv2 ViT-L (1024) | ✓ Δframe (1024) | ✓ (99d) | 2147 | ~4.5M |

> **关键问题**: 
> - Δframe（帧间差分）在 DINOv2 的语义空间中是否有意义？与 clip 间差分不同，帧间变化更微小、更细粒度
> - DINOv2 已经隐式编码了姿态和运动信息，显式 Pose 还能带来增益吗？
>
> **决策阈值**（基于 Phase 3 的 fall_f1 epoch 间波动 std≈0.004，2σ≈0.008）：
>
> | 4b 结果 (Δfall_f1 vs p4b_dino) | 判断 | 行动 |
> |--------------------------------|------|------|
> | Δ < **0.010** | 噪声级，Pose+Diff 无效 | 摘掉，4c 用纯 DINOv2 |
> | Δ = **0.010~0.015** | 边际显著 | 4c 同时测纯 DINOv2 和全量两组 |
> | Δ > **0.015** | 明确有价值 | 保留 Pose+Diff 进 4c |

#### Phase 4c: Transformer 架构微调（固定最优特征配置）

> **目的**: 从保守 baseline 出发，逐步增加容量，找到收益-风险平衡点。

搜索顺序（从小到大，遇过拟合即停）：

| 实验 ID | hidden_dim | num_layers | num_heads | dropout | 参数量 | 风险 |
|---------|-----------|------------|-----------|---------|--------|------|
| `p4c_base` | 384 | 1 | 6 | 0.3 | ~4-5M | 🟢 主线基线 |
| `p4c_h768` | **768** | 1 | 8 | 0.3 | ~8M | 🟢 |
| `p4c_L2` | 384 | **2** | 6 | 0.3 | ~8M | 🟡 |
| `p4c_L2h768` | 768 | 2 | 8 | 0.2 | ~16M | 🟡 |
| `p4c_drop01` | 384 | 1 | 6 | **0.1** | ~4-5M | 🟡 (正则化减弱) |

> **搜索策略**: 始终从最简配置开始。记录各组 train/val loss gap 作为过拟合诊断依据。只在 train-val gap 未显著扩大时尝试更大配置。

#### Phase 4d (可选): 高风险高回报探索

> **触发条件**: Phase 4c 最优配置的 train-val gap < 0.1 且 val loss 仍有下降趋势。

| 实验 ID | 特征 | 时序模型 | T | 说明 |
|---------|------|---------|---|------|
| `p4d_vitg` | DINOv2 **ViT-g/14** (1536) | Transformer (4c 最优架构) | 32 | ViT-g vs ViT-L 边际收益 |
| `p4d_large` | DINOv2 ViT-L (1024) | Transformer (**2-4层, 768-dim**) | 32 | 大容量 Transformer |
| `p4d_T16` | DINOv2 ViT-L (1024) | Transformer (4c 最优架构) | **16** | 短窗口消融：验证 T=32 是否必要 |
| `p4d_full` | ViT-g + diff + pose | Transformer (大容量) | 32 | 全量最强配置，与 P3 最优做最终对比 |

## 5. 预期收益与风险

### 5.1 预期收益

| 收益项 | 来源 | 预期幅度 |
|--------|------|---------|
| seg_acc 提升 | DINOv2 更强的语义特征 + 帧级细粒度信息 | +3~8% |
| fall_f1 提升 | Transformer 在 T=32 上的长程建模 (覆盖 1.28s 窗口) + DINOv2 对运动的隐式编码 | +5~10% |
| fallen_f1 提升 | Self-attention 全局上下文捕获倒地后持续状态 | +5~10% |
| 跷跷板缓解 | Self-Attention 多尺度建模 → fall/fallen 共享更好的中间表示 | gap 缩小 |

### 5.2 风险与对策

| 风险 | 可能性 | 对策 |
|------|--------|------|
| DINOv2 逐帧提取耗时过长 | 中 | fp16 + batch inference (batch_size=16)；预计 ~4h / 960K 帧 |
| 帧级 NPZ 文件过大 (~2GB) | **中** | fp16 存储；Git LFS 追踪；可考虑 mmap 模式加载 (已有) |
| 小数据集上 Transformer 过拟合 | **中** 🟡 | 主线用 1L/384d/drop0.3；帧级滑窗 (T=32, stride=8) 相比 clip 级多 40% 样本；4c 从小到大搜索遇过拟合即停 |
| Δframe 在 DINOv2 特征空间无意义 | 中 | Phase 4b 消融单独验证；如无增益则不加 diff |
| Pose 被 DINOv2 隐式编码，显式 concat 无增益 | 低-中 | 同上，4b 消融验证 |
| T=32 仍不能覆盖极端长的 fall 事件 (P90=80帧) | 低 | T=32 @25fps = 1.28s，已覆盖 57% 的 fall；极长事件 (P90+) 必然跨窗，非模型缺陷 |
| Transformer 训练不稳定 | 低 | Pre-LN (norm_first=True) + gradient clipping (已有) |
| LongSequenceDataset 不支持 diff/pose | **确定** | 步骤 3 扩展 dataset.py（~30 行改动） |

## 7. 已确认决策

1. ✅ **DINOv2 模型选择**: 主线用 **ViT-L/14 (1024-dim)**。ViT-g/14 (1536-dim) 放入 Phase 4d
2. ✅ **特征层级**: **帧级提取，保留 80 帧/视频**，不做 clip 聚合。主线滑窗 **T=32, stride=8** (覆盖中位 fall 1.12s)
3. ✅ **Δframe 差分**: 主线不含 diff，通过 Phase 4b 消融验证帧间差分的增量价值
4. ✅ **Pose 融合方式**: 主线用简单 concat。Cross-attention 融合留待后续探索
5. ✅ **训练策略**: DINOv2 完全冻结，不参与训练
6. ✅ **FP16**: 特征提取 + 训练全程启用
7. ✅ **默认架构**: **1 层、384-dim、dropout=0.3**，从保守配置起步
8. ✅ **数据集**: 扩展 `LongSequenceDataset` 添加 diff 和 pose 支持
