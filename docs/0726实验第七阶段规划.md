# 实验第七阶段规划 — 事件级因果 + lying/fallen 消歧

## 一、动机：Phase 6 的重新审视

### P6 的核心错误

Phase 6 将"因果约束"理解为**帧级因果**——每一帧只能看过去，不能看未来。这在逐帧实时预测场景下是正确的，但**跌倒检测不是逐帧实时任务**。

跌倒检测的告警逻辑天然允许缓冲窗口：

```
缓冲 T 帧 → 窗口内双向推理 → 检测 fall→fallen 序列 → 告警
延迟 ≤ T 帧（~2秒），完全可接受
```

这意味着**窗口内的双向注意力是合法的**——它不"作弊"，因为部署时你本来就在缓冲。它只是在窗口内部把"看到 fallen 后回推到前面确认 fall"这个过程模型化了。

### 帧级因果 vs 事件级因果

| | 帧级因果（P6） | 事件级因果（P7） |
|---|---|---|
| 约束对象 | 每帧不能看未来帧 | fall 事件必须发生在 fallen 之前 |
| 窗口内注意力 | mask 掉未来 | 双向（合法） |
| 跨窗口信息 | 无 | **核心设计对象** |
| 适用场景 | 零延迟逐帧输出 | 缓冲窗口后告警 |
| 对 lying/fallen 的区分 | 不解决——lying 视频里本来就没有 fall | **解决——查跨窗口历史中有没有过 fall** |

### P6 数据确认的 lying/fallen 混淆

对 p6_bridge 在测试集上的逐帧分析（按原始 16 类标签拆解）：

```
normal→fallen 误报 8,930 帧:
  lying 贡献 54.0%（4,826 帧）——压倒性第一来源

normal→fall 误报 6,493 帧:
  lie_down 贡献 16.0%（1,037 帧）——"主动躺下"视觉上像"开始倒"

lying + lie_down 合计 = 42.1% 的所有假警报（6,494/15,423）
```

**结论：lying 和 fallen 的单帧视觉特征完全相同，任何模型都无法仅靠窗口内信息区分。** 区分它们需要跨越窗口边界的信息——"这个人在过去一段时间里有没有摔倒过？"

## 二、核心思路：事件级因果 + 跨窗口记忆

### 事件因果链

```
正常活动 → fall（摔倒动作）→ fallen（倒地状态）
lie_down → lying（躺地状态，无 fall 前因）

区分逻辑：
  当前帧 = "人在地上"
  → 往前查：过去 K 秒内出现过 fall 帧？
    有 → fallen（确认跌倒，告警）
    没有 → lying/normal（不告警）
```

这与注意力方向无关。窗口内双向注意力是合法的，关键是**跨窗口的事件记忆**。

### 部署逻辑

```
实时流 → 缓冲 64 帧窗口
      → 双向推理（Bridge 或等效模型）
      → 对每个窗口：
          检测到 fallen 帧 → 查 fall 事件缓存
            fall 缓存命中（过去 2 秒内有 fall）→ 告警
            fall 缓存未命中 → 判定为 lying，不告警
      → 更新 fall 事件缓存（记录有 fall 帧的时间窗口）
```

## 三、实验设计

### A. 规则化事件门控（零训练成本）

最直接的跨窗口方案：不训模型，只在 Bridge 的输出上加规则后处理。

**p7a_event_rule：**

```
输入：p6_bridge 的逐帧三分类预测
规则：
  1. 滑动检测：连续 ≥3 帧 fall  → 标记为 fall_event 的开始
  2. fall 事件缓存：记录最近 N 秒（N=2,3,5 可调）内是否有 fall_event
  3. 重标逻辑：
     - 模型预测 fallen + fall 缓存命中  → 保持 fallen（确认真跌倒）
     - 模型预测 fallen + fall 缓存未命中 → 改判 normal（疑似 lying）
     - 模型预测 normal 但有 fall_event      → 不强制改判（允许 normal 中有其他动作）
```

评估：对 test set 的逐帧预测做后处理，对比原始 Bridge 的混淆矩阵变化。
- 关键指标：fallen 的 precision 提升幅度；lying 的 →fallen 误报下降幅度
- 潜在代价：部分"无前序 fall 的残缺窗口"中的真实 fallen 被错误修改
  - P6 规划中分析过：T=64 下残缺 fallen 窗口仅 8.6%，影响有限

**这个实验回答：零成本的事件规则能提升多少？如果提升显著，说明"跨窗口查 fall"这个方向是对的，值得投入训练资源。**

### B. 双窗口联合推理

**p7b_dualwin：**

```
输入：[Window_{t-1} | Window_t] → 拼接为 T=128 序列
模型：Phase6TernaryModel, T=128, bidirectional
      → 模型在前 64 帧和后 64 帧之间做双向注意力
      → 相当于让模型显式看到"前一个窗口有没有 fall"
```

| 参数 | 值 |
|------|-----|
| 窗口配对 | (W_{n-1}, W_n)，步长=8（与 stride 对齐） |
| 训练数据 | ~18K 窗口对（~36K 窗口配对为 18K 对） |
| 架构 | 与 p6_bridge 相同，仅 T=64→128 |
| 对比基线 | p6_bridge (T=64) |

**这个实验回答：让模型直接看到跨窗口边界的 fall→fallen 序列，能比 64 帧窗口多捕捉多少信息？**

### C. 梯度化事件记忆（可训练）

**p7c_event_memory：**

```
架构：
  DINOv2 ViT-g → Linear → PE → Bidirectional Transformer (T=64)
    → Temporal Pool → [fall_event_detector]
    → LSTM Event Memory → 拼入逐帧特征
    → 三分类

关键模块：
  1. fall_event_detector: 对 Transformer 输出做 lightweight 二分类
     （是否为 fall_event 帧？），训练时用 fall 标签监督
  2. LSTM Event Memory: 接收 pooled window embedding，维护跨窗口 hidden state
     输出 "过去 N 个窗口发生过 fall 吗" 的编码
  3. 融合：将 memory 输出拼入每帧特征，再做最终三分类
```

| 参数 | 值 |
|------|-----|
| Memory dim | 128（压缩的事件状态） |
| Memory LSTM | 1 层, 128d |
| 训练策略 | 两阶段——先预训练 fall_event_detector，再联合训练 |
| 对比基线 | p6_bridge |

**这个实验回答：可训练的跨窗口记忆能在 Bridge 基础上再提升多少？**

## 四、实验矩阵

| ID | 类型 | 核心思路 | 训练成本 | 预期 fall_f1 | 预期 fallen_precision 提升 |
|----|------|---------|---------|-------------|--------------------------|
| p6_bridge | 基线（已有） | 双向 T=64, 无跨窗口 | 已跑 | 0.684 | 基线 |

## 五、可选辅助实验

### D. 数据层面——lying 降权/移除

如果 lying 帧是误报主要来源且视觉上与 fallen 不可区分，可以试探：

**p7d_lying_mask（零训练成本，仅改 loss）：** 训练时对 lying 帧的 loss 乘以 0（不学习 lying），消除 lying 对模型判断"人在地上→normal"的拉扯。

评估：看 fallen 分类边界是否变清晰（fallen_f1 是否上升），以及 lying 帧的预测分布变化。

### E. 标签细化

**p7e_four_class：** 将 lying 从 normal 中拆出，变成四分类（fall / fallen / lying / normal_其他）。
- 让模型诚实面对 lying vs fallen 的区别
- 后处理时 lying 和 fallen 合并告警策略另定

## 六、优先级

| 优先级 | 实验 | 理由 |
|--------|------|------|
| **1** | p7a_event_rule | 零成本验证事件因果方向是否正确。如果规则后处理能显著降 lying→fallen，整个 P7 方向就被确认 |
| 2 | p7b_dualwin | T=128 双向，改动最小，直接检验跨窗口边界的信息增益 |
| 3 | p7c_event_memory | 可训练的事件记忆，上限最高但成本也最高 |
| 4 | p7d_lying_mask | 快速验证数据层面方案的可行性 |
| 5 | p7e_four_class | 如以上均不理想，考虑标签层面重构 |

## 七、评估重点

| 指标 | 为什么重要 |
|------|-----------|
| **fallen_precision** | 直接衡量 lying→fallen 误报的抑制效果（P7 核心目标） |
| **lying→fallen 降幅** | 按原始 16 类标签拆解的细粒度指标 |
| fall_f1 | 不能因抑制 lying 误报而牺牲 fall 检出 |
| fallen_recall | 不能因 lying 重标而漏掉真实 fallen |
