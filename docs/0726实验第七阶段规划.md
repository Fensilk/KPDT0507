> 经由 `/grill-me` 质询后定稿。p7a 四项规则测试完成，事件级 RuleV1 确认有效（lying→fallen −55.3%）。p7b 事件门控退化（标签密度 99.6%）。下一步 p7c：Ternary vs Binary 消融——去掉 fall/fallen 区分子任务，验证容量是否被浪费在区分 fall/fallen 上。

## 一、P6 教训与 P7 方向

### P6 核心错误

将"因果约束"理解为帧级因果。跌倒检测可承受 ≤2 秒缓冲，窗口内双向注意力合法。

| | 帧级因果（P6） | 事件级因果（P7） |
|---|---|---|
| 约束对象 | 每帧不能看未来 | fall→fallen 顺序 |
| 窗口内 | 因果 mask | 双向 |
| lying/fallen | 不解决 | 扫描 fall→fallen 序列 |

### P6 证据

| 发现 | 数据 |
|------|------|
| Bridge vs 最优因果 fall_f1 | 0.684 vs 0.615（−6.9pp） |
| T=64 被 T=32 消融确认 | T=32 全面退步 −8.0pp |
| Lying = 54% normal→fallen | 单帧不可分 |

### Bridge 预测质量

| 指标 | 值 |
|------|-----|
| GT fall 碎片化率 | 4.7% |
| Fall 连续性（最长/GT） | 中位数 1.00 |
| Last fall → first fallen 间隔 | 中位数 1 帧，91.7% ≤4 帧 |

## 二、核心思路：事件因果

```
fall→fallen → 事件确认。lying→fallen（孤立，无 fall 前因）→ 压制。
```

### Test 3：RuleV2（fallen 触发 + 因果回查 + 视频上下文）→ ✅ 最优规则

RuleV2 相比 RuleV1 有三项核心改进：

**1. Fallen 触发 + 因果回查**：事件由 `fallen` 帧触发，回查前 W 帧寻找 ≥K2 帧连续 `fall`。因果方向从 RuleV1 的"fall 开门等 fallen"改为"fallen 回头验证 fall"——更贴合物理因果逻辑。

**2. Fall 作为事件边界**：事件在 `fallen` 之后的下一个 `fall` 帧结束——下一次跌倒动作天然分隔两次事件，不需要人工 timeout。兜底用 GT 最长 fallen 序列长度（80 帧）防止极端情况。

**3. 视频级上下文感知**：若视频内 `pred=fall < K1`（即连 K1 帧 fall 都凑不齐），跳过规则压制。这保护了纯 `fallen` 类视频（录制时人已倒地）不被因果约束误杀。

**算法**：

```
FOR each video:
    n_fall = count(pred==fall), n_fallen = count(pred==fallen)
    IF n_fallen == 0 → 跳过（无事可做）
    IF n_fall < K1 AND n_fallen ≥ 8 → 跳过（纯 fallen 视频，信任模型）

NORMAL state:
    逐帧累积连续 fall 计数
    遇到 fallen → 回查前 W 帧，存在 ≥K2 帧连续 fall？
      ├─ 是 → IN_EVENT（事件起点 = 回查到的连续 fall 第一帧）
      └─ 否 → 此 fallen 为孤立帧 → 改判 normal

IN_EVENT state:
    遇到 fallen → 保持，不触发新回查
    遇到 fall   → 事件结束，此 fall 开始新累积
    超时（GT最长fallen序列）→ 事件结束
```

**参数**：K1=2（上下文跳过阈值），K2=7（连续 fall 触发阈值），W=64（回查窗口）。

**p7d_delta + RuleV2 结果**：

| 指标 | p7d raw | p7d + RuleV1(k=5) | p7d + RuleV2(2,7) | vs RuleV1 |
|------|:--:|:--:|:--:|:--:|
| event_f1 | 0.756 | 0.763 | **0.774** | **+0.011** |
| fallen_f1 | 0.657 | 0.662 | **0.692** | **+0.030** |
| event_precision | 0.687 | 0.736 | 0.721 | −0.016 |
| event_recall | 0.840 | 0.791 | **0.835** | **+0.043** |
| false_events | 5,315 | 3,934 | 4,492 | +558 |

**K1×K2 调参结论**：K1 越小越好（保守跳过），K2=7~8 最优（严格因果约束反而提升 fallen_f1——被拒绝的"弱事件"里 fallen 多半是假阳性）。W ≥ 48 后饱和，取 64。

## 五、后续方向

### A. p7c_binary_event — 二分类事件检测（下一步）

**动机**：Ternary 模型把容量花在区分 fall/fallen 上。但事件检测不需要这层区分——fall→fallen 的 1,200 帧互混在 binary 视角下都是正确预测。

```
Ternary: fall_f1=0.699, fallen_f1=0.628
Binary（合并后）: event_f1=0.737（+3.8pp / +10.9pp vs fall/fallen）
```

**假设**：去掉 fall/fallen 区分 → 模型容量 100% 投入 event vs normal → event_precision 提升。

**实验**：Ternary vs Binary 纯消融——唯一差异是输出头。

| 维度 | Ternary（p6_bridge） | Binary（p7c） |
|------|------|------|
| 输出头 | Linear(384→3) | Linear(384→2) |
| 标签 | fall=0, fallen=1, normal=2 | event=0, normal=1 |
| 参数量 | 2.37M | 2.37M（少 384） |
| 其他 | 完全相同 | 完全相同 |

**评估**：
1. Binary event_precision / recall vs Bridge（binary 合并视角）
2. 按 16 类拆解假 event 来源
3. 核心诊断：lying→event 是否减少

#### p7c 结果（2026-08-04 已跑）

| 指标 | Bridge（binary 视角） | p7c Binary | 变化 |
|------|:--:|:--:|:--:|
| event_f1 | 0.737 | 0.753 | +1.6pp |
| event_precision | 0.648 | 0.660 | +1.2pp |
| event_recall | 0.856 | 0.875 | +1.9pp |
| lying→event | 13.8% | 12.9% | **几乎不变** |
| lie_down→event | 12.4% | 9.3% | −25% 相对 |

**结论：Ternary→Binary 容量释放真实但微小。lying→event 几乎纹丝不动——瓶颈在 ViT-g 特征层，不在任务设计。p7c 的价值是排除了这条路径。**

### B. p7d_delta — Δframe 运动特征（已跑）

**触发条件已满足**：p7c 确认特征层是瓶颈。

**实验设计**：p6_bridge + Δframe 特征，与 p6_bridge 唯一差异是输入维度。

| 维度 | p6_bridge | p7d_delta |

| 输入特征 | ViT-g 1536d | ViT-g 1536d + Δframe 1536d |
| 输入维度 | 1536 | 3072 |
| 参数量 | 2.37M | 2.96M（+592K） |
| 训练 | CE + pos_weight, T=64 | 相同 |

| 类别 | p6_bridge | p6 + R1 | p7d_delta | **p7d + R1** | vs p6+R1 |
|------|:--:|:--:|:--:|:--:|:--:|

**核心发现**：

1. **p7d 基线假 event 总量已比 p6_bridge 少 18.5%**（6,354→5,180）——Δframe 在未加规则时已经在压制假报警，尤其是 other（−36.8%）和 lie_down（−32.7%）

3. **other→event 是单类最大改善**（926 vs 1,518，−39%）——Δframe 对"其他"杂乱动作的过滤效果最显著
4. Phase 4b 用 ViT-L + Δframe 跌 2.6pp 的结论被推翻——ViT-g 下 Δframe 是正优化。可能原因：ViT-g 更强的外观特征 + Δframe 运动特征形成互补，而 ViT-L 特征不够强导致 Δframe 噪声占比高
