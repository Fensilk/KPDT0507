# 第八阶段规划（正式版）

## 一、背景与诊断结论

Phase 7 的 p7d_delta（ViT-g + Δframe + RuleV2）达到 event_f1=0.774，但 lying→event 假阳性仍是主要瓶颈。

Phase 8 前期诊断（对 test 集 1200 视频做逐样本推理 + 人工检查 25 个假阳性视频）揭示了**两个独立的模型失效模式**：

| 失效模式 | 表现 | 混淆率 | 病因 |
|---------|------|--------|------|
| **静态混淆** | 人躺着不动被判 fallen | lying 帧 12.3% | 躺姿 ≈ 倒地姿态，纯外观无法区分 |
| **过渡混淆** | 主动躺下被判跌倒 | lie_down 帧 5.8% | 躺下速度 ≈ 跌倒速度（中位 2.65s vs 1.75s） |

**关键结论**：
1. 数据是**干净的**——人工检查确认无标签错误，混淆是真实的模型能力瓶颈
2. 本质是**时间维度信息缺失**：ViT-g 静态特征 + 一阶 Δframe 不足以区分"躺卧"与"倒地"
3. 两个失效模式成因不同，需**不同特征**分别应对

**Baseline**：p7d_delta（ViT-g + 一阶 Δframe + RuleV2），event_f1=0.774，avg_f1=0.764

## 二、方向 1：二阶差分（加速度）

**定位**：针对"过渡混淆"——跌倒 vs 主动躺下的本质区别是**突然性**（jerk），而非速度。

- 当前 Δframe 只做一阶差分（速度）：`diff[t] = feat[t] - feat[t-1]`
- 新增二阶差分（加速度）：`accel[t] = feat[t+1] - 2·feat[t] + feat[t-1]`
- 输入拼接：`[feat, diff, accel]`，维度 1536 → 4608

**理由**：跌倒有"突然开始加速下坠"的急变，主动躺下是平滑受控的。加速度信号是一阶速度差分补不了的。Phase 7 已用双向 attention（bridge mode），中心差分（用到 feat[t+1]）合法。

## 三、方向 3：姿态关键点

**定位**：同时针对"静态混淆"（躺姿 vs 倒地姿态的关节配置差异）和"过渡混淆"（受控下降 vs 失控坠落的轨迹差异）。

**分步开展**：
1. **探针实验（先做）**：用 MediaPipe Pose（33 关键点，无需训练）提取派生特征，单独训练轻量模型，看纯姿态特征能拿到多少 F1
   - 若纯姿态 F1 ≥ 0.5 → 姿态携带 ViT-g 之外的信息，值得集成
   - 若纯姿态 F1 很低 → ViT-g 已隐含姿态信息，方向 3 收益小
2. **派生特征**（约 10-15 维标量）：
   - 头部高度（相对髋部中点）、髋部离地高度
   - 躯干倾角（肩-髋连线 vs 垂线）
   - bbox 高宽比
   - 上述量的速度 + 加速度
3. **集成方式**：小 MLP 10-15d → 64d，concat 到 ViT-g 的 384d 投影后（384 → 448d），避免被 1536d 淹没

## 四、方向 2：光流（降级为备选）

**定位**：原本列为方向 2，但诊断显示速度差异微弱（2.65s vs 1.75s），且光流与 Δframe 重叠度高，边际价值存疑。

**降级为备选**：仅当方向 1 + 方向 3 不足以解决问题时再启动。
- 编码方案：光流场空间池化 8×8×2 = 128d，concat 到 ViT-g 投影后

## 八、阶段性实验结果

### 方向 1（二阶差分）——负结果，已否决

| 实验 | 配置 | avg_f1 | fallen_f1 |
|------|------|--------|-----------|
| baseline (p7d_delta) | 无 accel | **0.7641** | 0.6609 |
| E1 (p8a_accel) | accel | 0.7532 | 0.6451 |
| E1 正则化 (p8a_accel_reg) | accel + dropout0.5 + lr3e-4 | 0.7439 | 0.6193 |

- **结论**：二阶差分没有帮助，反而变差，且正则化无法挽救（val loss 仍崩到 1.59）
- **根因**：二阶差分的是 ViT-g **语义特征**，不是物理加速度。ViT-g 帧间高度相关（ρ≈0.976），accel 捕获的是语义微小变化，与"跌倒突然性"无对应关系
- **性质**：accel 特征本质是"额外塞入无判别信号的容量"，模型拿来过拟合

### 方向 3（姿态关键点）探针实验——正结果，值得集成

| 指标 | 纯姿态（99维，212K参数） | ViT-g baseline | 随机 |
|------|--------------------------|----------------|------|
| avg_f1 | **0.6797** | 0.7641 | 0.333 |
| fall_f1 | 0.6017 | 0.6775 | — |
| fallen_f1 | 0.5150 | 0.6609 | — |
| normal_f1 | 0.9225 | 0.9538 | — |

- **结论**：纯姿态 avg_f1=0.68（远高于随机 0.333，达 ViT-g 的 89%），且只用 1/14 的参数 → **姿态信息密度极高，与 ViT-g 互补，值得集成**
- **探针脚本**：`experiments/probe_pose.py`（复用 `data/omnifall_pose_frame.npz` 的 99 维特征）
- **观察**：fallen_f1 仅 0.52，印证"静态躺着 vs 倒地"是核心难题；单帧 xyz 难区分，需引入姿态的**时序轨迹**（躯干倾斜速度、髋部下降加速度）
- **下一步**：E2 实验（ViT-g + 姿态 concat），并考虑派生语义特征（头高/髋高/躯干角 + 速度/加速度）

### 姿态集成（E2 / E2b）——负结果，探针判据有误

| 实验 | 输入 | avg_f1 | best_epoch | normal→event 假阳性 |
|------|------|--------|-----------|--------------------|
| baseline (p7d_delta) | ViT-g + Δframe | **0.7641** | 34 | 12,489 |
| E2 (p8_pose) | + 原始 99 维姿态 | 0.7527 | 12 | 16,043 |
| E2b (p8_pose_semantic) | + 派生 8 维姿态 | 0.7413 | 7 | 17,362 |

- **结论**：姿态集成（无论原始 xyz 还是派生语义特征）都**低于 baseline**，且假阳性单调增加、过拟合越来越早
- **根因**：探针判据"纯姿态 F1 ≥ 0.5"是**错的**——它只证明姿态"有信号"，但该信号**与 ViT-g 冗余**（ViT-g 已隐式编码姿态）。正确判据应是"ViT-g + 姿态 是否超过 ViT-g 单独"
- **派生特征**（`preprocessing/step9_derive_pose.py`，8 维 = 头高比/躯干角/高宽比/髋高 + 速度）虽然可解释且区分清晰（站立头高比 1.29 vs 躺卧 -0.18），但集成后仍最差（0.7413，epoch 7 即过拟合）

## 九、最终收敛结论（含门控融合的精细发现）

**"加特征 + naive concat"路线全部证伪**，呈单调趋势：特征加得越多，过拟合越早（best_epoch 34→11→12→7），假阳性越高（12,489→17,362）。

| 方向 | test avg_f1 | 性质 |
|------|------------|------|
| baseline (ViT-g + diff) | **0.7641** | 基准 |
| 方向 1（二阶差分） | 0.7532 ❌ | 语义特征二阶差 ≠ 物理加速度 |
| 方向 3（姿态 concat） | 0.7527 ❌ | 姿态信号与 ViT-g 冗余 |
| 方向 3（派生姿态 concat） | 0.7413 ❌ | 同冗余，过拟合最早 |
| 方向 2（光流 concat） | 0.7469 ❌ | fall vs lie_down 光流幅度接近 |
| E5（姿态门控融合） | 0.7548 ⚠️ | **见下方精细发现** |

### 门控融合（E5）——三元有细微变化，但主指标 event_f1 全部失败

门控融合（`GatedFusionModel`，gate 由 aux 决定，`fused=(1-gate)·main+gate·aux`）在三元指标上有细微变化，但**主指标 event_f1 全部低于 baseline**。

**三元层面**（原始预测，未过规则）：

| 指标 | baseline test | 姿态门控 test | 光流门控 test |
|------|--------------|--------------|--------------|
| avg_f1 | 0.7641 | 0.7548 | **0.7654** |
| fall_f1 | 0.6775 | 0.6842 | **0.6922** |
| fallen_f1 | 0.6609 | 0.6339 | 0.6502 |

- 姿态门控：fall_f1 涨（+0.007），但 fallen_f1 崩（-0.027）→ 姿态对运动有效、对静态有害
- 光流门控：fall_f1 显著涨（+0.015），fallen_f1 略降（-0.011）→ 光流（纯运动）规避了部分静态污染

**主指标 event_f1 层面**（RuleV2 K1=2, K2=7, W=64 后处理）：

| 指标 | baseline | 光流门控 | 变化 |
|------|----------|---------|------|
| **event_f1** | **0.7735** | 0.7492 | **-0.0243** ⬇ |
| event_recall | 0.8346 | 0.7962 | -0.0384 ⬇ |
| false_events | 4,492 | 4,575 | +83 ⬆ |

- **三元 avg_f1 的微弱提升是误导**——门控融合把模型推向"高精度、低召回"（fall recall 从 0.792 降到 0.750）
- RuleV2 依赖 **fall 召回** 触发事件（fallen 回查 ≥7 连续 fall），门控融合漏检 fall → 事件触发更少 → event_recall 崩到 0.796
- 结论：门控融合的"更谨慎"在 RuleV2 下**有害**，主指标 event_f1 显著下降

### 重要修正：RuleV2 曾丢失，已重做

Phase 7 文档记录的 event_f1=0.774 依赖 RuleV2（K1=2 视频上下文跳过 + 无 fallback_timeout），但该实现**在某次 git 清理中被删除**（`bb79ae6`）。现已在 `eval_rule_c.py` 重新实现 `apply_rulev2`，验证精确复现 baseline 0.7735（false_events 完全一致 4,492）。

### Phase 8 最终结论（修正后）

**所有"加特征"路线（concat 4 种 + 门控融合 2 种）在主指标 event_f1 上全部失败**，无一超过 baseline（0.7735）。

| 路线 | 三元 avg_f1 | event_f1 (RuleV2) |
|------|------------|-------------------|
| baseline | 0.7641 | **0.7735** |
| concat（accel/pose/flow） | 0.74-0.75 | 未逐一算，均 ≤ baseline |
| 门控融合（姿态/光流） | 0.75-0.77 | 0.7492（光流） |

**根本原因（最终确认）**：冻结的 ViT-g 特征无法区分 lying vs fallen，这是唯一的、根本的瓶颈。任何特征层面的增补（concat 或门控）都不能改善主指标 event_f1。**微调 DINOv2（ViT-g）是唯一出路。**
