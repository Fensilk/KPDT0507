# 0804 实验第七阶段总结 — 事件因果检测

## 1. 概述

第七阶段重新定义了跌倒检测的核心假设：从 Phase 6 的帧级因果（"每帧只能看过去"）转向事件级因果（"fallen 必须有 fall 前因"）。窗口内双向注意力被重新定性为合法工程资源（≤2 秒缓冲可接受），跨窗口/窗口内的事件序列检测成为核心设计对象。

本阶段共完成 **7 项实验**（4 条规则测试 + 3 个模型实验），最终确定 **p7d_delta（ViT-g + Δframe）+ p7a RuleV1（事件级单向压制）** 为最优方案。

---

## 2. 实验全景

### 2.1 规则测试

| Test | 规则 | lying→fallen 降幅 | 结论 |
|------|------|:--:|------|
| 1 边界投票 | W_n 开头 fallen → 回查 W_{n-1} 末尾投票 | −0.2% | 负 — 只碰到 339 帧 |
| 2 Oracle | GT fall 查询"过去 64 帧有无 fall" | **−97.5%** | 上限 — 事件因果方向确认 |
| **3 RuleV1** | ≥3 连续 fall → 激活事件 → 事件内 fallen 保留，外 fallen 压制 | **−55.3%** | ✅ 最佳规则 |
| 4 RuleV2 | RuleV1 + 事件内间隙填充（gap_fill=5） | −49.8% | 负 — 填充放大假 fall |

**RuleV1 算法**：

```
FOR each video frame:
    IF 连续 ≥5 帧 fall → event_active = True, timer = 0
    IF event_active AND pred == fallen → 保持 fallen, timer = 0
    IF event_active AND pred == fall → timer = 0
    IF event_active AND pred == normal → timer += 1
    IF timer > 32 → event_active = False
    IF NOT event_active AND pred == fallen → 改判 normal（孤立 fallen, lying 抑制）
```

**规则不触碰 fall 预测**——只做 fallen 的 suppression，不做 fall 的 promotion，避免假 fall 放大。

### 2.2 规则参数优化：k=5 优于 k=3

对 fall 触发阈值 k ∈ {1, 2, 3, 5, 8, 12} 进行扫描（`experiments/sweep_rule_threshold.py`），发现 **k=3 并非最优**。

**p7d_delta 在不同 k 下的表现**：

| k | lying→event | 假 event 总量 | 事件数 | fallen 压制 |
|:--:|:--:|:--:|:--:|:--:|
| 1 | 1,407 | 4,480 | 291 | 1,333 |
| 2 | 1,351 | 4,405 | 281 | 1,408 |
| 3 | 985 | 4,033 | 269 | 1,821 |
| **5** | **769** | **3,799** | 257 | 2,055 |
| 8 | 695 | 3,654 | 244 | 2,226 |
| 12 | 631 | 3,506 | 223 | 2,696 |

k=3→5 的边际改善最大：lying→event −216（−21.9%），假 event 总量 −234（−5.8%）。k=3 放过了过多由短促假 fall（13.6% fall 预测是单帧）触发的事件；k=5 利用 Bridge/Δframe 的 fall 预测连续性（52.8% ≥16 帧）有效过滤假触发，同时不显著漏真事件（真 fall 中位数 23 帧）。**后续结果均以 k=5 为准。**

### 2.3 模型实验

| ID | 改动 | 核心发现 |
|------|------|------|
| p7b_event_gate | Bridge + 逐帧 event head | 退化 — 标签密度 99.6%，门控 always-1 |
| p7c_binary_event | Ternary→Binary（2类） | +1.6pp event_f1，lying→event 几乎不变 → 特征瓶颈 |
| **p7d_delta** | ViT-g + Δframe | +R1: 假 event −36.5%，全面优于 p6+R1 |

## 4. 关键架构决定

### 4.1 为什么不是 p6_bridge + RuleV1

p7d+R1(k=5) 的假 event 总量 3,799 vs p6+R1(k=5) 的 4,831（−21.4%，即少 1,032 帧）。lying→event（769 vs 816，−5.8%），other→event（926 vs 1,518，−39.0%）。Δframe 的基线改善 + k=5 的更精准触发共同贡献。

### 4.2 为什么不是 p7c_binary

Ternary→Binary 消融只带来 +1.6pp event_f1，lying→event 几乎不动。任务简化本身不能解决特征瓶颈。

### 4.3 为什么 Δframe 在 ViT-g 下有效（而 ViT-L 下无效）

Phase 4b（p4b_dino_diff）：ViT-L 1024d + Δframe → fall_f1 −2.6pp。  
Phase 7（p7d_delta）：ViT-g 1536d + Δframe → avg_f1 +1.4pp。

可能的解释：ViT-g 更强的外观特征提供更干净的基准，Δframe 的运动信号在更高的信噪比下成为有效补充而非噪声。ViT-L 的特征本身不够确定，Δframe 的噪声占比较高。这与 Phase 5b 的发现一致——特征质量（ViT-g > ViT-L）决定了后续改进的有效性。

## 5. 最终推荐

```
p7d_delta（ViT-g + Δframe, T=64 bidirectional）
    + p7a RuleV1（≥5 fall → 事件激活 → 孤立 fallen 压制, timeout=32）

==== Ternary ====
fall_f1:          0.691（vs Bridge 0.684）
fallen_f1:        0.662（vs Bridge 0.629, +3.3pp）
fallen_precision: 0.722（vs Bridge 0.576, +14.6pp）
fallen_recall:    0.611（vs Bridge 0.694, −8.3pp）
avg_f1:           0.770（vs Bridge 0.753, +1.7pp）
accuracy:         0.916（vs Bridge 0.899, +1.7pp）

==== Binary Event ====
event_f1:         0.763（vs Bridge 0.737, +2.6pp）
event_precision:  0.736（vs Bridge 0.648, +8.8pp）
event_recall:     0.791（vs Bridge 0.856, −6.5pp）

==== 假 Event 压制 ====
假 event 总量:     3,799（vs Bridge 6,354, −40.2%）
lying→event:      769（vs Bridge 2,152, −64.3%）
other→event:      926（vs Bridge 1,593, −41.9%）
```

规则零训练成本，模型在 p6_bridge 基础上仅加 Δframe 特征（+592K 参数）和 k 参数调整。两者叠加达到当前最佳 binary event 检测性能。

## 7. 方向关闭

| 方向 | 原因 |
|------|------|
| 帧级因果 + 因果 mask（P6） | 双向注意力的未来信息是合法工程资源，不是作弊 |
| 跨窗口边界投票规则 | 只碰到 339 帧，问题不在窗口边界 |
| 事件内间隙填充（RuleV2） | fall 精度不足时放大假 fall |
| 逐帧 event gate（p7b） | 标签密度 99.6% 导致门控退化 |
| T=32 窗口消融 | 全面退步 −8.0pp fall_f1，窗口完备性 > 数据量 |
| Ternary→Binary（p7c） | 容量释放真实但微小，特征瓶颈不在此 |

## 8. 未完成方向

| 方向 | 理由 | 优先级 |
|------|------|--------|
| Fine-tune DINOv2 | frozen ViT-g 是最终瓶颈。让 ViT 学习跌倒姿态可进一步区分 lying 和 fallen | 高 |
| 更大窗口（T=128） | 当前 80 帧视频限制了 T>80。若数据集允许更长序列 | 中 |
