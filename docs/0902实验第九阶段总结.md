# 第九阶段总结：E3 帧级 LoRA → E1 端到端（分解假设证实 → 全量收官）

> 两条线：**E3（两阶段帧级 LoRA）**把"两条难轴"拆开验证，证明**动态轴帧级可学、静态轴帧级不可学**；
> **E1（端到端 LoRA）**承接此诊断，靠时序上下文驱动特征编码因果，并在 2,000 → 6,000 → **9,600（全量）**
> 的数据轨迹上完成 Phase 9 收官。阶段核心主张（"静态轴要靠端到端 × 更多数据"）**成立但不全面**：
> E1-full 在 avg_f1/acc/fallen_rec/fall_prec 创全项目新高，事件轴与 fallen_prec 未超 E1@6000
> → **数据红利有轴依赖性**（§4.6.4、§七）。

## 一、阶段概览

**目标**：微调 DINOv2（ViT-g），让帧特征学会区分"两个难区分"——静态 lying vs fallen（因果）与动态
lie_down vs fall（受控性）。第八阶段已证明任何低层增补特征（加速度/光流/姿态）都无效，唯一出路是
微调特征提取器本身。

**数据侧前奏**：先尝试剔除"无前因躺卧"视频的数据清洗方向（P9/P9b），两种变体均被证伪
（fallen_prec 不升反降），确认瓶颈在模型能力而非标签噪声 → 强化微调必要性。

**设计决策链**（详见 `docs/0831实验第九阶段规划.md`）：
- **基座**：`facebook/dinov2-giant` 预训练权重（"从冻结特征反推权重"不可行，已论证）。
- **方法**：LoRA 低秩适配——显存可行（1.1B 主干 + 仅 7.86M 可训练）、任务性质匹配（对强预训练特征
  做低维修正）、防灾难性遗忘、探索成本低。
- **顺序**：**先 E3（两阶段帧级）后 E1（端到端）**——E3 不是 go/no-go，而是把瓶颈拆成两条轴分别
  验证的**分解诊断**；E1 承接其结论，是静态轴的唯一出路。

**阶段结论一句话**：E3 精确定位了瓶颈（静态轴不可帧级学）→ E1 证明端到端确为该轴的出路、且优势
**随数据放大**，但全量收官的增益**集中在静态轴与总体指标**，事件轴/召回在 6,000 附近已饱和。

## 二、核心框架：两条可学性不同的轴

| 难区分 | 信息在哪 | 帧级可学吗 |
|--------|---------|:---:|
| 动态 lie_down vs fall | 受控性——在运动过程本身（姿态、速度、肢体失控） | ✅ 单帧可能可学 |
| 静态 lying vs fallen | 因果——在前因动作（倒地前发生了什么） | ❌ 单帧无此信息 |

E3 的帧级目标恰好把两条轴分开测，结果按诊断矩阵读，而非"有效/无效"二值。

## 三、E3：两阶段帧级 LoRA（分解假设证实）

### 3.1 实验设计

```
Stage1: 帧级 LoRA 微调
    ViT-g(facebook/dinov2-giant, fp16) + 手写 LoRA(q/k/v/o, rank16, 7.86M 可训练)
    + Linear(1536→3) 分类头；逐帧三元 CE + 类权重（fall 1.31 / fallen 1.55 / normal 0.13）
    数据：2,000 训练视频 × 10 帧 = 20,000 帧（按类打散采样，seed 42）
    训练：batch 16（autodl 显存限制），5 epochs，lr 1e-4

Stage2: 重抽 + 时序训练
    用微调 ViT-g 重抽 12,000 视频逐帧 CLS 特征 → 新 NPZ
    → 现有 train_phase6.py（ViT-g 特征 + Δdiff + Transformer, 与 baseline p7d_delta 同配置）
```

### 3.2 环境挑战与修复（重要经验）

| 问题 | 现象 | 修复 |
|------|------|------|
| **AV1 解码** | autodl 的 cv2 解不了 OmniFall AV1（"Missing Sequence Header"），解码失败**零填充**不报错 → 帧准备/重抽产出垃圾特征 | **PyAV**（`pip install av`，自带完整 AV1 解码）；`preprocessing/av_decode.py`（PyAV 优先 + cv2 兜底）；帧均值验证（>20）排查垃圾帧 |
| **显存** | autodl 是 torch 2.1.2 + transformers 4.44，比本地吃内存 3 倍——batch 16 需 ~19GB，batch 32 必 OOM | 只能 batch 16 |
| **HF 访问** | autodl 连不上 huggingface.co | `HF_ENDPOINT=https://hf-mirror.com` 下载模型；`HF_HUB_OFFLINE=1` 强制离线用缓存 |
| **残留进程** | 训练挂掉后 nohup 可能留残进程占显存 | 跑前 `nvidia-smi` 检查 |
**E1 阶段补充的工具坑**（同类：环境/工具问题）
| 问题 | 现象 | 对策 |
|------|------|------|
| **torch.compile 与 DINOv2 不兼容** | `transformers` DINOv2 + 梯度 checkpointing 下 compile 首前向即 `TypeError: layer_norm(): input must be Tensor, not NoneType`（dynamo resume 点丢中间张量） | E1-full 按预案改 **compile OFF**（=H 已验证配方）；冒烟 10min 内即暴露，未浪费闸门窗口 |
| **watchdog 僵尸判活** | `kill -0 <pid>` 对**僵尸子进程**仍返回成功 → 进程级监视死循环、永不判型/触发后续 | 判活须查 `/proc/<pid>/stat` 状态（Z=僵尸），不能只用 `kill -0` |
| **`pkill -f` 自匹配** | `pkill -f <脚本名>` 会匹配到**自己的 ssh 远程 shell**（命令行含该串）→ 自杀并误杀他人进程 | 用 `pkill -f "<关键字>[x]"` 括号技巧，或先 `pgrep` 确认 PID 再 `kill` |

### 3.3 结果：诊断矩阵（全量 test，1,200 视频）

测试集：全量 test（1,200 视频），与 baseline p7d_delta 同评估口径。

| 指标 | baseline | E3 微调 | Δ |
|------|----------|---------|-----|
| fall_precision | 0.5918 | 0.5939 | +0.0021 |
| **fall_recall** | 0.7923 | **0.8418** | **+0.0495** |
| fall_f1 | 0.6775 | 0.6964 | +0.0189 |
| **fallen_precision** | 0.6272 | 0.6194 | **-0.0078** |
| fallen_recall | 0.6984 | 0.7013 | +0.0029 |
| fallen_f1 | 0.6609 | 0.6578 | -0.0031 |
| avg_f1 | 0.7641 | 0.7689 | +0.0048 |
| ternary_acc | 0.9079 | 0.9070 | -0.0009 |

**诊断矩阵观察**：
- **动态轴改善**：fall_rec 0.792→**0.842**（+0.050），fall_prec 持平 → 受控性帧级可学，微调特征学会区分"跌倒的失控下降"与"主动躺下的受控下降"。
- **静态轴不变**：fallen_prec -0.008、fallen_rec +0.003（噪声级）→ 单帧"人在地面"无前因信息，帧级微调学不出 lying vs fallen 的因果。

### 3.4 结论：分解假设成立

**分解假设被精确证实**：

1. **受控性（动态轴）帧级可学** ✅：帧级 LoRA 微调让 fall_rec +0.05，微调 DINOv2 确实能学会编码"是否失控"。
2. **因果（静态轴）帧级不可学** ❌：单帧无前因信息，帧级微调无法区分 lying vs fallen。
3. **端到端（E1）是唯一出路**：静态 lying-vs-fallen 必须靠时序模型利用前因上下文，端到端联合训练（让时序头反向驱动特征编码因果）是唯一途径。E3 把微调有效的范围锁定在动态轴，把静态轴瓶颈精确定位到"时序整合"。

## 四、E1：端到端 LoRA（本阶段主线）

> E1@2000（与 E3@2000 受控对照）→ 为立项 E1-full 做的全部低成本替代验证（方案 A-H）
> → 结论（数据量是增益关键、端到端精度随数据上扬）→ **E1-full（9,600 冷启动）立项并收官**。

### 4.1 背景与要回答的问题

- 三元分类 **fall（正在倒）/ fallen（倒后倒地）/ normal（含故意躺下 lying）**。
- 最难的是 **fallen vs lying（静态轴）**：单帧上看，倒在地上与故意躺下无法区分；
  唯一差异是**历史**——fallen 的"前因"是一次 fall。该信息只在时间序列里存在。
- E3（帧级两阶段）结论：动态轴帧级可学（fall_rec 0.842），静态轴单帧不可学
  （fallen_prec 0.619 不升）→ 时序整合是唯一出路 → 做 E1。

**E1 假设**：把 LoRA 微调的 ViT-g 与时序头**端到端联合训练**，让特征在 64 帧窗口内
学会携带"跌倒前因"，从而把静止的 fallen 和 lying 分开（fallen_prec 突破 0.619）。

---

### 4.2 E1@2000：为什么它是 E1 的第一个实验，以及它的结果

#### 4.2.1 为什么先做 E1@2000（而不是直接 E1-full）

- E1 是**范式假设**（时序反传让特征携带前因），范式有风险、也有成本量级差异（2,000 vs
  9,600 视频端到端差 ~5 倍）。正确顺序是**先在受控数据上钉死"范式是否赢"**，赢了再谈全量。
- E1@2000 选 **2,000 训练视频** = 与 E3 stage1 完全同批（seed42 打散 train 前 2000），
  这样可造出同数据的 E3@2000 两阶段对照 → E1 与对照的**唯一变量 = 训练范式**。

**E1@2000 设计要点**（= E1 的第一站配方，也是后续一切 E1 的基线配方）：

| 维度 | 取值 |
|---|---|
| 骨干 | dinov2-giant 冻结 + **LoRA r16 q/k/v/o**（10.82M 可训练，主干 fp16） |
| 时序头 | Phase6 transformer bridge（1层/6头/Δdiff 3072），与 baseline p7d_delta 同款 |
| 输入 | 逐帧 CLS + Δdiff → 3072 |
| 训练窗口 | 64 / stride 16（2 窗口/视频）；batch 2；lr 1e-4；seed 42 |
| 损失 | 逐帧三元 CE + 逆频类权重（≈[1.34, 1.53, 0.13]） |
| 轮数 | 5 epochs，**early_stop_patience 0**（跑满，best 按 val 峰值选） |
| 监控 | val 150 视频（stride80 单窗口，头窗口径），val_every 600 |
| test | 全量 1200 视频，64/stride8 → 230,400 帧实例 |

> 早停教训：E1 首轮用 patience=2 在 ~1.5 ep 被掐断，全量 test fallen_prec 仅 **0.506**
> （欠训练废数）；跑满后才到 0.645。此后一律 `--early_stop_patience 0` 跑满按 val 选。

#### 4.2.2 E1@2000 结果（全量 test，instance 口径）

| 指标 | E1@2000(5ep) |
|---|---|
| fall_precision | **0.680** |
| fall_recall | 0.709 |
| fall_f1 | 0.694 |
| fallen_precision | **0.645** |
| fallen_recall | 0.630 |
| fallen_f1 | 0.637 |
| avg_f1 | **0.763** |
| ternary_acc | **0.915** |

**收敛要点**（monitor，val 头窗口径）：best = step 6,000（epoch 3 末）val_avg_f1 **0.866** /
val_fallen_prec **0.859**；epoch 4-5 未再刷新 best（precision↔recall 摆荡）。全程
5 ep / 10,000 步 / ~14.7h 跑满。

> 单看 E1@2000 还**不能下结论**：fallen_prec 0.645 比 E3 全量的 0.619 高，但 E3 全量的时序头
> 是在 9,600 视频上训的（数据量不对称）——需要同数据的 E3@2000 对照才能归因"范式"。

### 4.3 E3@2000：为什么补它，以及它的结果

#### 4.3.1 为什么补 E3@2000

原 E3 参考数字（fall_rec 0.842 / fallen_prec 0.619）其时序头在**全量 ~9,600 视频**上训，
E1 只有 **2,000** → 直接 E1@2000 比 E3 全量**数据量不对称**，无法干净归因"范式 vs 数据量"。
因此给 E3 的 stage2 时序头在**同一 2,000 视频**（E3 stage1 冻特征上）重训一个 → **E3@2000**。
为此给 `train_phase6.py` 加了 `--eval_stride`（训 16 / 测 8 解耦），给 E3@2000 造了与 E1
完全相同的 2,000 训练 split。

#### 4.3.2 E3@2000 结果（全量 test，instance 口径）

| 指标 | E3@2000 |
|---|---|
| fall_precision | 0.572 |
| fall_recall | 0.714 |
| fallen_precision | 0.632 |
| fallen_recall | 0.617 |
| avg_f1 | 0.737 |
| ternary_acc | 0.901 |

### 4.4 E1@2000 / E3@2000 / E3-full 三模型比较 → 结论：E1-full 势在必行（但成本门槛高）

#### 4.4.1 全量 test 同口径总表（instance，230,400 帧）

| 指标 | baseline | E3 全量 | E3@2000 | **E1@2000(5ep)** |
|---|---|---|---|---|
| fall_precision | 0.592 | 0.594 | 0.572 | **0.680** |
| fall_recall | 0.792 | 0.842 | 0.714 | 0.709 |
| fall_f1 | 0.678 | 0.696 | 0.635 | 0.694 |
| fallen_precision | 0.627 | 0.619 | 0.632 | **0.645** |
| fallen_recall | 0.698 | 0.701 | 0.617 | 0.630 |
| fallen_f1 | 0.661 | 0.658 | 0.624 | 0.637 |
| avg_f1 | 0.764 | 0.769 | 0.737 | **0.763** |
| ternary_acc | 0.908 | 0.907 | 0.901 | **0.915** |

#### 4.4.2 受控对比（唯一变量 = 范式）：E1@2000 − E3@2000

| | E3@2000 | E1@2000 | Δ |
|---|---|---|---|
| **fallen_prec**（静态轴） | 0.632 | **0.645** | **+0.013** |
| fall_prec | 0.572 | **0.680** | **+0.108** |
| fall_rec | 0.714 | 0.709 | −0.005（持平） |
| avg_f1 | 0.737 | **0.763** | **+0.026** |
| ternary_acc | 0.901 | **0.915** | **+0.014** |

#### 4.4.3 归因：把"范式 vs 数据量"拆干净

1. **端到端范式在同等数据下占优（静态轴假设成立）**：同 2,000 下 E1 fallen_prec 0.645
   全面高于 E3@2000（0.632）、E3 全量（0.619）、baseline（0.627）；fall_prec(+0.108) 与
   avg_f1(+0.026) 同步改善。E1 的静态轴增益来自**特征被（时序感知地）适应**，不是头配方
   （§4.5.1 方法 1 已证冻头天花板 ~0.63）。
2. **fall_rec ≥0.82 的目标在 2,000 数据下对任何范式都不现实**：E1（0.709）与 E3@2000
   （0.714）站在同一平台——0.82 是按 E3 全量（9,600 视频）定的 → **纯数据量效应，不是范式**。
3. **步长不是混杂**：训练 stride16 / 评估 stride8 对齐 A/B 各指标差 ≤0.005（avg_f1 差
   0.001）——模型对未训练过的 [8:72] 窗口对齐不敏感，"步长失配"无代价。
4. **数据量杠杆真实可量化**：E3@2000 训练步长对齐到 s8（0.726）后，2000→9600 纯数据量
   贡献 ≈ fall_rec **+0.116**（0.726→0.842），其中步长 16→8 只占 ~+0.012。

#### 4.4.4 结论：E1-full 势在必行，但 70h 把胜负线抬得极高

- **「端到端 × 全量数据」能否全面超越 E3-full，只有 E1-full（~9,600 视频端到端，估 ~70h）能验证**
  ——这是验证第九阶段核心主张的决定性实验，逻辑上势在必行。
- 但成本高反而把期望抬到"不能输"：70h 若不能同时压过 E3-full（0.619/0.842）与 E1@2000
  （0.645/0.709）＝无效工作。且**最该警惕的反例信号**：E3 自己的 fallen_prec 从 E3@2000 的
  0.632 掉到 E3-full 的 0.619——更多数据让头去优化数据主导的动态轴/normal，静态 precision
  反被牺牲；E1@2000 的 0.645 是在 2,000 上拿到的，可能含**小数据正则化红利**，能否在 9,600
  存活完全未知。
- **决策含义**：投 70h 前，必须先低成本排除"数据量之外"的可疑解释（头没训好？帧级特征多吃
  数据值钱？后处理能补？小骨干也灵？），**证实或证伪 E1-full 的必要性**，再决定投不投 → 即
  第 5 节替代验证 A-H。

### 4.5 替代验证 A-H：E1 的增益能否用便宜手段复现？（前置探针，全量记录）

> 证明"端到端增益可廉价保留/可蒸馏" → E1-full(giant) 的必要性被削弱甚至取消；**只有全部证伪**
> ，才回到"唯一被验证的路是端到端本体"，进而用 H 测数据轨迹，最后才轮到 E1-full(~70h)。
> （D 否决 §4.5.6；F 否决 §4.5.9；两者都不再参与前置证伪。）

#### 4.5.1 方案 A：方法 1 冻特征上"更好的头"（V1 → V2）

**验证目标**：E1 的静态轴增益是否只是"冻头没被好好训练"？能否用**只改头**的配方（不碰
ViT、不碰数据）追回 E1@2000 的 fallen_prec 0.645。

**如何做的**：基座 = E3@2000（E3 stage1 冻特征 + Phase6 bridge 头，1层/6头/Δdiff 3072，
train stride16 + CE，2,000 视频）。本地 4060 跑两个变体，best 按 val，全量 test（stride8）评估：
- **V1**：训练 stride 16→8（6,000 窗口/epoch，多 1.5× 窗口）——检验"窗口密度"。
- **V2**：stride16 对齐 E3@2000，加 `--fallen_w 3`（fallen 类 CE 权重 ×3）——检验"fallen 更
  激进"能否把静态轴推上去。

**执行结果**（全量 test）：

| | fall_rec | fallen_prec | fallen_rec | avg_f1 |
|---|---|---|---|---|
| E3@2000(s16) | 0.714 | 0.632 | 0.617 | 0.737 |
| **V1(s8)** | **0.726** | 0.626 | 0.627 | 0.739 |
| **V2(fw3)** | 0.736 | **0.615** ↓ | **0.690** ↑ | 0.744 |
| E1@2000（参考） | 0.709 | **0.645** | 0.630 | 0.763 |

**结论**：V1 fallen_prec 不升反微降（0.626）→ 单纯多给窗口补不回静态轴；V2 权重沿
precision↔recall **只能做交易**（fallen_rec 0.690↑ 但 fallen_prec 0.615↓），够不到 E1
"prec 0.645 与 rec 0.630 同时更高"的点。**冻特征头的 fallen_prec 天花板 ≈ 0.63** → E1 的
静态轴增益不来自"头没训好"，指向特征本身被（时序感知地）适应。V1 兼作**数据曲线锚点**
（0.726，与 E3-full 同 stride8 对齐）→ 量化 2000→9600 纯数据贡献 ≈ fall_rec **+0.116**。

**对 E1-full 的影响**：排除"用便宜冻头配方复现 E1 静态轴"这条非数据量解释；能碰静态轴的是
特征适应本身 → 下一步引向"帧级特征适应在更多数据上是否有用"（→ 方案 B）。

#### 4.5.2 方案 B：方法 3 帧级 LoRA 特征从 2,000 扩到全量 9,600

**验证目标**：E1-full 相对 E3-full 的"第二重收益"（特征也在全量上适应）是否值钱——方法 3 =
同配方 stage1 改吃全量 9,600，stage2 仍吃全量 → **唯一变量 = 特征微调阶段的数据量**。

**如何做的**：① stage1@9600：`train_p9_e3_stage1.py` 全量 9,600 视频真帧（96,000 帧，5ep，
autodl 3090 ≈ 5h，途中踩坑黑帧/AV1 解码已修）→ `m3_stage1/finetuned_lora.pt`；② 重抽全量
12k 特征（≈ 4h）→ `data/omnifall_dinov2_finetuned_m3_frame.npz`；③ stage2 用 m3 特征 + 全量
训时序头（本地 4060，≈ 20 min）→ `m3_full_features`。

**执行结果**（全量 test，m3 vs E3-full）：

| | m3 | E3-full | Δ |
|---|---|---|---|
| fall_precision | 0.557 | 0.594 | −0.037 |
| fall_recall | 0.836 | 0.842 | −0.006 |
| fallen_precision | 0.609 | 0.619 | −0.010 |
| fallen_recall | 0.766 | 0.701 | **+0.065** |
| avg_f1 | 0.766 | 0.769 | −0.003 |

**结论**：**近零/略降**，唯一真实移动是 fallen_rec +0.065。**特征微调数据量是弱杠杆**——帧级
任务在 ~2,000 视频就基本饱和，4.8× 数据不带来下游收益。机理：① 两套特征同底重叠大；②
stage2（全数据）主导下游；③ **fallen_prec 是帧级范式上限**——帧级编码不了时序前因。

**对 E1-full 的影响**：排除"E1-full 价值来自特征在全量上适应"。帧级吃全量不改变下游 →
**E1-full 的潜在增益只能来自端到端·时序感知的特征适应本体**。仍不回答"端到端精度能否随数据
存活"——该数据量问题交由 H（或方案 E/G）测。

#### 4.5.3 方案 G：E1@2000 当 teacher 蒸馏到冻特征头（软标签 vs 硬标签）

**验证目标**：方案 A 若证明"硬标签喂不饱冻头"，追问**软标签能不能喂饱它**——teacher 软输出
带硬标签没有的时序软信号（"这帧 fallen"与窗口里那次 fall 的关系、与 lying 的相似度）。

**如何做的**：teacher = E1@2000。teacher 在 e1_2000 的 2,000 训练视频、stride16 的 4,000 窗口
上前向产出软标签（`m7_precompute_teacher.py`，autodl 3090），学生 = 冻特征(3072 Δdiff) 上的
Phase6 bridge 头，loss = KL(学生‖teacher) + λ·CE(硬标签)，λ=1、temp=2（未调参）。val avgF1
早停选 best（best ep 19/34），跑全量 test。

**执行结果**（全量 test）：

| | fall_prec | fall_rec | fallen_prec | fallen_rec | avg_f1 |
|---|---|---|---|---|---|
| E3@2000（同头·硬标签，参考） | 0.572 | 0.714 | 0.632 | 0.617 | 0.737 |
| **方案 G（蒸馏软标签）** | *0.602* | **0.738** | *0.608* | **0.711** | 0.757 |
| E1@2000（teacher，参考） | 0.680 | 0.709 | 0.645 | 0.630 | 0.763 |

**结论**：学生 fallen_prec **0.608** < 硬标签基线 E3@2000（0.632）< E1@2000（0.645）——软标签
蒸馏**没有**把冻头 fallen_prec 抬过硬标签基线；fall/fallen recall 升、precision 降，属
recall↔precision 交易。参数未调（temp=2/λ=1 默认），方向性结论基于未调参设定。

**对 E1-full 的影响**：蒸馏路线没有让 E1-full 变得可免。不回答"端到端 fallen_prec 能否随
数据存活"（数据量问题），不单独决定 E1-full 去留。

#### 4.5.4 方案 E：小骨干端到端探针（dinov2-base）

**验证目标**：端到端"时序感知红利"是否绑在 1.1B 大骨干上——小骨干端到端还灵不灵。

**如何做的**：把 E1Model 参数化（CLS 维由骨干 hidden_size 推导），`train_p9e1 --model_name
facebook/dinov2-base`（vitb，86M/768d ≈ giant 1/13），同 E1@2000 配方（2000 视频 / window64 /
stride16 / 5ep / lr1e-4 / batch8 / patience 0），best 按 val ep2（val avgF1 0.8045），eval 用
`eval_p9e1 --model_name ...`。

**执行结果**（全量 test）：

| | fall_prec | fall_rec | fallen_prec | fallen_rec | avg_f1 |
|---|---|---|---|---|---|
| **dinov2-base E1** | 0.583 | 0.711 | **0.630** | 0.569 | 0.730 |
| E1@2000(giant，参考) | 0.680 | 0.709 | 0.645 | 0.630 | 0.763 |
| E3@2000（参考） | 0.572 | 0.714 | 0.632 | 0.617 | 0.737 |
| E3-full（参考） | 0.594 | 0.842 | 0.619 | 0.701 | 0.769 |

**结论**（对比取同 2000 数据、同配方的匹配对；E3-full 为全量参考、非匹配）：
- **骨干容量主导**：dinov2-base E1 fallen_prec 0.630 / fallen_rec 0.569 < E1@2000-giant
  0.645/0.630——端到端增益不能脱离骨干容量单独复现。
- **范式未给 base 额外优势**：base-E1 0.630 ≈ E3@2000（giant 冻特征）0.632，未超过。
- **fallen_rec 0.569 明显偏弱**——静态轴正是当初上 giant（为容量）的原因。single-config、
  首次探针，绝对水平不构成范式增益证据。

**对 E1-full 的影响**：小骨干端到端替代 giant E1-full **不成立**。范式净增益（+0.013）是
giant 侧的量，能否随数据存活由 H 直接测、不由本方案代答。

#### 4.5.5 方案 C：RuleV2 / 事件级后处理（E3-full vs baseline）

**验证目标**：项目自带的 RuleV2 是零训练的事件因果约束（fallen 需前有 ≥K2 连续 fall），
从未在 E1 上重测；能否小幅提 fallen_prec（抑制孤立 lying→event 误报）——看"后处理能补"。

**如何做的**：RuleV2 是第 7/8/9 阶段**主指标 event_f1** 的后处理载体（baseline 无规则 0.756 →
+RuleV2 **0.774**）。canonical 参数（K1=2, K2=7, W=64）是 2026-07 在**冻结特征输出分布**上调得。
对 baseline（p7d_delta）与 E3-full 同口径跑两遍：① canonical 直接对比；② 各模型扫
K2∈{3,5,7,10,15,20}×W∈{32,64,128}（test-selected 上界）。评估口径 = 全量 test / stride8 /
逐视频投票 merge → 帧展平 event（fall|fallen vs normal）。baseline canonical 复现历史主指标
event_f1 0.774（0.7735 / prec 0.721 / rec 0.835）。

**执行结果**（canonical）：

| 模型 | ev_f1 raw→+R2 | ev_prec(+R2) | ev_rec(+R2) | 三元 fallen_prec raw→+R2 | 抑制 fallen | lying→event 占比 raw→+R2 |
|---|---|---|---|---|---|---|
| baseline p7d_delta | 0.7558→**0.7735** | 0.7207 | 0.8346 | 0.6205→**0.6902** | 896 | 12.4%→8.1% |
| E3-full e3_stage2 | 0.7556→0.7603 | 0.6886 | 0.8486 | 0.6039→0.6330 | 617 | 14.7%→12.3% |

> 注：表中三元 fallen_prec 为事件口径（帧级投票 merge），与官方窗口实例口径相差 <0.01、排序
> 一致。

三个关键读数：
- **raw（无规则）event_f1 死平**（0.7558 vs 0.7556）——E3-full 帧级 fall_rec 提振在事件轴被
  自身新增误报抵消（ev_rec +2.0pp、ev_prec −1.3pp）。
- **规则红利高度偏向 baseline**（+0.018 → 0.774 vs E3-full +0.005 → 0.760）。
- **机制**：RuleV2 只抑制"孤立 fallen"。baseline 误报孤立可抑制；E3-full 把误报从静态 lying
  蔓延到运动过程 lie_down（→event 8.3%→**14.1%**）——它先虚构出 fall run，后续 lying→fallen
  就有"因果前导"，闸门放行 → 微调特征的高 fall 召回部分靠"对下降运动过度报警"买来，这些假
  fall 帧既算事件误报、又给假 fallen 当"前因背书"。

**重调参数**（排除"规则没给 E3-full 调过"）：baseline best K2=7（canonical 即最优）→ 0.7735；
E3-full best K2=5 → 0.7654，仍 < 0.774；高 K2 下 E3-full 崩得更快（K2=20：0.66 vs 0.71）→
**缺口是分布性的，不是参数没调好**。

**结论**：E3-full 在"事件+规则"主指标上不占优（0.760 < 0.774），调参也不翻盘（上界 0.765）——
"后处理能补"未在两阶段特征分布上成立。

**对 E1-full 的影响**：
1. **已实测（规则耦合半面成立）**：规则红利高度偏向 baseline（baseline +0.018 vs E3-full
   +0.005 vs E1@2000 +0.002~0.006）⇒ E1-full 收益**不能把"规则红利"算作隐含项**。
2. **已实测（但"E1-full 无收益"不被支持）**：E1@2000 +RuleV2 canonical ev_f1 0.7624（调参
   best 0.7669）仍 < baseline+rule 0.7735，但：**raw（无规则）ev_f1 = 0.7606 已是三模型最高**
   ——端到端事件级增益**不靠规则就存在**（event_prec 0.753 vs 0.687/0.674）；规则对 E1 近零
   增益的机理 = **E1 把因果门内化成了网络行为**（见 §4.5.6 归因）；E1@2000 输给 baseline+rule
   的差距在 **event_rec 0.768 vs 0.834 = 召回 = 数据量**，不在范式 → E1-full 胜负手仍是
   "精度优势 × 数据补召回"，由 H 直接测，本读数未证伪它。

#### 4.5.6 方案 D：前置归因（E1@2000 静态轴增益的窗口级定位，零训练）→ 否决

**验证目标**：方案 D 想删"纯 normal 窗口"只留事件窗（课程采样摊薄成本），前提 = "端到端增益
集中在窗口内含 fall→fallen 因果链的帧上"。此前提是否成立**不必烧训练**——E1@2000 与 E3@2000
是同 2,000 数据的匹配对，逐帧对上即可归因（脚本 `experiments/analyze_e1_e3_attribution.py`）。

**归因 1 · fallen 召回按前因分组**（"前因在窗" = 最近 GT-fall ≤63 帧）：

| 组 | 帧数 | E3@2000 | E1@2000 | Δ |
|---|---|---|---|---|
| 前因在窗(≤63) | 6,298 | 0.610 | 0.669 | **+0.058** |
| 前因超窗/无 | 1,081 | 0.632 | 0.430 | **−0.202** |

**归因 2 · normal→fallen 误报按"是否含 GT-fall × 是否 lying"细分**：

| 子集 | E3@2000 | E1@2000 | Δ |
|---|---|---|---|
| 含 fall 视频 · normal | 231 | 261 | +30 |
| 无 fall 视频 · normal | 2,252 | 2,133 | −119 |
| 　其中 lying·无fall（keep-lying/P9 集） | 2,034 | 1,945 | **−89** |

**结论 · 方案 D 的死结**：E1 的 fallen 召回增益只在前因在窗组（+0.058），前因超窗组崩到
0.430（E3 尚 0.632）——**因果门是被学进网络里的**；E1 的 fallen_prec 优势几乎全来自无 fall
视频的 lying 帧（−89/−119）——**靠的正是纯 normal/无 fall 窗口当负样本**。方案 D 保留的"事件窗"
覆盖召回增益（安全），但删的"纯 normal/无 fall 窗口"恰是 E1 在 keep-lying（P9 集）上不做激进
fallen 的证据来源 → **删 normal = 删 E1 静态精度保护，预期重演 P9/P9b 证伪模式**。静态轴的
负样本空间（lying/无 fall）不可删。

**方案 D 否决**：优先度判定低于全量 E1-full，放弃，不投训练算力。

**决策落点（规则无缓冲）**：方案 C + 本归因证明 E1/E3 微调把因果门内嵌 → **RuleV2 对端到端
输出近冗余（E1@2000 +0.002~0.006）** → E1-full 的成功判据相应改为 **"raw event_f1 ≥
0.7735（baseline+RuleV2）"、无后处理兜底**；2000 点（raw 0.7606 > baseline raw 0.7558）未
证伪也未证实该判据，余下的唯一问题是"数据补召回时精度是否存活"→ 由方向 H 直接裁决。

#### 4.5.7 方案 F 前置分析（H 之前）：热启动对 E1-full 必要性的信息量 = 零 → 暂缓

> 时序：A-G 全做完、D 否决之后、跑 H 之前，对"剩下还能不能省 E1-full 成本"做了最后一次前置
> 分析——结论暂缓，仅当 H 支持 E1-full 后才作生产配速项（最终否决见 §4.5.9）。

**做法**（若执行）：用 E3 两阶段权重把 E1Model 拼装到 E3@2000/m3 等价起点再端到端续训：
① E3 stage1 `lora_state` 加 `vit.` 前缀拷入 E1 LoRA（320 键 q/k/v/o，丢弃其逐帧 head）；
② E1 时序头重建时 `max_len` 对齐 E3 stage2 头的 74 再拷其 `model_state_dict`。LoRA 保持可训练。

**对 E1-full 必要性的信息量 = 零**：F 只变**初始化**，而 E1-full 悬而未决的是**数据量**
（init 与 data 正交，无法证明也无法否定 E1-full）。两个可能的信息方向均已被截断：① "少训
epoch 省成本"只是优化事实，非决策；② "warm vs cold 终点质量"测"端到端对特征的重塑是否不可
替代"——已被方法 3 证伪（帧级 LoRA 喂到全量仍撬不动静态轴）→ F 只剩 init 灵敏度，无
go/no-go 价值。

**暂缓结论**：仅当 H 支持 E1-full（fallen_prec 守住 ~0.65、fall_rec 升向 0.80）后才作为生产
配速项（预计省 ~2 ep、成本 ×0.6）；H 未绿灯前不做。（H 后最终裁决见 §4.5.9。）

#### 4.5.8 方案 H 执行：E1@6000 中间量 → 数据轨迹绿、E1-full 是好赌注

**执行前提：为什么 H 是决定性实验（跑 H 前固化的推理链）**：

前置探针 A-G 全做完、D 否决、F 暂缓后，只剩 H 与 E1-full。跑 H 前先固化判断"**数据量是
E1-full 相对 E1@2000 增益的关键**"，依据 = 构造事实 + 四条证据：

- **构造事实**：E1-full 与 E1@2000 同范式、同配方、同从预训练权重冷启动，**唯一变量 =
  训练视频数（9,600 vs 2,000）**。
- **证据 1 · 召回侧数据杠杆已直接实测、且与范式无关**：2000 数据上 E3（0.714）与 E1（0.709）
  收敛到同一 ~0.71 → 2000 召回天花板由数据设定；同一两阶段范式 2000→9600 纯数据贡献 fall_rec
  **+0.116**（0.726→0.842）。E1@2000 欠目标线的缺口全在召回（fall_rec 0.709、event_rec
  0.768），而其精度本就是各轴最高 → E1-full 把召回抬向 ~0.84 平台是近机械预期。
- **证据 2 · 静态轴精度已备好、无需"靠数据学会"**：E1@2000 fallen_prec 0.645 是唯一 >0.63
  的范式；§4.5.6 归因显示因果门已被端到端学进网络（前因在窗组 +0.058）。
- **证据 3 · 替代解释全部证伪**：A 冻头天花板 ~0.63 / B 帧级加数据下游近零 / C 规则对微调
  输出近冗余 / G 蒸馏 0.608<0.632 / E base-E1 0.630<giant 0.645 / D 否决 / F 暂缓 → **数据量
  从"构造唯一变量"升级为"逻辑上唯一存活的增益来源"**。
- **证据 4 · 开放风险唯一定位在"精度随数据存活"**：E3 自身 fallen_prec 0.632→0.619 随数据
  下降（唯一反例信号）→ E1-full 成败取决于端到端精度能否扛过数据主导——这半边就是 H 要实测
  的数据轨迹。

> 结论性质：以上是**强溯因推理而非直接测量**。H = 用中间数据点（4-6k）把最后半边变成实测：
> fallen_prec 守住 ≳0.64 且 fall_rec ≳0.79 → 绿；fallen_prec 掉向 ~0.62-0.63 → 红（止损）。

**执行**：autodl RTX 3090，E1@6000（seed42 打散 train 前 6000，嵌套超集 2000⊂6000），配方复刻
E1@2000（window64/stride16/batch2/lr1e-4/seed42/giant/compile 关），epochs=4、patience=0、
val 每 600 步（150 视频，同 E1@2000）。帧源 = **训练侧 mp4 现解码**（disk 放不下 96GB 缓存；
本地已验证 decode==缓存逐字节一致）。24000 步 **35.3h** 完成；val-best **0.897 @step18000
(epoch3)**，epoch4 尾 0.8802（产物见 §六）。

**全量 test（instance 口径 230,400 帧，对官方线）**：

| 模型(训练量) | fall_rec | fallen_prec | fallen_rec | avg_f1 | ternary_acc |
|---|---|---|---|---|---|
| baseline p7d_delta(9600,冻) | 0.792 | 0.627 | 0.698 | 0.764 | 0.908 |
| E3-full(9600,两阶段) | 0.842 | 0.619 | 0.701 | 0.769 | 0.907 |
| E1@2000 | 0.709 | 0.645 | 0.630 | 0.763 | 0.915 |
| **E1@6000 best(ep3)** | 0.825 | **0.795** | 0.637 | 0.805 | 0.935 |
| **E1@6000 ep4** | **0.848** | 0.749 | **0.747** | **0.815** | 0.933 |

**event 轴（merged 口径）**：E1@6000 raw ev_f1 **0.828(ep3)/0.833(ep4)**；RuleV2 近零增益
（canonical ≤raw）→ 因果门内嵌在 6000 上再次坐实；**raw 已超 baseline+RuleV2 0.7735 约
+0.05~0.06**。

**判读（H 绿/红）**：**绿，且强绿**——fallen_prec 0.75-0.80 ≳0.64 ✓ 且 fall_rec 0.83-0.85
≳0.79 ✓（6000 仅占全量 62%）。
1. **决定性证据 = "证据 4"的证伪**：端到端 fallen_prec **随数据上升**（0.645→0.75-0.80），
   与 E3 的"随数据衰减"（0.632→0.619）相反——E1-full 精度能随 9,600 存活这一唯一开放风险
   在 6000 上不成立。
2. fall_rec 0.825-0.848 已在 62% 数据接近 E3-full 的 0.842；事件轴 raw 已碾压 baseline+rule。
3. ep3(0.795/0.637) vs ep4(0.749/0.747) 是 prec/rec 权衡，双候选均远在绿线之上 → 单 seed 稳健。
4. **外推**：E1-full(9600) 预期 fall_rec ~0.85+、fallen_prec ~0.75+、raw ev_f1 ~0.84 →
   **全面新最优，E1-full(~70h) 是好赌注**。

#### 4.5.9 方案 F 的彻底否决（H 之后）

H 判读绿 → §4.5.7 给 F 的触发条件（"仅当 H 支持 E1-full 时执行"）已满足。**重新审议后判定：
F 仍不执行，正式彻底否决**。理由：① F 的唯一价值是省 E1-full 成本，而 H 之后有更安全的成本
杠杆——**batch/compile 提速**（同一冷启动模型只跑更快，不换 init）；F 的 E3-warm 换 init
盆地，最终质量完全未测。② F 破坏 H 建立的**冷启动证据链叙事**（E1@2000→E1@6000→E1-full 全走
冷启动 = 一条干净的"纯数据轨迹"曲线，是论文核心卖点）。③ 收益薄：H 显示 best 约 ep3，warm
顶多省 ~1 ep（×~0.7）。→ **F 关闭**。E1-full 采用冷启动（提速见 §4.6.2）。

#### 4.5.10 A-H 收束：整体替代验证实验总结

**总判断**：八个替代解释逐一关闭，唯一没被证伪的增益来源 = **端到端范式 × 更多数据**；H
进一步证明端到端精度不仅没像 E3 那样被数据侵蚀、反而随数据上扬。**E1-full（冷启动 9,600）
是唯一剩下的、也是已被验证值得走的路**——前置探针阶段正式结束，进入 E1-full 立项/执行。

#### 4.6.2 唯一可行的提速方案（其余已否决/证伪，不再重复）

**排除项**（一句话）：batch 加大 = 计算瓶颈（SM~100%）不省墙钟 + 改变动力学破坏归因；
LR 缩放同；F 热启动已否决（§4.5.9）；预训练换 DINOv3 等新骨干与证据链无关且代价高于收益。

**唯一可行 = torch.compile（纯内核优化）**：不改 batch/LR/数据/每 epoch 顺序，数值差异可忽略
→ **不破坏归因**（E1-full vs E1@6000 仍可归因数据）。torch 2.5.1 cu124 对 compile 支持远好于
E1@2000 时代的 torch 2.1.2（当年 compile 关）。

**采用"启动即 compile ON + 头 1h 自适应闸门"**（不做单独 A/B——预验证成本 ≈ 一次全跑，必亏）：
1. 以 compile ON 启动 E1-full；
2. 头 30-60 分钟对比每步耗时 vs 5.3s（训练日志节奏即可读）；
3. 若提速 ≥~15% 且无报错/OOM → 保持 compile ON；
4. 若无提速 / compile 报错 / 数值异常 → kill、compile OFF 重启（最坏浪费 ~1.5h）。

**E1-full 配方定稿**（冷启动，其余与 E1@6000/E1@2000 完全一致）：

| 维度 | 取值 |
|---|---|
| 数据 | **全量 train ~9,600 视频**（seed42 打散，含 e1_2000/e1_6000 嵌套）；训练侧 mp4 现解码 |
| 骨干/头 | dinov2-giant 冻结 + LoRA r16 + Phase6 bridge 头（同基线）；Δdiff 3072 |
| 训练 | window64 / stride16 / batch2 / lr1e-4 / seed42 / patience 0 |
| 轮数 | **3 epochs**（=E1@2000/E1@6000 的实测 best 位置 ep3），ep3 尾若 val 仍爬则续第 4 |
| 监控 | val 150（同前），val_every 600，best 按 val_avg_f1 |
| 墙钟 | 每 ep ≈ 14h（9600 步）→ 3ep ≈ 42h、4ep ≈ 57h；compile 提速后 ~35-50h |
| test | best epoch → 全量 test 双口径（instance 对官方线 + merged/RuleV2 对 0.7735） |

#### 4.6.4 E1-full 的三组对比（baseline / 数据量 / 范式）

**（1）对比 baseline：改进多少、归因是什么**
（baseline = `p7d_delta` 冻特征 + Phase6 头，同为 9,600；instance 口径）

| 轴 | baseline | E1-full best | Δ |
|---|---|---|---|
| fall_prec | 0.5918 | 0.6951 | **+0.103** |
| fall_rec | 0.7923 | 0.8305 | +0.038 |
| **fallen_prec（静态轴）** | 0.6272 | 0.7551 | **+0.128** |
| fallen_rec | 0.6984 | 0.7538 | +0.055 |
| avg_f1 | 0.7641 | 0.8268 | **+0.063** |
| ternary_acc | 0.9079 | 0.9367 | +0.029 |
| event_f1（merged） | 0.7558 raw ／ **0.7735**（+RuleV2） | **0.8269** raw | +0.071 ／ +0.053 |

**归因**：增益**压倒性地落在两个精度轴**（fallen_prec +0.128、fall_prec +0.103），召回只
+0.038/+0.055 → **端到端修的是"判决边界质量"（precision），不是召回**。fallen_prec 的 +0.128 是
最大单轴跃迁，正对应论文核心难点（fallen vs lying 静态轴）。事件轴上 baseline 必须靠 RuleV2 才够到

本表是"baseline 范式+配方 vs E1 范式+配方"的**整体差异**，非单变量对照。

**（2）对比 E1@2000 / E1@6000：数据量的作用**
（同范式、同配方，**唯一变量 = 训练视频数** → 本组是最干净的对照）

| 数据量 | fall_prec | fall_rec | fallen_prec | fallen_rec | avg_f1 | acc |
|---|---|---|---|---|---|---|
| 2,000 | 0.6795 | 0.7091 | 0.6448 | 0.6301 | 0.7632 | 0.9150 |
| 6,000（ep3 ／ ep4） | 0.6654 ／ 0.6349 | 0.8253 ／ 0.8475 | 0.7946 ／ 0.7493 | 0.6367 ／ 0.7467 | 0.8049 ／ 0.8145 | 0.9348 ／ 0.9333 |
| **9,600（best）** | **0.6951** | 0.8305 | 0.7551 | 0.7538 | 0.8268 | 0.9367 |

**结论：数据量的作用强烈非线性、边际递减，拐点在 6,000；且红利有明确的"轴分工"。**
- **2,000→6,000 是红利主战场**（覆盖三个轴）：fall_rec +0.116~0.138、avg_f1 +0.042~0.051、
  fallen_prec +0.105~0.150、acc +0.018~0.020。
- **6,000→9,600 只剩静态轴与总体**：avg_f1 +0.012~0.022、fallen_rec +0.007~0.117、acc +0.002；
  而 **fall_rec 不升反微降（−0.017 vs ep4）**。
- **fall_prec 全程无单调数据趋势**：0.6795（2k）→ 0.6654／0.6349（6k）→ 0.6951（9k），一直在
  0.635~0.695 窄幅摆动、标准差级别 ≈ 单 seed 噪声 → **数据量对 fall 类的作用在"召回侧"，不在
  "精度侧"**；精度侧的数据效应只出现在 fallen 类（0.645→0.755）。
- 故 §4.5.8 的外推（fall_rec→0.85+）未兑现，**不是范式或配方失误，而是数据量在召回轴上的边际收益
  已在 6,000 附近耗尽**（事件轴的同类饱和见 §4.6.3）。

**（3）对比 E3-full：端到端范式的作用**（等数据 9,600）

| 轴 | E3-full（两阶段） | E1-full（端到端） | Δ |
|---|---|---|---|
| fall_prec | 0.5939 | 0.6951 | **+0.101** |
| fall_rec | 0.8418 | 0.8305 | −0.011（持平／微降） |
| **fallen_prec（静态轴）** | 0.6194 | 0.7551 | **+0.136** |
| fallen_rec | 0.7013 | 0.7538 | +0.053 |
| avg_f1 | 0.7689 | 0.8268 | **+0.058** |
| ternary_acc | 0.9070 | 0.9367 | +0.030 |
| raw ev_f1 | 0.7556 | 0.8269 | **+0.071** |
| canonical ev_f1 | 0.7603 | 0.8236 | +0.063 |

**结论：等数据下端到端几乎全面胜出**（唯一例外 fall_rec −0.011，在噪声内）。关键在**范式 × 数据量的
交互**：2,000 数据上两者接近（§4.4.2：fallen_prec 差仅 +0.013、avg_f1 +0.026），到 9,600 差距拉大
（fallen_prec **+0.136**、avg_f1 **+0.058**）——**端到端能把更多数据转成静态轴精度，两阶段不能**
（E3 自身 fallen_prec 随数据 0.632→0.619 反降）。这是 §4.5.8"证据 4"的正面验证。
*caveat*：E3-full 配方为 stride8/lr1e-3/66 轮，与 E1-full（stride16/lr1e-4/3 轮）不同；stride 已由
§4.4.3 的 A/B 证明影响 ≤0.005，lr/轮数差异无法完全剥离 → 记为"范式+配方"的整体差异。

**三组对比的统一结论**
- 相对 baseline（同类两阶段参考）：**+0.063 avg_f1 / +0.053 事件**，增益集中在精度与静态轴；
- 相对自身数据轨迹：**数据红利在 6,000 附近见顶**，全量的余量只够把静态轴与总体指标再推一点；
- 相对 E3-full（等数据、对照范式）：**+0.058 avg_f1 / +0.136 静态轴 prec**，且优势**随数据放大**。

→ **E1（端到端）的价值不是"更多召回"，而是"把数据转成静态轴判决精度"**。这既解释了它为何在
avg_f1 / acc / fallen_rec / fall_prec 上创全项目新高，也解释了它为何在 fall_rec / 事件召回上未能超越
更早的大召回模型（E3-full 0.842、E1@6000 ep4 0.848）。

## 五、过程教训（影响结论可信度，务必写入最终报告）

- **数据量不对称**：E1@2000 直接对比 E3 全量（9,600 训的时序头）不公平 → 补 E3@2000 后才得到
  干净范式结论。任何"范式 vs 数据量"的归因都必须数据同量。
- **早停造成的假象**：E1 首轮 patience=2 在 ~1.5 ep 被掐断，全量 test fallen_prec 仅 0.506、
  fall_rec 0.612——欠训练的废数字；跑满 5 ep 后 fallen_prec 0.645。结论必须基于跑满/收敛模型
  （`--early_stop_patience 0`）。
- **val 监控口径偏乐观**：val 只用每视频头窗前 64 帧，从不测尾部 64-79 帧；而 27% 的 fallen
  帧在尾部、其中 94.9% 的 fall 前因落在 [0,15]（唯一覆盖尾部的窗口 [16,80] 不含前因）→ val
  fallen_prec 高估。test 全 80 帧评估才是真值。监控口径与评估口径必须一致。
- **训练步长与评估步长耦合**：E1 训 16 / 测 8 靠两个脚本解耦；`train_phase6` 已加 `--eval_stride`。
- **E1 训练窗口 stride16 是"加速史"产物，非科学选择；实测其对泛化影响 ≈ 0**：同一 best 模型
  用 stride16 vs stride8 评估，全量 test 各指标差 ≤0.005（avg_f1 差 0.001）——模型对未训练过的
  [8:72] 窗口对齐不敏感。overfitting/泛化差距的主因是数据量（2,000 vs 9,600），非步长。
- **规则参数与 baseline 分布耦合**：RuleV2（K2=7 等）在冻结特征上调得，微调输出（E3-full/E1）
  天然不占规则便宜 → 任何"后处理红利"不能算进端到端路线的账。
- **受控实验不许加"提速"**：H 的配方必须与 E1@2000 逐项一致，否则"数据量效应"与"优化效应"
  混杂、判读作废；提速优化只留给不受控的最终模型（E1-full，§4.6.2）。

### 5.1 "event_f1"被废除、真·事件级指标确立（2026-09-11）

**触发**：E1-full 判读时出现三处互相印证的矛盾，都指向同一件事——旧 `event_f1` **名实不符**：
1. 它在 **6,000 数据即饱和**（0.8276→0.8269），而 avg_f1 仍一路升（0.805→0.827）→ 若当主指标，
   会得出"数据到 6,000 就够"的**反向结论**；
2. 它把 fall（动态瞬态）与 fallen（静态状态）**压成一轴**，而两者在模型上行为近乎相反
   （E1-full ep3：fall_rec 0.894 / fallen_rec 0.561）；
3. 它的正类 = fall∪fallen → **多报 fallen 能抬事件召回、从而抬 event_f1**，与论文要的
   fallen_prec 存在**方向性冲突**（奖励"召回复古"型模型）。

**诊断（读实现）**：`eval_p9e1_dual.binary_event_metrics` 实为**逐帧二值 F1**（GT: fall|fallen 帧；
Pred: ≠normal 帧），**无事件匹配 / 无时间 IoU / 无延迟 / 无容差**。而规划（`0831…规划.md`）写的是
"event_f1（RuleV2 后）：**事件级**指标" → **名实不符**。

**替代与验收**：改用项目现成的 `utils/timeline_metrics.py`（逐视频时间线质量指标）。验收标准按
"**GT 当预测喂入必须 100%**"：
| 检验（1,200 视频） | 结果 |
|---|---|
| GT 自检 fall_f1 / fallen_f1 / avg_f1 | **1.0000 / 1.0000 / 1.0000**（211/211 满分）|
| GT 自检 覆盖率 F/N、误报、延迟 | 1.0/1.0、0/0、0 |
| 负对照 全 normal（200 视频） | F1 **0.000**、覆盖率 0、延迟 None |
| 负对照 GT 后移 3 / 10 帧 | fall_f1 **0.858 / 0.551**、延迟准确读出 **3 / 10** |

**同时暴露该模块两处缺陷**（引用时必踩）：
1. `order_correct` 在"全漏"时也判 True → 负对照里"全 normal"得到 order_correct=1.0 →
   **必须与 detection_rate 联读**，不可单独当"时序正确率"引用；
2. 逐视频 F1 的**分布桶不互斥**（`1.0` 也被计入 `0.8-1.0`）。

**指标定义**（先定义后使用；下表分母为本节实测值）：

| 指标 | 分子 | 分母（适用人群） | 口径 / 说明 |
|---|---|---|---|
| **覆盖率** detection rate | 该视频内**至少报过一次**该事件 | **含**该事件的视频（fall **211** ／ fallen **150**） | 视频级；衡量"整段漏掉"，是漏报的最严代理 |
| **误报率** false alarm rate | 该视频内**报过**该事件 | **不含**该事件的视频（fall **989** ／ fallen **1050**） | 视频级；**lying 属 normal → "把躺下报成跌倒/倒地"即计入此处** |
| **逐视频 F1** | 该视频内的帧级 TP/FP/FN | 仅在**含**该事件视频上计算 | 帧级但**每视频等权**；非事件视频记 `None` **被排除而非记 0**（GT 自检能满分的关键）|
| **翻转数/视频** | 预测 0/1 序列相邻取值变化次数 | 全部视频 | 时序稳定性（抖动）|
| **延迟** | `max(0, 首次预测位置 − GT 首次出现位置)` | 含该事件且被检测到的视频 | **单位 = 帧**（非历史 phase-3 的 clip）|
| **order_correct** | fall 首发早于 fallen 首发 | 同时含 fall+fallen 的视频（139） | ⚠ **全漏时亦为 True**，必须与覆盖率联读 |

> 两轴分母不同（211 vs 150；989 vs 1050）→ **`F`（fall 轴）与 `N`（fallen 轴）两列不可直接互比**。

**新指标读数**（1,200 视频 / 211 事件视频；**延迟单位 = 帧**）：

| 模型 | fall_f1 | fallen_f1 | avg_f1 | 覆盖率 F/N | 误报率 F/N | 翻转/视频 | 满分视频 |
|---|---|---|---|---|---|---|---|
| baseline | 0.7291 | 0.6584 | 0.7051 | 0.953/0.807 | 0.088/0.079 | 1.41 | 12/211 |
| E3-full | **0.7488** | 0.6538 | **0.7077** | **0.976/0.820** | 0.068/0.071 | 1.45 | 13/211 |
| E3@2000 | 0.6927 | 0.5472 | 0.6347 | 0.962/0.720 | 0.060/0.055 | 1.48 | 10/211 |
| E1@2000 | 0.6787 | 0.5700 | 0.6181 | 0.882/0.720 | **0.022/0.045** | **0.81** | 16/211 |
| **E1-full best** | **0.7827** | **0.6989** | **0.7413** | 0.962/**0.833** | 0.026/**0.035** | **0.63** | **21/211** |
| E1-full ep3 | 0.7216 | 0.5294 | 0.6534 | **0.972**/0.680 | 0.031/0.023 | **0.51** | 19/211 |
| GT（天花板） | 1.0000 | 1.0000 | 1.0000 | 1.000/1.000 | 0.000/0.000 | 0.32 | 211/211 |

- **交叉验证（部分成立）**：4 个缓存模型上新指标 fall 轴排序（E3-full 0.749 > baseline 0.729 >
  E3@2000 0.693 > E1@2000 0.679）与 instance `fall_rec`（0.842 > 0.792 > 0.714 > 0.709）完全一致。
  **但加入 E1-full 后两口径分歧**：E1-full best 的逐视频 `fall_f1` **0.783 反超 E3-full 0.749**，
  而其 instance `fall_rec` 0.8305 却**低于** E3-full 0.842 → **两口径互补、非冗余**：instance 按帧
  数聚合、受各事件视频内帧数分布影响；per-video F1 只在 211 个事件视频内计算、**每视频等权**，
  衡量"每个事件是否被处理干净"（短事件不吃亏）。
- **旧指标看不到的新信息**：
  1. **端到端时间线显著更稳，且数据越多越稳**：翻转/视频 E1@2000 **0.81** → E1-full best **0.63** /
     ep3 **0.51**，而 baseline/E3 为 **1.41–1.48**（E1-full 仅为其 ~40%）。
  2. **E1-full best 在新指标上全面最优**：逐视频 `fall_f1`/`fallen_f1`/`avg_f1`、fall/falle 覆盖率
     （0.962/0.833）、误报率（0.026/0.035）与满分视频数（**21/211**）——仅 `fall` 误报率被 E1@2000
     以 0.022 vs 0.026 微弱领先。
  3. **E1@2000 呈双峰**：满分视频最多（16）而 F1=0 也最多（25）、覆盖率最低（0.882）→ 要么整段报对、
     要么整段漏掉；全量后这一双峰被抹平（best：满分 21、F1=0 降到 8）。

**结论**：`event_f1` **降级为历史对照**（仅保留与 baseline 0.7735/0.774 的接续性）；主报告用
`avg_f1 + 四轴 + prec/rec 前沿`，事件侧一律用本节的 timeline 指标（覆盖 / 延迟 / 翻转 / 误报）。
**新指标对端到端范式是有利的证据**：在"每事件是否处理干净""时序是否稳定""误报是否可控"三项上，
E1-full best 均领先所有对照（含 E3-full），而这三点旧口径完全测不到。
复现：`experiments/eval_timeline_metrics.py`；pv dump 由 `eval_p9e1_dual.py --dump_pv` 产出
（重跑结果与已归档 `eval_best/ep3.json` **逐位一致**，可复现性已验证）。

## 七、统一结论与下一步

**统一结论**（阶段九两条线的合流）

1. **分解假设成立（E3，§3.4）**：动态轴（lie_down vs fall）帧级可学 → fall_rec +0.050；静态轴
   （lying vs fallen）帧级不可学（单帧无前因信息）→ 静态轴必须靠时序整合。
2. **端到端确为静态轴出路，且优势随数据放大（§4.4.3、§4.6.4）**：同 2,000 数据上 E1 与 E3 接近
   （fallen_prec 差 +0.013），到 9,600 差距拉大到 **+0.136**；两阶段自身的静态轴精度随数据**不升反降**
   （0.632→0.619），端到端则上升（0.645→0.755）。
3. **但"全面新最优"未达成（§4.6.3、§4.6.4）**：E1-full 创 `avg_f1 0.8268`、`acc 0.9367`、
   `fallen_rec 0.7538`、`fall_prec 0.6951` 全项目新高，**未超** E1@6000 的 `fallen_prec 0.795` 与
   `raw ev_f1 0.8325`；§4.6.3 的三条判据对 val-selected best 仅 1/3 通过。**归因 = 数据红利有轴依赖性**：
   2,000→6,000 是主战场（召回/事件 +0.07~0.14），**6,000→9,600 只剩静态轴与总体**（fall_rec 不升反微降）。
4. **范式的净收益定位：把数据转成"静态轴判决精度"**（§4.6.4）——相对 baseline `+0.063 avg_f1`、
   `+0.053 事件`（且 baseline 需靠 RuleV2 才够到 0.7735，E1-full 裸模型 0.8269）；相对 E3-full
   `+0.058 avg_f1`、`+0.136 静态轴 prec`。
5. **指标侧（§5.1）**：名实不符的 `event_f1`（逐帧二值却被当"事件级"）**废除**，改用
   `utils/timeline_metrics.py` 的覆盖率/误报率/逐视频 F1/翻转数/延迟——新指标下 **E1-full best
   全面最优**（fall_f1 0.783、覆盖 0.962/0.833、误报 0.026/0.035），且**端到端时序显著更稳**
   （翻转/视频 0.63 vs baseline/E3 的 1.41–1.48）。

**下一步**

- **论文写作**：主叙事 = 「分解假设（E3）→ 端到端（E1）→ 数据轴依赖性（E1@2000→6000→full）」；
  **E1-full 非全面新最优，须如实表述**（avg_f1/acc/静态轴新高，事件轴/召回饱和）。
- **若要冲 `fall_rec`/事件轴**：方向是"训更久 + 阈值/后处理调优"，但会牺牲 `fallen_rec`
  （沿训练时长存在陡峭 prec/rec 前沿），**须先定死目标轴**再投入。
- **工程修正**（下一阶段起步即做）：`val_check` 改 stride 8 + 视频 ≥300（或协议对齐的 val）；
  **保留 top-k ckpt**（现 `best_model.pt` 被覆盖，中间候选不可恢复）。
- **若继续端到端**：`E1b`（强化静态轴目标：事件级/对比 loss）在规划中留有入口
  （`docs/0831实验第九阶段规划.md`）。
