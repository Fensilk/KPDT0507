# 第9阶段规划：微调 DINOv2（ViT-g）

> 草案，待讨论细化。

## 目标

让冻结的 ViT-g 帧特征学会区分"两个难区分"：
- **静态 lying vs fallen**（都是"人在地面"，只差因果/受控性）
- **动态 lie_down vs fall**（都是"人下降"，只差受控性）

第八阶段已证明：任何低层增补特征（加速度/光流/姿态）都无法在不牺牲 fall/fallen 召回
的前提下压低 lying→fallen 误报；根因是**冻结的 ViT-g 特征不携带这些语义属性**。
本阶段唯一的出路是**微调 DINOv2 本身**，让特征提取器自己学会区分所需的高层语义。

数据侧方向（剔除无前因视频）已在 P9/P9b 实验中被证伪：剔除后 fallen_prec 反而下降，
说明瓶颈确在模型能力而非标签噪声——进一步强化了本阶段的必要性。

## 为什么微调从 LoRA 起步

**LoRA（低秩适配）**：不直接更新预训练权重 W₀，而是冻结它、在旁边加两个低秩矩阵 A、B，
只训练 A/B（W_new = W₀ + α·B·A）。对 ViT-g（约 1.1B 参数）只在注意力层 q/k/v/o 上插
adapter，可训练参数从 11 亿降到几百万（约 0.1%）。直觉：强预训练特征本身已会看东西，
任务只需把它"往特定方向轻轻推一下"，所需的权重变化落在一个低维子空间里。

**第一步选它而非全量微调的理由**：

1. **显存**：全量微调 1.1B 的 ViT-g，光模型+优化器+梯度就 ~17GB（fp16），加激活值和
   时序模型在 24GB 上很紧张，本地 4060-8GB 完全不可行。LoRA 只训练几百万参数，显存富余。
2. **任务性质匹配**：第八阶段诊断是"冻结特征缺因果/受控性这类特定语义属性"——这是对
   强基础特征的精修，不是重造；需要的正是低维修正，LoRA 与之吻合。
3. **防灾难性遗忘**：在 12,000 个合成视频的小数据上全量微调通用特征，极易过拟合合成域、
   练崩通用能力。LoRA 把更新锁在低秩子空间，破坏面小得多。
4. **探索阶段要便宜**：Phase 9 第一步是试探性的（微调能否救活 lying-vs-fallen 未定），
   LoRA 训练快、可快速扫 rank/学习率，失败成本低、好及时止损。
5. **推理零开销、管线兼容**：训练后把 BA 合并回 W₀，推理速度不变；用适配模型重新抽取
   1536d 帧特征喂给现有时间模型，与 baseline 对比干净。
6. **标准方案**：LoRA（Hu et al., 2021）是高效微调事实标准，peft 库支持，实现风险低。

若 LoRA 端到端跑完容量不足（fallen_prec 上不去），再升级到"最后几层全量微调"或
"全量微调 + 梯度检查点"——由浅入深，每步有对照。

## 为什么先 E3（两阶段帧级）后 E1（端到端）

**E3 不是整体 go/no-go，而是分解诊断。** lying-vs-fallen 的瓶颈可拆成两条可学性
不同的轴：

| 难区分 | 信息在哪 | 帧级可学吗 |
|--------|---------|:---:|
| 动态 lie_down vs fall | 受控性——在运动过程本身 | ✅ 单帧可能可学 |
| 静态 lying vs fallen | 因果——在前因动作 | ❌ 单帧无此信息 |

E3 的帧级目标恰好把两条轴**分开测**，结果按诊断矩阵读，而非"有效/无效"二值：

- **动态轴改善、静态轴不改善** → 证实"受控性帧级可学，静态终态必须靠时序整合" →
  端到端（E1）是唯一出路，且事先知道它针对哪条轴；
- **两条轴都不改善** → 连帧级可学的受控性都学不出来，ViT-g 微调在此合成域难学到东西，
  E1 预期也要下调，先审视目标/数据是否匹配；
- **动态轴就有改善** → 微调特征确实有用，E1 的起点更好。

**顺序决策的其他理由**：

1. **E3 便宜**：帧级、无时序模型，Stage 2 复用现有 `train_phase6.py` 管线（只换特征
   NPZ），本地 4060 可跑；远低于 E1 需要的数据管线重写 + 显存优化成本。
2. **给 E1 准备解释框架**：E1 跑完能归因"改善来自哪条轴"，而不是一个解释不清的总分。
3. **补充零成本诊断**：微调前先对现有冻结特征做 fallen-vs-lying 线性/非线性探针
   （几分钟，无需训练）；若探针显示单帧特征无可分性，则"单帧无信息、只能靠时序"更硬。

注意：E3 的**阴性结果不能排除 E1 有效**（两者目标不同，E3 只测帧级）。这正是它作为
分解诊断而非 go/no-go 的原因。

## 改进方向

1. **LoRA 微调 ViT-g（端到端）**：在 ViT-g 的注意力层插入 LoRA adapter，
   与现有时序模型（Transformer/LSTM）**联合训练**，直接优化逐帧三元分类。
   - 显存友好：3090-24G 上可行（gradient checkpointing + 小 batch）；
   - rank 默认 16，可调。
2. **帧级先微调、后冻结**：先用逐帧三元/对比目标微调 ViT-g（无时序模型），
   再冻结新特征训时序模型。两阶段解耦，显存压力小，可作对照。
3. **全量微调（备选）**：如果 LoRA 不够，尝试低学习率全量微调最后若干层。

## 预期实验（执行顺序）

- **E3（先做）**：帧级预微调 + 冻结特征 + 时序模型（两阶段）——分解诊断，便宜，复用现有管线
- **E1（后做）**：LoRA 端到端（ViT-g LoRA + Transformer, window 64 / stride 8）——主攻，静态轴唯一出路
- E2：LoRA rank 敏感性（r=8/16/32）——平衡"适应任务"与"防灾难性遗忘"
- E4：微调数据量与正则敏感性（dropout / 学习率 / 微调轮数上限）

## 评估指标

主指标（跌倒检测视角，同第八阶段）：
- **fall_rec / fallen_rec**：漏报保护线，不可牺牲（baseline 0.792 / 0.698）
- **fall_prec / fallen_prec**：误报控制，重点看 **fallen_prec** 能否突破 0.627
- **event_f1（RuleV2 后）**：事件级指标，baseline 0.774

test 报两组：全量 test（1,200）与过滤后 test（1,046，剔除无前因样本）——
后者反映"剔除不可验证样本后"的模型能力上限。

## 关键风险

- **灾难性遗忘**：DINOv2 是通用视觉特征，微调可能损伤泛化 → LoRA + 低 lr + 限制微调轮数
- **显存**：ViT-g 约 1.1B 参数，端到端联合训练需 gradient checkpointing，可能需降 batch
- **特征复用**：现有 1536d 特征文件是冻结版，微调需重建 `omnifall_dinov2_giant_frame.npz` 或改训练管线
