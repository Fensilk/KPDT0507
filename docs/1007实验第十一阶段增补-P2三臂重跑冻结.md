## 0. 参照系 = **基线 E1-full**；**不引用 W2 的任何东西**

## 1. 设计

### 1.1 三臂

| 臂 | 相对基线命令的差异 | 输出 |
|---|---|---|
| **`p2_anchor`** | **无**（逐字复刻 E1-full） | `logs/phase11/p2_anchor/` |
| **`p2_1a`** | `+ --use_boundary_head --boundary_lambda 0.3` | `logs/phase11/p2_1a/` |
| **`p2_4`** | `+ --pose_npz data/omnifall_pose_semantic_accel.npz` | `logs/phase11/p2_4/` |

其余 flag（含 `--val_data/--val_n/--val_every/--seed/--workers`）**一律不动**。

### 1.2 训练期的 val：**原样保留**（含那份旧 150）

**它不影响训练轨迹**——代码逐条追过：

| 潜在耦合 | 实际 |
|---|---|
| 早停 | `patience 0` → `no_improve` 算了但**永不触发** |
| BatchNorm running stats | 无 BN（DINOv2 与时序头都用 LayerNorm） |
| dropout 的 RNG | val 在 `eval()` + `no_grad()` 下跑，**不抽样** → 主进程 RNG 流不受扰动 |
| DataLoader / shuffle | `val_check` 直接 for 循环遍历 `WindowCache`，**不走 DataLoader**；训练的 `persistent_workers` 在子进程 |
| 优化器状态 / cudnn autotune | 均不碰（`benchmark=False` 默认） |

**留着它的理由不是功能，是忠实性**：它在**新设计里已经没有用途**
（`best_model.pt` 冗余——我们要存全部检查点；shortlist 用离线的新配平 val）。
但留着 ⇒ `p2_anchor` 与 E1-full 的差异**只剩环境**，这是可核查的事实；
删掉 ⇒ 多一个"我论证过但没实测"的等价性假设。**代价 32 min/臂（≈3%），买这个保险。**

### 1.3 ⚠ 三台 host driver 不一致（**记录在案 + 已定处置，2026-10-07**）

实测：

| 机器 | host driver |
|---|---|
| **I1**（anchor，**暂停待 595 机器**） | 580.105.08 |
| **I2**（1a）/ **I3**（4）（先跑） | **595.71.05** |

决定数值路径的三样**三台完全一致**：**cuDNN 91002 / CUDA 12.8 / compute capability (12,0)**
（cuDNN/cuBLAS 随 torch wheel 打包，**不由 host driver 决定**）→ 判为**极可能无数值影响**，
但这是**判断**，不是已消除的事实。

**处置**：**I2/I3 先跑；I1 暂停，等一台 driver 595 的机器** ⇒ 三台全 595 ⇒
**R3（主事件）的两侧同环境**。

**R2 需不需要为此打折？——不需要（前稿写"R2 混入 driver 差异"，那是自相矛盾的过度保守，已撤）。**

理由：决定数值路径的组件**旧新两侧全同**——cuDNN **91002** / CUDA **12.8** /
compute capability **(12,0)** / torch **2.8.0+cu128**（三台逐一核对）。
host driver 只提供底层接口，**不参与 cuDNN/cuBLAS 的核选择**，因此**不是数值变量**。
→ **R2 仍是纯 run 间 band**，无需打折。

> 记一条纪律：**核实过的事情不要再加一句反向的警告**。前稿一边给出"数值组件全同"的核实结果，
> 一边写"混入 driver 差异"，两者不能并存——这种自相矛盾的过度保守会让读者无法判断该信哪句。

**I1 的定位重申**：**它不是新基线**。它的作用是**滤除环境与选点变化**，
使 I2/I3 有一个"同批次、同环境、同规则"的对照。**已发表 E1-full 仍是报告口径**（§4 第 1 条）。

### 1.4 新增：**每个 val 检查点存一份 ckpt**（唯一对训练侧代码的改动）

* 新增 flag `--save_every_check`：在每 `--val_every` 步的 val 检查后存
  `step_{N}_model.pt`（48 份/臂，41.5 MB × 48 ≈ **2 GB/臂**）。
* 目的：让**离线全评**有密集候选池可用——只存 epoch 边界的话，"val 最优点"可能压根没被存下来
  （1006 实测过：锚点的平滑极大落在未被存的步上）。训练计算量**不变**。
* ⚠ 这是"改动 val 相关路径"，按本项目教训**冒烟必须用 `--val_every 1` 逼出该路径**（A.5）。

### 2.1b 与 W2 彻底脱钩（2026-10-07 定）

**P2 的参照系只有两个**：基线 **E1-full**（R1）与**同批次的 `p2_anchor`**（R3）。
**不引用 W2 的任何数字、结论或产物。**

理由：W2 是本阶段**执行有缺陷**的那一轮（对照跨环境 + 未执行选点规则），
它既不是对照物、也不是判据来源。**I2/I3 是「从 W1 筛出的两个臂」**，
P2 做的是**按规划该有的样子把那次实验重做一遍**——不是"对 W2 的复核"。

**由此产生的两条后果（必须随结论声明）：**

1. **本实验不产出"纯 run 间 band"。** R3 给出的是**同环境单变量的效应量点估计**（效度好、干净），
   但**没有误差棒**——它回答不了"这个差有多少是这一次跑的运气"。
2. **R1 不能充当 band**（初稿写"保守上界"，**错，已撤**）：R1 ≈ δ(环境) + ε(重跑)，
   **单次实现里两者可反号相消**（δ=+0.03、ε=−0.05 → R1=−0.02，幅度比 |ε| 还小）→
   幅度**既非上界也非点估计**。只有**方差**口径（且需独立假设）才有 `Var(R1) ≥ Var(ε)`，
   那是**分布参数**的界，拿它当 band 是偷换概念。
3. 要 band 须**同环境、换 seed 复跑**（**未决**，见 §4b）。

### 2.2 判据：**曲线为主，§7.3 为辅**（并标注噪声敏感性）

| 优先级 | 判据 | 为什么 |
|---|---|---|
| **主** | **曲线口径**（P@R=0.80 + 支配关系），对照 `p2_anchor`；并按 **§2.4 做多 ckpt 平均** | **对落点不变**——它测的是"能力/前沿"，不是"这次落在哪"；本阶段已用**两道验收**验证过（§7.2b） |
| 辅 | **§7.3 五项**（阈值**沿用、不得重算**）：`fall_prec > 0.6951`、`fall_rec ≥ 0.8205`、逐视频 `fall_f1 > 0.7827`、`fallen_prec ≥ 0.7351`、逐视频 `avg_f1 ≥ 0.7213` | 单点 + **余量 0–0.02**，而落点噪声 **0.076–0.179** → **噪声主导，仅供辅助** |

> ⚠ **不得因 `p2_anchor` 的数字与 E1-full 不同就移动阈值**——那是事后挪球门。

**§7.3 的噪声敏感性必须随结论声明**：五条相对锚点的余量是 **0 / 0.01 / 0 / 0.02 / 0.02**，
而**同一臂内仅换一个 ckpt** 的单点摆幅就有 **0.076–0.179**。
→ **一个真实能力与锚点相同的模型，落在阈值哪一侧基本是抽签。**
这正是 §7.2 被废止的原因（§7.2b 原话：「阈值低于指标自身的噪声带，**在原理上无从区分"效应"与"落点"**」），
而 **§7.3 从未被同样审查** → 因此**不得以它为主判据**。

**为什么不把 §7.3 提为主**：对调会让判定由落点噪声主导（R3 的效应 0.02–0.06 会被 0.08–0.18 的落点噪声淹没），
等于把 §7.2 的错误制度化。
对调**看似**的好处是让**事件轴**重新有牙齿（§7.3 有 ③a/③c 两项逐视频，曲线口径只覆盖帧级）——
但那副牙齿同样是单点、且其噪声从未量过，**不是真收益**。
→ **事件轴的洞照旧登记**（总结 §8.2 第 1 条：事件侧没有曲线工具、事件轴否决条款空缺），**不靠 §7.3 假装补上**。

### 2.3 决策规则（**先写下，跑后照办；自成一体，不引用任何旧结论**）

| 判据 | 作用 |
|---|---|
| **曲线口径（主）+ 多 ckpt 平均（§2.4）** | 给出 `p2_1a`/`p2_4` 相对 `p2_anchor` 的**能力**比较 → **判定依据** |
| **§7.3 五项（辅）** | 作为**辅助读数**并列，**标注噪声敏感性**，**不单独用于判定** |
| 两者若**指向不同** | **如实并列**，并写明分歧来自"能力"与"落点"是两个不同的量 |

### 2.4 多 ckpt 平均（**本次新采纳**；这正是 §7.2b 条款④ 写着"本阶段未做"的那一条）

* **做什么**：每个臂把它 **48 个密集 ckpt 的全部**前沿**平均**后再比较——而不是只比选出来的那一个。
* **为什么**：落点噪声（0.02–0.14）**大于**待检效应（0.02–0.06）；平均后该分量的方差按 **1/√k** 缩小
  （k=48 → 约 **7×**）。
* **压不掉什么**：48 个 ckpt **同属一次训练、彼此相关** → **它压的是落点噪声，压不了"换一次训练"的波动**。
  后者仍需**换 seed 复跑**（未决，§4b）。两者**互补，不互替**。
* **口径冻结**：明写"对**全部 48 个** ckpt 平均"——**不得事后缩小到对自己有利的子集**。

## 3. 离线选点：**全评（不设 shortlist）**

| 段 | 做什么 | 成本/臂 |
|---|---|---|
| ① | **48 个密集 ckpt 全部**在 **val.csv 全量 1200** 上评分 → 按 1006 的 F6+F7（读法 A）取最大 | 一次性解码 5 min + 48×12.5 min = **≈10.1 h** |
| ② | 选中者 + epoch 末尾 3 个 + 次优 1 个（共 5 个）跑 **全量 test 1200** → 三口径 + 曲线 + §7.3 + 逐视频 + 边界 | 5×24 min = **≈2.0 h** |

**为什么不做两段式**：两段式唯一的作用是省钱，代价是**多引入一条规则**（"先用小 val 取 top-k"），
于是要额外解释"为什么 k=8 而不是 6 或 12"、并押注"小 val 不会漏掉真最优"。
实测还表明该押注难以兑现：**ρ 是排序质量、不是漏检率**，而现有数据每个池只有 4 个候选，
**映射不到"48 选 8"**。→ **多花 ≈¥28 买判据只剩一条**（48 个候选里取全量 val 最大），值得。

* **配平说明（已实测，见 1006 附加分析）**：`val.csv` 全量与 `test.csv` 的**帧级三元分布差 ≤0.63pp**
  （fall 6.35/6.78%，fallen 8.31/7.69%，normal 85.34/85.53%）→ **val.csv 本身就是配平的，无需人为对齐**。
  当前旧 150 的 fallen 密度是 test 的 **1.63×**（正好复现规划 §6.2 的 1.62×），那是 **150 的抽样噪声**。
* **读出台账**：既然 1006 已实测**选点本身不稳定**（全量 1200 下 `1a` 72%、`4` 57%），
  R3 除选中的那个外，**必须并列报 epoch 末尾 ckpt（固定网格，跨臂可比、且是 R1/R2 的依凭）**。

1. **协同性检验**——两臂的落点波动是否同向。同向则"臂−锚点"的差值比单臂更稳，**这是唯一能翻案的情形**。
