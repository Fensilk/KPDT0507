## 0. 一句话结论

**本阶段按预登记标准「未达成功」。** 两个候选手段（显式边界监督、外部姿态输入）在 9600 全量上
**都没能实现"提升 fall 轴且不拆其它轴"**：

- `1a`（boundary head）在 9600 上**被锚点支配**（曲线口径硬否决），且其声明机制
  "显式监督 → 边界定位改善"在边界指标上**得到零改善**（+0.005）；
- `4`（姿态 12d）在 9600 上**曲线强通过**（支配锚点的静态轴），但**事件级全面退化**，
  §7.3 只过 2/5；8 个 ckpt **无一全过 §7.3**。

**但本阶段产出了三条比"成功/失败"更有价值的东西**：① 判据方法学的完整闭环（曲线口径 + band + 指标验收）；
② 一条有机制解释的负结果（**显式监督的收益在数据充足时被隐式学会**）；③ `@2000 → @9600 不转移`
的**第二次实测复现**（秩反转）。

> **对规划各条既定假设的逐条结论见 §6.1**（手段类假设 / 判据与协议承诺 / 风险登记 R1–R8 兑现 /
> 未执行项，各一张表）。⚠ 本阶段在**模型改进**侧只有 **1 条**成立（§6.2 A 组），
> 且它同样**未过 §7.3 成功标准**。
>
> **（2026-10-07 增补）**规划 §6.3 的选点规则**从未被执行**，已补做并**收束**：
> 用重建的 val 重评 12 个 ckpt 后，**三个 run 仍都选各自的 `best`**（= 现状），
> 故**对照物与 §7.3 阈值均不动**，上面的判定**不受选点噪声影响**（详见 §6.1.2b）。

## 1. 阶段目标与设计

**目标**：在主攻轴 = **fall 轴边界**（fall onset / fall→fallen 切换的定位）上取得可复现的显著提升，
**且不拆掉静态轴与事件稳定性**。

**为什么只动"监督信号"与"时间尺度"**（规划 §1.3）：前五条杠杆均已被历史阶段关闭 ——

| 方向 | 关闭依据 |
|---|---|
| 时序解码器 | Phase 6，三种解码器差 <0.2pp |
| 损失权重 / Focal γ | Phase 5，19 组无一超越默认 |
| 特征层增补 | Phase 8，5 特征 × 4 集成全败（静态轴） |
| 数据清洗 | Phase 9，P9 / P9b 一致否定 |
| 模型容量 | 秩截断 r16→r4 指标不变 |

**监督信号**与**时间尺度**是"从未被触碰"的两个维度 → 立项理由。

**三波两闸门**：W1（2000 止损筛选）→ 闸门 1 → W2（9600 确认）→ 闸门 2 → W3（收尾）。

**预算**：规划 96–156 GPU 小时；**实际** 两臂 @9600 并行 ≈ 16.5 h 墙钟 / ≈￥115（换卡，见附录 A.1）。

### 2.2 判据改写（本阶段方法学结论之一）

原 §7.2 用**单点** `fall_prec`/`fallen_prec` 比大小（阈值 0.02–0.05）。实测证明它**没有判别力**：

- 同一臂内**仅换一个 ckpt**：`fall_prec` 摆 0.119、`fall_rec` 0.166、`fallen_prec` 0.179
  —— **全部超过阈值 2~9 倍**
- 这些 ckpt 的 (prec, rec) 落在一条**陡峭前沿**上（r = −0.955 ~ −0.988），而 `avg_f1` 极差仅 0.035

→ **判定改为前沿曲线口径**（规划 §7.2b）：**P@R=0.80（两轴并列）+ 支配关系**。

**后果**：`1a` 由"硬否决"改判为"强通过"。修订经**两道验收**（自测=基准→无可判定差异；负对照→硬否决触发）。

## 5. 本阶段的方法学结论（**最有价值的一节**）

> 本阶段真正的产出不在"哪个臂更强"，而在**判据与指标本身被反复证伪并修正**。
> 以下六条独立于任何臂，可直接用于后续阶段与论文方法章节。

### 5.1 判据必须对"落点"不变，否则在原理上无从区分效应与噪声

**现象**：同一臂仅换一个 ckpt，单点指标摆动 0.119~0.179，**远超原判据阈值**。
**根因**：ckpt 差异主要是**沿精度-召回前沿滑动（落点）**，不是**能力差异**（前沿在哪）。
**解法**：改用**匹配召回下的精度 + 支配关系**（曲线口径），它对落点不变。
**证据**：A0 自身 (prec, rec) 相关系数 r=−0.955；`avg_f1` 极差仅 0.035（vs `fallen_prec` 0.21）。

### 5.2 `val` 不可用于跨臂/跨 ckpt 选型 —— 六臂 + 八 ckpt 双重实证

- W1 六臂：`val_max` 排序与 test `avg_f1` 排序**几乎无关**（Spearman ρ = **−0.14**）：
  val 第 2 的 `2a` 在 test 垫底，val 第 3 的 `1a` 在 test 第一。
- W2 八 ckpt：**按 val 选出的 `best`，在两臂上都是事件级最差的之一**。
**根因**：val 仅 150 视频、类分布与 test 不同（fallen 密度 1.62×），且 `best` 按 val 挑 → **落点噪声主导**。
**⚠ 已撤回的错误归因**：val→test 落差**不是**"只看前 64 帧"造成的（实测仅占 11%，见 A1）。

### 5.3 任何跨 run 的差异，**必须同时报告单臂内的 band**

band（同一模型、同一配置、**仅换 ckpt** 的波动）随配方剧烈变化：
Phase 6 0.0144–0.0712 ｜ Phase 8 中位 0.0301 ｜ E3@2000 **0.0099** ｜ E1 **0.0782**（**差 8 倍**）。
**→ 写常数会腐烂；只写原则**："差异 > band 才算差异，否则只能写'不可分辨'"。
**本阶段两次因没报 band 而误判**：§1.2 的"边界 F1 0.1810→0.2406"（已降级）、
以及 §5.3 声明的"边界指标 <0.03 不可当真"（实测 0.10–0.15）。

### 5.4 新指标必须过两道验收才可采用，且**已知缺陷随它一起声明**

边界指标（§5）采用前跑出：① **GT 自检**（GT 当预测 → P=R=F1=1.0000，τ=1/3/5 全满分）；
② **负对照**（全漏→0；真值平移容差内保真/超容差坍缩；抖动单调劣化）。
**声明了四条已知缺陷**，其中第 3 条（噪声门槛）**在 W3 被实测修正**——这正是"随指标一起声明"的用处。

### 5.5 显式监督 vs 隐式涌现：**收益会被数据量抹平**（本阶段的机制层负结果）

**定义**：*隐式涌现* = 没为该子技能写损失，期望它在优化主任务时顺带被学会；
*显式监督* = 为该子技能单独写损失（通常配单独的头），直接施加梯度。
**核心区别只有一句：梯度是否直接指向该子技能。**

本项目把显式监督用在"帧是否处于状态切换邻域"上（`1a`）。**实测回答**：

| 训练数据 | 无 head | **+ boundary head** |
|---|---|---|
| 2000 | A0 0.1810 | 1a **0.2406（+0.06）** ← 当时的"有效"证据 |
| 9600 | E1-full **0.2710** | 1a 均值 0.2016（**+0.005 ≈ 零**） |

**光靠数据量（0.1810→0.2710，+0.09）就超过了加 head 在 2000 上的收益。**
→ **机制解释（假设）**：数据充足后主 CE 已**隐式**学出足够好的边界表示；此时再挂一个
正类率仅 1.77% 的辅助头，其梯度**反过来扰动**已学好的表示 —— 显式监督从"补短板"变成"添噪声"。

> 这正是规划 §9 风险 **R2 预登记**的失败模式：「Boundary Head 的收益"已被三分类 loss 隐式学走"」
> —— 当时列为"中"概率。**本阶段把它从猜测变成了有数据支持的结论。**

**⚠ 显式监督不是免费的 —— `1c` 是活教材**：对真值 normal 帧只罚 `P(fallen)`，
而 softmax 下"压低 `P(fallen)`"有**两条等价路径**（抬 normal 或抬 fall），损失不区分
→ 模型走省事那条（抬 `fall`），`fall_rec` 0.898 全场最高 / `fall_prec` 0.564 全场最低。
**判据**：*这个辅助损失，有没有"不学该技能也能降低"的捷径？*
（`1a` 的 boundary head 无此病 —— 独立头、独立损失、不共享 softmax。）

### 5.6 `@2000 → @9600` **不转移**，且两次都是"秩反转"

| 次 | @2000 | @9600 |
|---|---|---|
| 历史（Phase 9） | `fallen_prec` 与 `event_f1` 在 6000 见顶 | 9600 回落 |
| **本阶段** | `1a` fall 轴 +0.0608 > `4` +0.0455，判据不可分辨 | **只有 `4` 转移**，`1a` 被锚点支配 |

**→ 结论：小数据档只能做"止损筛除"，不能做"择优"。** 本阶段把这条从"预登记的风险"变成"实测复现的规律"。
**配套**：因此 W1 的臂数必须收缩（只留机制最有依据的），择优搬到全量。

## 8. 遗留与下一步

### 8.1 必须解决的方法学缺口（**优先级最高**）

**（2026-10-07 更新）原缺口是"选点规则从未执行"，该缺口已部分闭合；但补执行暴露了一个更深、更该优先的缺口。**

**① 已闭合的部分**：规则已**预登记并补执行**（`docs/1006…增补-选点规则冻结.md`，开跑前冻结 F1–F8）。
做法是**零重训**——把 val 从"150 视频、只看帧 0–63"重建为**全量 1200、覆盖全片**，
重评三个 run 的 12 个已存 ckpt 再按冻结规则择一。结果见 §6.1.2b：
**三个 run 仍都选各自的 `best`（= 现状）**，故**收束**——对照物与 §7.3 阈值不动、第二步重跑取消。

**② 仍然敞开、且优先级更高的部分**：**事件轴没有选点信号**。
新 val 与帧级 test 排序 ρ=+0.955，但与事件级指标基本无关、个别强负相关
（`mean_fallen_as_fall_rate` **−0.750**），而 §7.3 五项里**两项是逐视频口径**。
→ 这不是噪声问题，是**目标错配**：**帧级的 val（乃至帧级的 test 指标）根本挑不出事件级更好的 ckpt**。
**下一阶段若继续打事件轴，第一件事是造一个事件级的选点信号**，否则无论怎么改模型，
选点这一环都在往错的方向拉。这与 §8.2 第 1 条（事件侧没有曲线工具、事件轴否决条款空缺）
**是同一个洞的两面**。

**③ 下一阶段开跑前仍须写死规则**，但要点已经变了：

1. `val` 的**口径**要显式声明（本阶段证明：视频数、帧覆盖、类配平三者中，**前两者影响小、配平影响大**；
   且"覆盖尾部 16 帧"几乎不贡献，+0.028）
2. **择一准则必须在开跑前写死**——本阶段这条是缺的（规划 §6.3 只写了流程、没写准则），
   教训是"**规则按构造不完整时，它不会被执行，也执行不了**"
3. **报告时必须给出"选点规则的敏感性"**（换规则结论是否翻转）。
   本阶段实测：换读法 C（旧 val 平滑）会在**三个 run 上全部改代表**——敏感性极大

  5090 填了稀疏 TFLOPS（错 1.35×）、`nvidia-smi` util 在容器里空载也报 100%（证据作废）。

### A.2 长任务四件套的实操坑（新增，2026-10-05）

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | **看门狗判型滞后最多 10 分钟**，期间外部监控 CPU/GPU/显存/内存**全为 0**（像挂起） | `while alive; do sleep 600; …; done; wait $PID` —— **一个轮询循环同时扛"等结束→接评测"与"查停滞"** | **解耦**：`wait $PID` 零延迟切换；停滞检查放后台子 shell。⚠ 实测判型时刻**精确等于**各 watchdog 启动后第 98 个 600s tick（算术可验） |
