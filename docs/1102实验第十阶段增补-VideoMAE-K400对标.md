## 3. 指标定义（定义先行）

> 本项目 2026-09 曾因 `event_f1` 名实不符付出代价。以下每个量均写明分子、分母、口径、单位。

| 量 | 定义 |
|---|---|
| **帧级（dense/merged）口径** | 对每个测试视频做 stride 1 稠密滑窗；每个窗口的三类 softmax 概率**写回窗口内所有帧**并在重叠窗口间**取平均**，再 argmax → 逐帧三元预测。统计分母 = **96,000 帧**（1,200 视频 × 80 帧），未覆盖帧（`pred=-1`）不计入。 |
| **acc** | 帧级三元正确率 = 预测正确的帧数 / 参与统计的帧数。 |
| **avg_f1** | 三类 F1 的**算术平均**（macro-F1）：`(F1_fall + F1_fallen + F1_normal) / 3`；每类 F1 = 2·P·R/(P+R)，分母为该类在帧级口径下的 TP/FP/FN。 |
| **P / R（类 c）** | P = 预测为 c 且真值为 c 的帧数 / 预测为 c 的帧数；R = 预测为 c 且真值为 c 的帧数 / 真值为 c 的帧数。单位 = 帧。 |
| **timeline（逐视频）口径** | 先对每个视频得到 80 帧三元预测序列，再对该视频内 fall / fallen 两个二元序列算指标；跨视频聚合时**每视频等权**。 |
| **逐视频 fall_f1 / fallen_f1** | 在**含该事件**的视频上，按该视频内的帧级 TP/FP/FN 算 F1，再对所有含该事件的视频**取平均**；不含该事件的视频**排除**，不记 0。 |
| **逐视频 avg_f1** | 每视频的 `(fall_f1 + fallen_f1) / 2`（仅当两事件均存在）；只存在一个事件时取该事件 F1；两事件都不存在时排除。再对可用视频取平均。 |
| **覆盖率** | 含该事件的视频中，模型**至少报过一次**该事件的比例；分母 = 含该事件的视频数。 |
| **误报率** | **不含**该事件的视频中，模型至少报过一次该事件的比例；分母 = 不含该事件的视频数。 |
| **翻转 / 视频** | 该视频二元预测序列中 0↔1 的切换次数；跨视频取平均。 |
| **顺序正确率** | 在真值同时含 fall 与 fallen 的视频中，预测的 fall 首帧早于 fallen 首帧的比例；已知缺陷：**全漏时也可能记 1.0**，必须与覆盖率联读。 |

> 与第十阶段汇总表的对应：§8 主表沿用第十阶段 §3 的列（acc / avg_f1 / fall_f1 / fallen_f1 /
> timeline avg_f1 / 训练时长），另补覆盖率、误报率、翻转，便于失败模式归类。

## 5. 验证与验收（先验后跑）

### 5.1 冒烟（约 10–20 min）

200 视频、1 epoch、`max_steps≈20` + 小规模 dense 评测。四项验收：

1. 模型总参数 **86–88 M**；
2. 权重加载 `missing` **仅分类头**、`unexpected=0`；
3. 前 20 step loss **有限**且整体下降；
4. dense dump 中每个测试视频的 80 帧均有覆盖（`pred >= 0`）。

### 5.2 指标读取验收（CLAUDE.md 强制）

复用 `eval_p10_timeline.py`，但仍须两道：

- **GT 自检**：把真值当预测喂入，帧级 acc/avg_f1 与逐视频 F1 应得 **1.0**；
  不含事件的视频按定义**排除**而非记 0；
- **负对照**：将预测整体平移 10 帧 / 随机打乱 → 指标应**单调劣化**。

两项都要跑出数并写进 §8。

### 5.3 全量运行

- 9,600 训练 / 1,200 验证 / 1,200 测试，5 epoch；
- 启动前写终止预案（§6），启动后配进程退出监视 + 定时进度检查。

## 6. 预算与终止预案

| 情形 | 预案 |
|---|---|
| 预估时长 | 8–12 h（冒烟实测吞吐后修正；单卡 3090） |
| loss = NaN / inf | **立即停**，诊断（降 lr 或查数据）后从头重启；**绝不带病跑完** |
| OOM | 训练 batch 16 → 8、eval batch 16 → 8 后从头重启；记录实际 batch |
| 进程崩溃 / 非正常退出 | 先判退出类型；配置错误修好后从头重启；不从未知状态续跑 |
| early stop 触发 | 记录停止轮次与 val 峰值，**不擅自加轮**（保持与第十阶段同预算） |
| 第 5 轮 val 仍在上升 | 在 §8 声明“5 epoch 可能偏短”，**不加轮**，以免破坏横向可比 |
| 定时检查发现无进度但进程存活 | 查 GPU 利用率与日志 mtime；确认卡死则停并诊断 |

监视方式：服务器端 cron/循环每 10 min 检查 `pgrep`、日志 mtime、`loss` 是否出现 `nan`；
进程退出即汇报，并给出日志路径与 tail 命令。

## 8. 结果（跑后追加；跑前为空）

> 本节在实验完成后填写，不回改 §1–§7。

### 8.1 冒烟验收

设置：200 训练视频 / 20 step / 1 epoch；随后 30 视频 dense 评测。

| 验收项 | 结果 |
|---|---|
| 参数量 | **86.23 M**（论文记 87 M） |
| 权重加载 | `missing=2 / unexpected=0 / head re-init=2`（仅 3 类头重初始化） |
| loss | 0.9808（第 20 step，有限） |
| 吞吐 | **29.3 clips/s**（batch 16，3090） |
| dense 覆盖 | **2,400 / 2,400 帧**（30 视频 × 80 帧，无未覆盖帧） |
| dense 指标（仅 20 step，不作结果） | acc 0.8854 / avg_f1 0.6925 / fall_f1 0.7426 / fallen_f1 0.4000 |

→ 管线验收通过。按 29.3 clips/s 估算全量 86,400 clips/epoch ≈ 49 min/epoch，
5 epoch + 评测约 **5–6 h**（以实际日志为准）。

### 8.2 指标读取两道验收

在 test 划分的 1,200 视频 × 80 帧上，用 `eval_p10_timeline.py` 实测：

| 输入 | 帧级 acc | 帧级 avg_f1 | 逐视频 fall F1 | 逐视频 fallen F1 | 逐视频 avg_f1 |
|---|---|---|---|---|---|
| **GT 自检**（真值当预测） | **1.0000** | **1.0000** | **1.0000** | **1.0000** | **1.0000** |
| 负对照：整体平移 10 帧 | 0.9746 | 0.9083 | 0.7748 | 0.7814 | 0.7886 |
| 负对照：逐视频随机打乱 | 0.9369 | 0.7662 | 0.3849 | 0.6178 | 0.5039 |

- GT 自检满分（n=96,000），且不含事件的视频按定义**排除**而非记 0；
- 两种负对照均**单调劣化**，随机打乱劣化幅度大于平移，符合预期；
- 键名注记：实现里覆盖率字段名为 `fall_detection_rate` / `fallen_detection_rate`
  （语义 = 本文件 §3 定义的“覆盖率”），不是 `*_coverage`。

### 8.4 失败模式与 limitations

#### 失败模式：**“fall 轴多报 + fallen 轴漏报”的方向分裂**

按第十阶段 §4.2 的四类失败模式，它最接近**保守型（漏报）**，但又不完全同类：

1. **fall（动态）轴是多报型**：recall 0.839 已略高于 E1（0.831），但 precision 仅 0.589
   （E1 0.6951）；混淆矩阵里 2,592 个 normal 帧被报成 fall，误报率 0.055（E1 的 2.1 倍）。
2. **fallen（静态）轴是漏报型**：recall 0.551、覆盖率 0.680；**49/150 个含 fallen 的视频
   逐视频 F1 直接为 0**（完全没报出）；2,085 个 fallen 帧被漏成 normal。
3. **时间线本身是稳的**：翻转 0.444（比 E1 的 0.63 还低）、顺序正确率 0.986，
   说明它不是“乱跳”，而是**稳定地漏掉静态段**。
4. 另有 26.3% 的 fallen 帧被预测成 fall（状态混淆），即部分静态段被当成了“跌倒瞬间”。

→ 这条结果对论文主线有用：**更强的预训练骨干（ViT-B、K400、86 M）把帧级分数推到基线第二，
但对“倒地状态 vs 正常躺卧”这一静态轴几乎没有帮助**。静态轴不是靠换更强外观骨干能解决的，
这与第十阶段“所有基线短板都落在 fallen”的结论一致，也支持本方法的事件级因果建模落点。

#### Limitations（按 §2.1 声明，并补充本次实测）

1. **5 epoch 预算可能偏短**：val_avg_f1 五轮单调上升
   （0.6694 → 0.7119 → 0.7324 → 0.7622 → **0.7741**），第 5 轮仍在涨，best 即最后一轮。
   按预登记**未加轮**；因此本行读数是“**同预算下**”的读数，**不代表 VideoMAE 的能力上限**。
   若要回答“它上限多高”，需另立预算梯度实验（不属本次预登记）。
2. **时间跨度偏离**：16 连续帧 = 1 s，而 VideoMAE 原生/论文冻结特征口径约 2.13 s；
   为与第十阶段其余基线同窗口构造，未单独改采样。
3. **分类头 3 类**，非论文的 16 类；**论文 Table 4 的 16 类视频级数字不可与本表比大小**。
