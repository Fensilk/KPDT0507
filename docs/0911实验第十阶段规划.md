> 日期：2026-09-11
> 状态：规划（Plan），待确认口径与预算后进入开发
> 本文件 = 阶段规划 + 六个参考仓库的逐个核查结论 + 适配方案

---

## 1. 目标与非目标

### 1.1 目标

1. 把 `reference/` 下的 6 个公开视频模型（C3D / I3D / SlowFast+X3D / TSM / TimeSformer / ViViT）
   适配到 OmniFall OF-Syn，**用同一数据划分、同一评估口径**跑出可比基线。
2. 回答论文里必须回答的问题：**通用视频动作识别模型 vs 本项目的"跌倒专用时序建模"，
   差距在哪里？** 特别是最难的 fall / fallen / lying（静态轴）三分类。
3. 产出可直接进论文的对比表 + 定性失败案例（谁是"把 lying 判成 fallen"的元凶）。

### 1.2 非目标（本阶段不做）

- 不追求复现各模型在原论文数据集（Kinetics/UCF101）上的精度。
- 不做 16 类细粒度任务，只做三元（fall / fallen / normal）。
- 不重训 ImageNet/Kinetics 预训练权重（成本不划算，且与公平性无关）。
- 不把 6 个模型都调到各自最优；目标是"代表性配置 + 统一协议"。

### 3.2 代码侧：六个仓库逐个核查结论

`reference/` 为本地第三方代码库（建议加入 `.gitignore`，不入库；在文档里只记 commit 哈希）。

| 模型 | 仓库 / commit | 框架 | 原生输入 | 权重 | 适配难度 |
|---|---|---|---|---|---|
| C3D | `reference/C3D` (71336a2) | **Caffe**（C3D-v1.1 = 完整 Caffe fork） | 16×112×112 | **仓库内无 .caffemodel** | 高 |
| I3D | `reference/kinetics-i3d` (0667e88) | **TensorFlow 1 + Sonnet** | RGB 64×224×224；Flow 64×224×224×2 | **已下载 5 套（2.1GB）** | 中-高 |
| SlowFast / X3D | `reference/SlowFast` (287ec00) | PyTorch（detectron2 生态） | 视频/帧，X3D-XS: 4 帧×采样间隔12，crop 160 | Model Zoo 可下（x3d_xs/s/m/l.pyth） | 中 |
| TSM | `reference/temporal-shift-module` (1f6a834) | **PyTorch（最轻）** | 帧目录 `img_{:05d}.jpg`，8/16 帧，224 | 官网 .pth（K400 8f/16f） | **低** |
| TimeSformer | `reference/TimeSformer` (a5ef29a) | PyTorch（自带 PySlowFast fork） | 8×224×224，sampling_rate 32 | Dropbox（K400/K600/SSv2） | 中 |
| ViViT | `reference/scenic` (a179cef) | **JAX/Flax + DMVR/TFRecord** | 32×224×224 | Google Scenic checkpoint | **很高** |

逐个核查到的关键事实（决定改造点）：

- **TSM**：数据入口在 `ops/dataset_config.py` 的 `return_<dataset>(modality)`，返回
  `(num_class, train_list, val_list, root_path, prefix)`；`main.py` 直接调用它。
  → 只要新增一个 `return_omnifall()` + 两个文本列表即可跑通，是改动量最小的一个。
- **SlowFast**：`slowfast/datasets/kinetics.py` 的标注格式就是 **每行 `视频路径 标签`**，
  解码后端可切 `torchvision`/`PyAV`；`configs/Kinetics/X3D_XS.yaml` 已给出 X3D-XS 全套超参。
  → 主要工作是把 OmniFall 转成 Kinetics 风格 CSV + 改 `NUM_CLASSES`。
- **TimeSformer**：训练路径自带 `timesformer/{datasets,models,utils}`（PySlowFast 的 fork），
  **只有可视化脚本 `tools/visualization.py` 才真正 `import slowfast`**。
  → 训练不需要额外装 PySlowFast，但需要 `fvcore` / `timm` / `einops`。
  配置关键项：`NUM_FRAMES 8, SAMPLING_RATE 32, TRAIN_CROP_SIZE 224, BATCH_SIZE 8, NUM_CLASSES 400`。
- **I3D**：`i3d.py` 直接 `import sonnet`，`evaluate_sample.py` 用 `tf.placeholder`，
  是**标准 TF1 代码（需 Python≤3.7）**；权重已就位，5 套 checkpoint 文件名与官方脚本一致。
- **C3D**：仓库只有 prototxt 架构定义（`crop_size:112, new_height:128, new_width:171, batch_size:30`）
  和 `.lst` 列表，**没有任何 .caffemodel**；C3D-v1.1 是整套 Caffe 源码（需自带 CUDA8 时代工具链）。
- **ViViT**：官方数据管线要求 **DMVR + TFRecord**（`data/data.md`），JAX/Flax 训练循环，
  全部模型取 **32 帧**输入；改成 OmniFall 需要自己写 TFRecord 生成器。

## 4. 统一评估协议（先钉死，再动手）

参考模型都是"一个 clip → 一个标签"的分类器，而我们的主线是"每一帧一个三元标签"。
两者要对齐，必须先定义转换口径。

### 4.1 主口径：帧级三元（与 E1/E3 完全一致）

1. 每个模型吃一个窗口（clip），输出三分类 logits。
2. **滑窗推理**：stride 8（与主线一致），把 clip 预测写回其**中心帧**；
   重叠处按 logits 平均（或按 max 取 fall/fallen），得到逐帧三元预测。
3. 指标：`ternary_acc / fall_f1 / fallen_f1 / avg_f1`（instance 口径，230,400 实例），
   与 `logs/phase9/e1_full/eval_best.json` 同口径直接可比。
4. 事件级：再过一次 RuleV2，报告视频级 fall 召回与 false-fallen 率。

### 4.2 窗口长度：两条线都报

窗口长度是模型的强先验，强行统一会削弱它们；但完全放开又不可比。因此：

| 线 | 规则 | 用途 |
|---|---|---|
| 主表 | 各模型**原生最优窗口**（TSM 8/16、TimeSformer 8、X3D-XS 4×12、I3D 64、ViViT 32） | 体现各模型真实实力 |
| 对照表 | 全部统一 **16 帧**（中心帧标签） | 排除窗口长度这一混杂因素 |

### 4.3 阶梯式评测（控制成本的关键）

每个模型分两档，先便宜的后贵的：

- **T1 线性探测**：冻结预训练骨干，抽 clip 级特征（全局池化），训练线性/MLP 头（3 类）。
  成本 ≈ 抽一遍特征 + 几分钟训练，用于回答"通用视频特征好不好用"。
- **T2 全量微调**：端到端训练（本阶段主结果）。

如果时间不够，ViViT / I3D 可以只交 T1 结果，并在论文中明确标注。

### 4.4 公平性约定

- 划分、种子（42）、测试视频（1200）完全一致。
- 预训练来源不同（K400/K600/ImageNet）是客观差异：主表用 **K400 同源**，
  另附"从零训练"档作参考（可选，成本翻倍）。
- 统一报告：参数量、训练时长、峰值显存、每视频推理延迟。

## 5. 共用数据准备（只做一次，所有模型复用）

### 5.1 密集抽帧

新增 `experiments/prep_p10_frames.py`（复用 `preprocessing/av_decode.py`）：

- 输入：`DATASET-omnifall/data_files/extracted/<class>/<video>.mp4`（AV1，1280×720，81 帧）
- 输出：`data/ref_frames/<class>/<video>/img_00001.jpg ... img_00081.jpg`
- 尺寸：**短边缩放到 256 后中心裁剪 256×256**（模型侧再各自 resize/crop 到 224/160/112）
- 采样：全 81 帧都存，抽样规则交给各模型 dataloader（train 随机、test 均匀）

**成本估算**：972,000 帧；JPEG q=90 约 15–25 KB/帧 → **磁盘 15–25 GB**（Autodl）。
AV1 解码是 CPU 活，PyAV 单进程约 100–200 fps，**16 进程并行约 1–2 小时**。

### 5.2 标注转换

新增 `experiments/prep_p10_annotations.py`，由 `ofsyn_frame_labels.csv` + splits 生成：

- `data/ref_annotations/kinetics/{train,val,test}.csv`：`视频路径 标签`（SlowFast / TimeSformer 用；
  clip 级标签用"窗口中心帧的三元标签"，或按窗口内多数投票）
- `data/ref_annotations/tsm/{train,val}.txt`：`帧目录路径 标签 总帧数`（TSM 用）
- `data/ref_annotations/framewise/{train,val,test}.csv`：逐帧三元标签（滑窗评测用）

### 5.3 评估脚本复用

- 复用 `experiments/eval_rule_c.py` 的 RuleV2（K1=2/K2=7/W=64）与 `utils/metrics.py` 的
  `compute_ternary_metrics`，保证与主线同口径。
- 新增 `experiments/eval_ref_model.py`：读某个模型的逐帧预测 `.npz` → 输出与
  `eval_best.json` 同结构的指标 JSON。

## 6. 逐个模型适配方案

### 6.1 TSM（**建议第一个做**，1–2 天）

- **目标配置**：ResNet50 + shift8/blockres，8 帧（对照 16 帧），224×224，三元输出。
- **改造点**：
  1. `ops/dataset_config.py` 新增 `return_omnifall(modality)` → 返回
     `(3, train_list, val_list, root_path=data/ref_frames, prefix='img_{:05d}.jpg')`
  2. 列表文件按 TSM 格式生成（见 5.2）
  3. 训练命令：
     `python main.py omnifall RGB --arch resnet50 --num_segments 8 --shift_div 8 --shift_place blockres --tune_from <TSM_K400_8f.pth> --root_path data/ref_frames --train_list ... --val_list ... --epochs 20 -b 32 --lr 0.005`
- **权重**：`TSM_kinetics_RGB_resnet50_shift8_blockres_avg_segment8_e50.pth`（官方站点直链，约 100 MB）。
- **成本**：8×224² batch32 显存约 6–8 GB（本地 4060 可冒烟，3090 跑全量）；
  9600 视频 × 20 epoch ≈ **2–4 h**。
- **风险/回退**：TSM 只做通道位移，静态轴（fallen vs lying）预期接近两阶段基线；
  若显著低于主线，正好说明"通用视频模型的时序先验不适用于跌倒因果"。

### 6.2 SlowFast / X3D（2–3 天）

- **目标配置**：先 X3D-XS（4 帧×采样12），再 X3D-S/M；三元输出。
- **改造点**：
  1. 新增 `configs/OmniFall/X3D_XS_omnifall.yaml`：复制 `configs/Kinetics/X3D_XS.yaml`，
     改 `DATA.PATH_TO_DATA_DIR=data/ref_annotations/kinetics`、`MODEL.NUM_CLASSES=3`、
     `TRAIN.BATCH_SIZE=32`、`NUM_GPUS=1`、`SOLVER.MAX_EPOCH=30`。
  2. `slowfast/datasets/kinetics.py` 可直接复用（CSV 就是 `path label`）；若需帧级标签，
     新增 `slowfast/datasets/omnifall.py` 复制 kinetics.py 改列解析。
  3. 运行：`python tools/run_net.py --cfg configs/OmniFall/X3D_XS_omnifall.yaml`
- **权重**：`x3d_xs.pyth / x3d_s.pyth / x3d_m.pyth`（Model Zoo 直链）；换 head 时注意
  `MODEL.NUM_CLASSES` 与 checkpoint 的最后一层不匹配（用 `CHECKPOINT_LOAD_MATCHING`）。
- **成本**：X3D-XS 约 3.8 M 参数、0.6 GFLOPs/帧，8 GB 显存可跑；
  9600 视频 × 30 epoch ≈ **3–6 h**（3090）。X3D-L（18 GFLOPs）另计。
- **风险/回退**：主要坑在环境（detectron2 + fvcore + PyAV/decord）。
  **必须单独建 conda env（建议 py38/py39）**，不要动 `py310`。

### 6.3 TimeSformer（2–3 天）

- **目标配置**：`TimeSformer_divST_8x32_224`（8 帧、224、divided space-time attention）。
- **改造点**：
  1. 复制配置到 `reference/TimeSformer/configs/OmniFall/`，改 `NUM_CLASSES=3`、
     `DATA.PATH_TO_DATA_DIR=data/ref_annotations/kinetics`、`BATCH_SIZE=8`（视显存）。
  2. 加载 K400 预训练（Dropbox `.pyth`），head 随机初始化。
  3. 运行：`python tools/run_net.py --cfg configs/OmniFall/TimeSformer_divST_8x32_224.yaml`。
- **依赖**：`fvcore`、`timm`、`einops`、`yacs`（仓库自带 `timesformer/` 包，
  **训练不需要安装 PySlowFast**，只有可视化脚本需要）。
- **成本**：ViT-B 8×224² batch 8 单卡约 12–16 GB；9600 视频 × 15 epoch ≈ **6–10 h**。
- **风险/回退**：小数据（9600 视频 / 3 类）上 attention 模型极易过拟合 →
  建议冻结 patch embedding、降 lr、强增强；若仍不收敛则退化为 T1 线性探测。
  仓库 2025-01 已归档，旧版 yacs/einops 版本要锁。

### 6.4 I3D（3–5 天，两条路线）

- **路线 A（官方 TF1）**：新建 `conda env tf1`（**Python 3.7 + tensorflow 1.15 + sonnet 1.x**），
  在 Autodl 上跑，输入 64×224×224 RGB。Flow 流需要 TV-L1 光流（972k 帧），
  **本阶段跳过 Flow，只做 RGB**（权重已备：rgb_scratch / rgb_imagenet / rgb_scratch_kin600）。
- **路线 B（PyTorch 移植，推荐）**：按 `i3d.py` 结构在 `models/ref_i3d.py` 复刻
  Inflated Inception-V1，然后写权重转换脚本把 TF checkpoint 映射到 PyTorch
  （关键点：BN moving_mean/var、inflated conv 的时间维复制）。
- **成本**：64 帧 batch 8 约 10–14 GB（3090）；9600 视频 × 20 epoch ≈ **8–15 h**。
- **风险/回退**：TF1 在新驱动/新 GPU 上编译困难；权重转换易踩坑。
  时间紧就只交 T1（用官方 checkpoint 抽 clip 特征 + 线性探测）。

### 6.5 C3D（2–4 天，建议 PyTorch 复刻）

- **为什么不用官方仓库**：Caffe fork 需要 CUDA8 时代工具链，Windows 不可行、
  Linux 现代环境要打大量补丁；且**仓库里没有 .caffemodel 权重**。
- **推荐做法**：按 `conv3d_ucf101_train.prototxt`（crop 112、16 帧、batch 30）在
  `models/ref_c3d.py` 用 PyTorch 复刻（8 个 3D conv + 2 FC，约 78 M 参数）；
  可选：从 C3D 官网下载 Sport1M/UCF101 caffemodel 做权重转换（否则从零训练）。
- **数据**：16 帧、112×112（从 256×256 帧下采样即可）。
- **成本**：16×112² batch 16 约 6–8 GB；9600 视频 × 20 epoch ≈ **3–5 h**。
- **风险/回退**：复刻实现需要在论文中注明"非官方实现、参数量对齐"；
  C3D 时序感受野小、预期是本批最弱基线之一。

### 6.6 ViViT（5–8 天，最后做 / 可降级）

- **官方路线**：JAX/Flax + Scenic，输入需 **DMVR 预处理成 TFRecord**，模型吃 32×224²。
  改造 = 写 TFRecord 生成器 + 数据集配置 + JAX 训练循环，且要新建 JAX 环境。
- **成本**：ViViT-B 32×224² 显存极大，单卡 3090 需 gradient checkpointing，
  batch 4–8；9600 视频训练一轮就要数小时。
- **风险/回退**：本阶段性价比最低，且与 TimeSformer 的结论高度重叠（都是视频 transformer）。
  **建议只做 T1 线性探测**（用官方 K400 checkpoint 抽特征 + 线性头），
  在论文里作为"视频 Transformer 特征质量"的参考点；若时间允许再补 T2。

## 9. 风险与回退
