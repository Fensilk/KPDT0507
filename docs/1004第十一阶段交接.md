## 三、本会话最重要的发现

### 发现 9：RTX 5090 栽在 **CUDA 代际**，不是硬件

5090 是 **sm_120（Blackwell）**，而镜像自带 **torch 2.5.1+cu124 只编译到 sm_90**。
**SASS 不跨代前向兼容** → 必须换 CUDA 12.8+/torch≥2.7 的轮子。
cu128/cu13 的依赖链（一整套 `nvidia-*` CUDA 运行时）比 cu124 长得多，镜像里没有，
联网拉取慢，改用浏览器下轮子再 scp 也没收敛 → **实例已关停，该方向放弃**。

> **普适教训**：跨代上卡（Blackwell）**前提是先拿到自带 cu128+ 的镜像**，
> 不要试图从 cu124 现场升级。**代际成本要算进选卡，不能只看算力与单价。**

### 发现 10：**换卡预测式**（本会话建立并已实测验证）

原来的"util 100% 但有效算力≈峰值 1%，疑似访存受限"**是错的**——我把
2.64 s/帧当成了 41.3 ms/帧，**差 64×**。真实：`5.28 s/步 ÷ (batch2 × 64帧) = 41.3 ms/帧`，
按 224² 折算 ≈57 TFLOPS ≈ **3090 fp16 峰值的 80%** ⇒ **确实是算力受限**。

把 batch 扫描（batch 2→4 耗时 1.95×，近似线性 ⇒ 吞吐主导）与算力受限结合：

```
每步耗时比 = 0.62 / σ算力 + 0.38 / σ带宽        σ = 新卡 / 3090
```

**验证**（3090 → A100-**PCIE**-40G）：σ算力 = 156/71 = 2.20，σ带宽 = 1555/936 = 1.66
→ `0.62/2.20 + 0.38/1.66 = 0.511` → **预测 1.96×**，**实测 1.95×（2.752 s/步）** ✅

> ⚠ **我先前估的 2.70× 是错的**——那是 **A100-SXM4**（312 TFLOPS / 2039 GB/s）的数，
> 而 AutoDL 租到的是 **PCIe 版**。**选卡必须认准 PCIe/SXM。**

**据此预测与算账**（两臂 = 28800 步 ×2 + 评测）：

| 卡 | 预测加速 | 单臂 | 两臂串行 | 时价 | **两臂花费** |
|---|---|---|---|---|---|
| **A100-PCIE-40G** | **1.95×**（实测） | 22.8 h | 45.6 h | 3.28 | **￥150** |
| RTX 4090D | 1.56× | 28.1 h | 56.2 h | 1.88 | **￥106** |
| RTX 5090 | 3.29× | 13.3 h | 26.6 h | 2.78 | ￥74 ⚠环境不通 |
| A800-80G(SXM) | 3.17× | 13.9 h | 27.8 h | 5.59 | ￥155 |

**三条读数**（详见 `reference/autodl_gpu_pricing.md`）：
- **价格几乎不随算力走**（5090 每元算力 ≈ A100 的 2.3 倍）→ **便宜档反而划算**。
- **并行不增加总花费**（每臂只跑一次，GPU 总小时数不变），**只把墙钟减半**
  → 想快应**加实例**，而非买更贵的单卡。
- **显存完全不是选卡维度**（峰值只用 11.4 GB / 24 GB）。

### 发现 11：**10 vCPU 不是瓶颈**（关闭一条此前未量化的风险）

用户曾质问"A100-40G 方案 cpu 只有 10 核带来的影响，你计算了吗"——**我没有计算**，
只答"唯一可靠的办法是实测"。**现实测关闭**：

| 项 | 实测 | 判读 |
|---|---|---|
| s/step | **2.752 s**（3090 是 5.380 s） | 加速比 **1.95×** |
| **GPU util 中位** | **100%** | **`WORKERS=8` 在 10 vCPU 上够用**，数据侧不是瓶颈 |
| 显存峰值 | 11653 MiB | 40G 只用 28% |

> 教训：**这类"管线跟不跟得上"的问题，实测一次就够，猜是猜不出来的。**
> 冒烟脚本 `_smoke_5090_pkg/run_smoke.sh` 一次同时回答兼容性、s/step、util 三问，
> 值得作为换卡的固定流程。

**两条硬结论**：
1. **"继续用 3090"不成立** —— 4090D 同架构族（sm_89，torch 2.5.1 原生支持），
   **又快又便宜**。
2. **A100 与 4090D 构成前沿**：A100 快 5.6 h、贵 ￥42 → **省下的时间合 ￥7.5/小时**。
   值不值由用户定，但这个交换比**远不如"A100 是明显更优选择"那么漂亮**。

⚠ **4090D 的 1.56× 是外推**：模型只在 **Ampere→Ampere**（3090→A100）验证过一次。
- 4090 的 L2 是 **72 MB**（3090 仅 6 MB），而模型的 `σ带宽` **只算了 DRAM**
  （1008/936 = 1.077），**没算 L2 改善** → **1.56× 大概率偏保守**。
- 但"**单核 CPU 顶不顶得住**"这条在 4090D 上**同样没有实测过**（A100 上是 100% util，够用）。
- **H800 那格不要当真**：Hopper 的优势集中在大矩阵张量运算，我们是 **batch=2 的 ViT-g**，
  小 batch 下很可能兑现不了；且跑到 13 h 时数据侧会变成瓶颈。

### 其它已知坑

- **"新开一路输入/输出"必须三处都接上：训练侧、val 侧、评测侧。**
  每漏一处 = 一轮 8.8h 白跑（Exp-4 实测爆了两次）。runner 用独立 `EVAL_EXTRA` 处理评测侧，
  **不能透传 `$EXTRA`**（eval 只认 `--pose_npz`，透传 `--use_boundary_head` 等会报未知参数）。
- **长任务四件套**：终止预案、进程级监视（判活用 `/proc/<pid>/stat` 查僵尸，`kill -0` 对僵尸无效）、
  定时进度检查、日志路径 + tail 命令 + 本地镜像。
- **`pkill -f 'pip install'` 会自匹配杀掉自己的 ssh 会话**（本会话踩过，exit 255）。
  杀进程要按显式 PID，或枚举 `/proc/*/cmdline`。
- **`pgrep -x python` 抓不到 pip**（它的 `comm` 是 `pip`）→ 用 `/proc` 枚举。
- **`read_bytes` / `ss -tn | grep ESTAB` 在本容器里不是有效的下载进度指示**
  （前者数的是磁盘读，后者在容器里报 0）。
- **评测成本**：E1 侧全量评测 = **53 min/ckpt**（3090），且是真实 GPU 前向成本
  （解码仅占 4%，批量前向无收益——ViT-g 在 64 帧 batch=1 已吃满 GPU）。
  → best 跑全量 1200、`epoch_*` 跑固定 300 随机子集。
- **eval 不是逐位确定的**：A0 重评 avg_f1 0.7665→0.7666，有 1e-4 量级运行间抖动。
- **`judge_w1_arm.py` 必须在 py310 下可跑**（本地是 3.13，会掩盖 3.12+ 才合法的语法）——
  改完请用远端 `/root/miniconda3/bin/python -m py_compile` 验一遍。
