## 0. 一页纸结论

**① 权威一轮的逐臂结论：`4` 通过主判据，`1a` 未确立。**
按规划该有的样子重做的权威一轮（**P2**：同环境、同批次、执行了选点规则）——
**`4`（姿态 12d）强通过 ✅**，**`1a`（boundary head）不确定带 ⚠**。
`4` 在**三轮独立训练上一致通过曲线口径主判据**（W1@2000 对 A0、W2@9600 对 E1-full、
P2@9600 对同批 `p2_anchor`）—— 这是本阶段**唯一**通过的模型改进方向。
> ⚠ 精确说，**支配发生在哪条轴在轮次间不同**：W1 与 P2 是 **fall（动态）轴**支配，
> W2 是 **fallen（静态）轴**支配；三轮的共同点是"**任一轴支配且另一轴未被支配**"（= 强通过）。
> 论文引用时**不要说成"三轮都在 fall 轴支配"**。

**② 但「`4` 通过」≠「本阶段成功」，差别在于**预登记的成功判据自身没有判别力**。**
规划 §7.3 是本阶段预登记的成功判据，而它五项**余量只有 0–0.02，远小于落点噪声 0.076–0.179**（§2.6）
→ 那 5/5 **基本是抽签**；P2 预登记据此已把它降为**辅读**、明令"不单独用于判定"。
剩下的主判据（曲线口径）只产出**臂级**结论 → **预登记里没有任何一条判据还能给出阶段级二元结论**：
能说的是"**`4` 通过主判据**"，**不能**说"**本阶段成功**"，也**不能**说"**本阶段未达**"（§3.5）。
> （附注：`4` 的 run 间波动也未测，但**本项目历来单次 run**，属**全局通例**，不作理由 —— 见 §3.5。）
另：`1a` 不仅未过主判据，它**声明的机制（显式监督 → 改善边界定位）也零正面证据**（§2.4）。

**③ 本阶段真正的产出不在"哪个臂更强"，而在判据与指标被反复证伪并修正。**
§5 的八条方法学结论，每一条都是"原本以为是效应、实测发现是噪声"换来的。
其中 **★问题 1–5** 那次闭环（§2.2）直接推翻并重写了本阶段自己的判据。

**④ 一句话叙事**：本阶段想用"显式边界监督 + 外部姿态输入"撬动 fall 轴边界。
在 2000 档两个都通过；到 9600 全量上，**只有姿态在三个轮次里都稳住了**，
而边界监督**连它自己声明的机制都没兑现**。
真正留下来的，是一套"如何不被噪声骗"的方法，和一条有机制解释的负结果。

## 1. 目标、设计与判据

### 1.1 目标与主攻轴

**目标**：在主攻轴 = **fall 轴边界**（fall onset、fall→fallen 切换的定位）上取得可复现的显著提升，
**且不拆掉静态轴与事件稳定性**。

**为什么是 fall 轴**：锚点 E1-full 的 fall 轴自身就是"低精度"结构 ——
`fall_prec 0.6951` / `fall_rec 0.8305`，差 **+0.135**，亏空几乎全在**误报**；
而 fallen 轴 prec/rec 基本平衡（0.7551 / 0.7538）。

**一条硬约束（决定了整个阶段形态）**：prec/rec 前沿极陡。延长训练可把 fall 召回推到 0.8939（历史最高），
但 fallen 召回同时崩到 0.5609 —— **单一检查点无法兼顾，必须先确定目标轴**。
本阶段因此把"不许压召回换精度"写成**硬否决条件**。

### 1.2 为什么只动这两件事

前五条杠杆已被历史阶段逐个关闭，**"监督信号"与"时间尺度"是仅剩的、从未被触碰的两个维度**：

| 方向 | 关闭依据 |
|---|---|
| 时序解码器 | Phase 6：三种解码器差 <0.2pp |
| 损失权重 / Focal γ | Phase 5：19 组无一超越默认 |
| 特征层增补 | Phase 8：5 特征 × 4 集成（静态轴）全败 |
| 数据清洗 | Phase 9：P9 / P9b 两变体一致否定 |
| 模型容量 | 秩截断 r16→r4 指标不变（数据受限，非容量受限） |

手段 1（改**监督信号**）与手段 2（改**时间尺度**）被**刻意拆成独立实验**：
二者机制不同，合跑无法归因，违反"唯一变量"纪律。

### 1.4 指标与判据（**定义先行**——CLAUDE.md 强制）

> 本项目 2026-09 曾因 `event_f1` 名实不符（逐帧二值 F1 却叫"事件级"）付出代价，
> 该指标已废除。以下每个量都写明**分子、分母、口径、单位**。

| 量 | 定义 |
|---|---|
| **instance 口径** | 逐**帧实例**统计（窗口重叠帧重复计入），230,400 帧实例 = 1200 视频 × 80 帧 × 滑窗。与 Phase 9 同口径 |
| **merged_raw 口径** | 逐帧**去重**后统计，96,000 帧 = 1200 × 80。与 Phase 10 通用基线同口径。两口径差 <0.01 |
| **timeline（逐视频）口径** | 每视频先聚合成一条预测序列（多窗多数投票 + 最小事件长度后处理），再逐视频算指标 |
| **P@R = r** | 扫遍判决阈值得到该类 (召回, 精度) 曲线；**P@R=r** = 召回最接近 r 的那个工作点上的**精度**。分子 = 该点上真值也为该类的帧数；分母 = 该点被判为该类的帧数。曲线口径 = `voted` |
| **支配（Pareto dominance）** | 在**共同召回支撑区间** `[max(lo,0.50), min(hi,0.95)]` 上取 **40 点网格**插值，本臂精度**处处 ≥ 基准**且**至少一处 >**。主判据取 **P@R=0.80**（两轴并列）。「至少一处 >」不可省，否则全等曲线会把自己判成硬否决 |
| **band** | 同一模型、同一配置、**仅换一个 ckpt** 的波动幅度（极差）。**它是本项目判断"差异是否可当真"的尺子** |
| **覆盖率** | **含该事件的视频中，模型至少报过一次的比例**（分母 = 含该事件的视频数） |
| **误报率** | **不含该事件的视频中被误报的比例**（分母 = 不含该事件的视频数） |
| **边界 F1** | 容差 τ 帧下，真值边界集合与预测边界集合**贪心一对一匹配**（按时间序，一个真值最多配一个预测）。P 分子 = 匹配上的预测边界数 / 分母 = \|B_pred\|；R 分子 = 匹配上的真值边界数 / 分母 = \|B_gt\|。单位 = **帧**。**不含任何边界的视频排除，而非记 0**。τ ∈ {1,3,5} 三档并列 |

**§7.3 五项判据（阈值冻结自 E1-full，全阶段不得重算）**：
`fall_prec > 0.6951`、`fall_rec ≥ 0.8205`、逐视频 `fall_f1 > 0.7827`、
`fallen_prec ≥ 0.7351`、逐视频 `avg_f1 ≥ 0.7213`。
> ⚠ **口径注记（2026-10-09 补做验收时发现）**：前三项中的 `fall_prec/fall_rec/fallen_prec` 来自
> **flat 口径**，后两项逐视频来自 **voted 口径** —— **§7.3 内部混用两个口径**，必须随指标声明。

**判定词表（全阶段统一）**：
**强通过** = 任一轴支配基准且另一轴未被支配；**不确定带** = 两轴均未支配、但两轴 P@R=0.80 均 ≥ 基准；
**硬否决** = 两轴均被支配，或任一轴 P@R=0.80 低于基准 −0.05；
**未达** = 其余情形 —— **它不是"否决"，只是"没拿到证据"**（多因剂量/样本量不足），
**不得读成"该方向被证伪"**。

### 2.1 W1（2000 档）：六臂筛选

**对照物 = `A0`**（= E1@2000 复刻，`logs/phase11/a0_2000/`）。六臂同配方，唯一变量各一个开关。

| 臂 | 机制 | fall 轴（曲线） | fallen 轴（曲线） | 判定 |
|---|---|---|---|---|
| **`1a`** | boundary head λ=0.3 | **支配** A0（+0.0608） | 交叉（+0.0268） | **强通过 ✅** |
| **`4`** | 姿态 12d + concat | **支配** A0（+0.0455） | 两端更好中段回落（+0.0411） | **强通过 ✅** |
| `1c` | 静态轴辅助损失 | 交叉（+0.0352） | 交叉（+0.0260） | 不确定带 ⚠ |
| `1b1` | 难例采样 `{lie_down}` | 交叉（+0.0162） | 两端更好中段回落（+0.0102） | 未达 |
| `2a` | 多尺度 | **被 A0 支配**（−0.0255） | 交叉（−0.0044） | 未达（**首个被支配臂**） |
| `a0cos` | 余弦退火（诊断） | — | — | 未达，方向放弃 |

**`1a` 与 `4` 判据上不可分辨**（fall 交叉 −0.0153 偏 1a，fallen +0.0143 偏 4）。

**两条必须进决策的判据外因素**：
① `4` 的推理**需要外部姿态特征** → 部署时须另跑一条姿态估计流水线；`1a` 无额外输入。
② `4` 帧级曲线支配 A0，但**逐视频 `fallen_f1`（0.5158）与 fallen 覆盖率（0.6733）反而低于 A0**
（0.5468 / 0.7267）—— 按"两口径并列、不挑有利者"的纪律如实并列。

#### 四条臂的失败，各自有机制解释（不是"结果不好"）

| 臂 | 机制层结论 |
|---|---|
| `2a` 多尺度 | fall 前沿在 40 个召回点上**处处低于基线**。预设风险 R3（+748K 参数 → 过拟合）**未以过拟合形式出现** —— 它的 `train_loss`（0.1636）反而**高于** A0（0.1348），**连训练集都没拟合得更好** → 是**整体前沿下移**，机制未归因 |
| `1b1` 难例采样 | **剂量按设计生效**（权重占比 2.63% → 7.48%，×2.84），短板是**杠杆本身偏弱**：sampler 抬 normal 窗口的*频率*，而三元 CE 类权重（normal 仅 0.132，是 fall 的 1/10）压低每个 normal 样本的*贡献*，两者**反向抵消** —— 有效梯度权重比在 (1+α)=3 时仅 **0.025**，放大到 20 倍也只有 0.170；且 `lie_down` 全池仅 **266** 个窗口，加大 α 只是**重复采样**。→ **实验无效，假设未被检验** |
| `1c` 静态轴辅助损失 | 见 §5.4 的 softmax 搭便车缺陷 |
| `a0cos` 余弦退火 | 见 §2.2 转折一 |

**难例章程（方法而非假设，✅ 成立）**：初稿的难例清单来自直觉（快速坐下、蹲下、弯腰、主动躺下），
实测**对不上模型的实际错误** —— 被点名的 `sit_down` 难度只有 **0.2×**（模型最擅长的类别之一），
而 `jump`/`squat_down` 虽"难"却"少"（合计仅占 6.2% 误报）。
→ 正确章程是三步：**量（难度 rate + 影响力 share）→ 筛（难度 ≥2× 基准 且 影响力 ≥5%）→ 验（采样分布负对照）**。
**挑难例要看"影响力"（贡献了多少错误），不是"难度"。**

#### 难例线的三个变体，各自的下场

| 变体 | 内容 | 状态 |
|---|---|---|
| **Exp-1b-1** | 难例池 `{lie_down}` | ✅ **已跑**（2026-10-01，8.83 h）→ 判 **未达**（机制见上表） |
| **Exp-1b-2** | 难例池 `{lie_down, other}` | ⏸ **暂缓、未跑**（理由见下） |
| ~~Exp-1b-3~~ | ~~切换邻域窗口加权~~ | ❌ **规划阶段即取消** —— `window64/stride16` 下每视频只切出 **2 个窗口**且并集覆盖全片 → 窗口级"边界邻域采样"是**空操作**；帧级读法则与 `1a` 的 boundary loss **冗余**。改列为 Exp-2b 的从属变体（2b 也没跑） |

**`1b-1` 的结果画像**：**"报得更多"** —— 覆盖率最高（fall 0.967）、误报率最高（0.050，≈A0 两倍）、
翻转最多（1.65 vs A0 0.95）、边界过度报告 **3.9×**；**没有转化成精度收益**（边界 F1 0.1627 < A0 0.1810）。
唯一方向性信号：`fall→fallen` 误判率降到 **0.035**（A0 0.096、`1a` 0.071）——
正是 `lie_down` 加权想压的那个方向，但被"整体报得更多"的代价抵消。

**为什么暂缓 `1b-2`**（两条，第二条更实质）：

1. **路线被 `1c` 替代** —— 同属"改配方"，而 `1c` 改动面更小（不新增参数、不改结构、不需新标签）。
2. **它与 `1b1` 用的是同一个杠杆**（难例采样器），只换池子；而 `1b1` 的短板已被定位在
   **杠杆本身**（频率 vs 贡献反向抵消），**换池子救不了**。

> ⚠ **但有一条代价要如实记**：`1b-2` 原本是**唯一**能回答
> "**难例池该不该保持语义同质**"的实验（`other` 影响力最大 **54.3%**，但语义最杂：
> 含推椅子走及各类未归类活动）→ **跳过它，这个问题悬空** ——
> 与 Exp-2b 让"多尺度思路错 vs 2a 表达力不够"悬空**同型**（§4.4）。

**难例线的净结论**：两次尝试（`1b1` 采样、`1c` 显式损失）**都没过**，
但**两次都是"实验无效 / 形式有缺陷"，不是"方向被证伪"**。
规划给的三条更对路的改法里，**(C) 显式辅助损失**已跑（= `1c`），
**(A) 拆开 normal 的 CE 权重**与 **(B) 离线难例挖掘** **未试**（见 §4.5）。

### 2.2 转折一：判据被自己的实验推翻（★问题 1–5）

**触发**：`1a` 的逐轮 Δ 指标**符号翻转**（`fallen_prec` 依次 −0.246 / +0.047 / −0.158），
而 A0 自身跨 ckpt 极差达 `fall_prec` 0.119 / `fall_rec` 0.166 / `fallen_prec` 0.179
—— **全部超过 §7.2 的判定阈值 2~9 倍**。若这是噪声，则整套 W1 判定都在噪声上做比较。

**三步排除，逐步闭环：**

### 2.4 W3：边界指标 —— 机制假设的正面检验失败

`1a` 的**声明机制**是"显式监督状态切换 → 边界判断从隐式涌现变为显式优化"。
§5 的边界指标是**唯一能正面检验这句话**的工具。结果（τ=3，组均值，正确对照 = 同一 9600 训练数据下比锚点）：

| 组 | 各 ckpt `micro_F1` | 均值 | 相对锚点 |
|---|---|---|---|
| 锚点 E1-full（无 head / 无 pose） | 0.2710 / 0.1220 | 0.1965 | — |
| **`1a`（+boundary head）** | 0.2170 / 0.2040 / 0.2535 / 0.1319 | 0.2016 | **+0.005 ≈ 零** |
| **`4`（+pose 12d）** | 0.2548 / 0.2542 / 0.2348 / 0.1554 | 0.2248 | +0.028 |

**① `1a` 装了显式 boundary head，边界定位零改善。** 单看"最好 ckpt"，锚点 0.2710 反而全场最高。
结合 W2 的硬否决 → **这条机制路线未获得任何正面证据**。

**② 更重要：该指标的噪声地板被低估了 3~5 倍。** 同一臂内**仅换一个 ckpt**，
`micro_F1` 极差即达 **0.10~0.15**（锚点 0.1490 / `1a` 0.1216 / `4` 0.0994），
而规划 §5.3 声明的门槛是 **0.03**。→ **本文关心的效应（0.02~0.06）全部落在噪声里**，
该指标在 9600 尺度**只能做粗略定性**。已作为勘误写进规划 §5.3。

**③ 线索（不下结论）**：`ep3` 在三个臂上都是各自最低、`best` 都是各自最高，
可能是"训练末段边界表示退化"，n=3 且噪声极大，仅记待查。

### 2.5 转折三：选点规则**从未被执行**（增补 1006）

收尾时发现两件事：

**① 规划 §6.3 的选点规则按构造就不完整。** 原文是"对 val 排序前 3 的 ckpt 各跑一次 test，
**在选择规则事先写明的条件下**选最终模型"—— 它登记了**流程**，把**判据内容**推给"以后再写"，而"以后再写"从未发生。

**② W2 的判定用的是被 §6.3 明文禁止的口径。** W2 报的数字取自 `best_model.pt` = **val 单点极大值**，
而 §6.3 第 1 条写的是"**选型不取单次 val 极值**"。
→ **W2 的判定不是符合规划的阶段性判定，而是"违规执行下的阶段性观察"，降级为诊断**
（数字完整保留、可查），不再是本阶段的权威判定。

**③ 实测证据表明这个偏差真的吃掉了结论**：两臂上**按 val 选出的那个 ckpt 恰恰是唯一跌破锚点的
事件级 ckpt**（`4-best` 逐视频 `fall_f1` 0.7325 / `avg_f1` 0.6873，均低于锚点；而 `ep1`/`ep2` 都高于锚点）。

**补执行（1006，零重训）**：把 val 从"150 视频、只看帧 0–63"重建为**全量 1200、stride 16 覆盖全片**，
重评已存 ckpt。四道检验：

| 检验 | 结果 |
|---|---|
| ① 规则自测 | ✅ 显然池给显然答案 |
| ② 负对照（已知最差的 `1a-ep3` 不得被选中） | ✅ 未选中（新 val 0.7540，全场最低） |
| ③ **外部效度**：新 val 排序 vs test 帧级排序 | **ρ = +0.955**（对照旧 val 的 **−0.14**） |
| ④ 剂量-响应 n=150/300/600/1200 | +0.700 / +0.573 / +0.964 / +0.955（**非单调**，只能读方向） |
| ④b 覆盖效应（只帧 0–63 vs 全帧） | +0.927 vs +0.955 → **覆盖尾部几乎不贡献（+0.028）** |

**结论一 · 收束**：新 val 下**三个 run 仍都选各自的 `best_model.pt`（= 现状）**
→ 对照物不动、§7.3 五个阈值不动、第二步重跑取消。
⇒ **W2 的判定不是"选错点"造成的** —— 选点噪声确实存在，但换成可用的 val 后选出来还是同一批 ckpt。

**结论二 · 事件轴上仍没有可用的选点信号**（新发现）：新 val 与**帧级** test 几乎完美同序（+0.955），
但与**事件级**指标基本无关、个别强负相关（`mean_fallen_as_fall_rate` **−0.750**、
`median_fallen_delay` −0.583、翻转数 ≈0），而 §7.3 五项里有**两项是逐视频口径**。
→ 正确表述不是"val 不可靠"，而是 **"帧级 val 挑不出事件级更好的 ckpt"是一个目标错配**，且**它不是噪声问题**。

> ⚠ **附带一条**：读法 C（旧 val 的末 k=3 平滑）在**三个 run 上全部要改代表**，
> 锚点那次指向的正是测试最差的 ckpt（`ep3` 的 `fall_prec` 0.5749 vs `best` 0.7027）。
> → 旧 val 不止"信号弱"，它**系统性地选偏**。

> **词表**：**未达** = 没拿到证据，多因**剂量 / 样本量**不足；
> **不确定带** = 两轴均未支配基准、但两轴 P@R=0.80 均 ≥ 基准。

| 方向 | 判定 | 为什么不能读成"被证伪" |

| **难例采样（`1b1`）** | ⚠ 未达 | **该实验本身无效**：剂量**按设计生效**（权重占比 2.63%→7.48%，×2.84），短板在别处 —— **杠杆偏弱**（sampler 抬 normal 窗口的*频率*，而三元 CE 权重压低每个 normal 样本的*贡献*，两者反向抵消）＋ **样本量小**（`lie_down` 全池仅 266 窗口，加大 α 只是重复采样）。**探索变量本身没到位 → 假设根本没被检验** |

## 5. 方法学成果（**本阶段最有价值的一节**）

> **本节与 §4 的分工**：§4 只谈**改动模型的尝试**（哪条成立、哪条没跑）；
> 本节谈**判据、指标、选点规则、band 这类"怎么判断"的成果** —— 它们**独立于任何臂**。
> 模型侧全阶段只成立 1 条（§4.1），而本节有 **8 条**，且每一条都是
> "**原本以为是效应、实测发现是噪声**"换来的。可直接用于后续阶段与论文方法章节。

**两条挂钩**（原本在 §4 的"明确否决"里，属方法学，移来此处）：
**单点判据已废止**（§5.1）；**val 不可用于选臂 / 选点**（§5.2）。

### 5.1 判据必须对"落点"不变

**现象**：同一臂仅换一个 ckpt，单点指标摆动 0.119~0.179，**远超原判据阈值**。
**根因**：ckpt 差异主要是**沿精度-召回前沿滑动（落点）**，不是**能力差异**（前沿在哪）。
**证据**：A0 自身 (prec, rec) 相关系数 r = −0.955；`avg_f1` 极差仅 0.035（vs `fallen_prec` 0.21）。
**解法**：改用**匹配召回下的精度 + 支配关系**（曲线口径），它对落点不变。
**实现**：`experiments/judge_w1_arm.py` 调用 `analysis/prec_rec_curves.py` 的 `dominance()`
—— **判定与画图同源，不写第二份副本**（本项目有"副本间漂移"的教训）。
**两道验收**：① 自测（臂=基准 → "无可判定差异"）；② 负对照（把 A0 当臂、`1a` 当基准 → 硬否决触发）。

### 5.2 `val` 不可用于跨臂/跨 ckpt 选型 —— 六臂 + 八 ckpt 双重实证

- **W1 六臂**：`val_max` 排序与 test `avg_f1` 排序**几乎无关**（Spearman ρ = **−0.14**，**负相关**）：
  val 第 2 的 `2a` 在 test 垫底，val 第 3 的 `1a` 在 test 第一。
- **W2 八 ckpt**：按 val 选出的 `best`，在两臂上都是**事件级最差的之一**。
- **W1 五臂时 val→test 落差全为正**（+0.067~+0.100）→ **val 系统性虚高**。

**⚠ 已撤回的错误归因**：val→test 落差**不是**"val 只看每视频前 64 帧"造成的
—— 实测截断只占落差的 **≈11%**，且方向是让 val **更好**。
主因是 **val 集类分布与 test 不同**（旧 150 的 fallen 密度是 test 的 **1.63×**）
+ 150 视频小样本与选型偏差。

### 5.3 任何跨 run 的差异，**必须同时报告单臂内的 band**

band（同一模型、同一配置、**仅换 ckpt** 的波动）随配方剧烈变化：

| 阶段 | band（单臂内 `avg_f1` 平台段极差） |
|---|---|
| Phase 6 | 0.0144 – 0.0712（四个 run） |
| Phase 8 | 中位 0.0301（0.0162 – 0.0518） |
| Phase 9 E3@2000 | **0.0099** |
| Phase 9/11 E1 | **0.0782** |

→ **差 8 倍。写常数会腐烂；只写原则**："**差异 > band 才算差异，否则只能写'不可分辨'**"。
**一条规律**：声称"**有**改进"的结论有风险（band 会淹掉它）；声称"**无**改进/无差异"的结论反而更稳。

#### band 从哪来 —— **两个来源，性质不同，别混**

| 来源 | 机制 | 打击哪个指标 | 证据 |
|---|---|---|---|
| **N1 落点漂移** | 各 ckpt 的 (prec, rec) 只是**沿一条极陡的前沿滑动**：参数微小变化把工作点推很远，而 `avg_f1` 几乎不动 | **单点 prec / rec / f1** | (prec, rec) 相关系数 **r = −0.955 ~ −0.988**；`avg_f1` 极差 **0.035** vs `fallen_prec` **0.21**（差 6 倍） |
| **N2 小样本 + 后处理离散** | test 只有 **249** 个真值切换点；预测边界数还会**整块跳**（430 / 499 / 624…） | **边界 F1** | band **0.10–0.15**（对照：`avg_f1` 的 band 是 0.078） |

其余来源可忽略：评测非逐位确定 ~1e-4；环境（torch 2.8.0 vs 2.5.1）
在**读数 R1**（§3.2）上 val Δ 均值 −0.0012。

**N1 的成因**是 E1 的配方（Adam + **恒定** lr + batch 2）下参数在极小值附近持续游走 ——
但另外两个候选解释**都已被实验排除**：①"轮数不够"（train loss 约 1 个 epoch 即停降、
val 去掉爬升段是平带无趋势）；②"未退火"（诊断臂 `a0cos` 把 val 带收窄 55%，
却**未迁移到 test**，test `avg_f1` 反而更差）。

> **⚠ 这个 band 不是加 head 带来的 —— 有直接证据**：它是**在无 head 的 `A0` 上量出来的**
> （`fall_prec` 0.119 / `fall_rec` 0.166 / `fallen_prec` 0.179），且跨阶段普遍存在（上表）。
> 至于加 head 是否**放大**了 band：现有两次读数**方向相反** ——
> 误报率 band：A0 **4.61 pp** vs `1a` **8.02 pp**（1a 更大）；
> 边界 F1 band：锚点 **0.1490** vs `1a` **0.1216**（1a 更小）。
> 两者都只基于 **n=3 个 ckpt** → **判不了**，不得声称任一侧。

**本阶段两次因没报 band 而误判**：
① 把 `1a` 在 2000 档的"边界 F1 0.1810→0.2406"当成有效证据（**已降级为不可分辨**，见 §6 勘误表）；
② 规划 §5.3 自己声明的"边界指标 <0.03 不可当真"（实测噪声地板是 0.10–0.15）。

### 5.4 辅助损失：**只罚 softmax 中某一个竞争类，会开出"对手类搭便车"的漏洞**

`1c` 对真值 normal 帧只罚 `P(fallen)`（想压低 lying→fallen 误报）。推导 + 数值验证：

```
∂L_aux/∂logit_j = [u/(1−u)]·(δ_{j,fallen} − P_j),   u = P(fallen)
  ∂L/∂logit_fallen = +u                             > 0  → 推低 fallen（意图）
  ∂L/∂logit_normal = −[u/(1−u)]·P(normal)          < 0  → 推高 normal（意图）
  ∂L/∂logit_fall   = −[u/(1−u)]·P(fall)            < 0  → **推高 fall（漏洞）**
```

**要害**：softmax 里 `P(normal)+P(fall)+P(fallen)=1`。要压低 `P(fallen)`，模型有
**两条完全等价的路**（抬 normal 或抬 fall），损失对二者毫不区分；
而 CE 对 fall 方向的压制只有 `0.132·P(fall)`（normal 类权重仅 0.132，是 fall 的 1/10），**拦不住**。

**实测完全吻合**：三类真值下 `P(fall)` 全面升高（normal 帧 0.0230 → **0.0411，×1.79**），
落点飘向极端召回端（`fall_rec` 0.8980 全场最高 / `fall_prec` 0.5639 全场最低）。

**普适判据（可迁移到任何项目）**：*这个辅助损失，有没有"不学该技能也能降低"的捷径？*
要罚就罚**该帧的"非目标"总质量**（如 `−log P(normal)`）。
**反例对照**：`1a` 的 boundary head **没有**这毛病 —— 它是**独立的一个头、独立的损失**，
不与被罚的量共享 softmax，没有"把质量倒给对手"这条捷径。

**设计错在哪**：当时挡住了"罚 `P(fall)` 会压住跌倒前那几帧"（选项 B 的风险），
**却没意识到"只罚 `P(fallen)`"会开出一个对手类搭便车的口子** —— 两个方向的错误只防了一个。

### 5.5 显式监督 vs 隐式涌现：**优势不跨数据尺度保留**（本阶段的机制层负结果）

**定义**：*隐式涌现* = 没为该子技能写损失，期望它在优化主任务时顺带被学会；
*显式监督* = 为该子技能单独写损失（通常配单独的头），直接施加梯度。
**核心区别只有一句：梯度是否直接指向该子技能。**

**本阶段的检验对象**：`1a` —— 给"当前帧是否处于状态切换邻域"单独加一个 boundary head + BCE 损失。

#### 两次受控对照（各自 vs 自己的同配方基线，**唯一变量 = 有没有 head**）

| 尺度 | 对照实验 | **主判据**（曲线口径，fall 轴） | **机制专用指标**（边界 F1，τ=3） |
|---|---|---|---|
| **2000** | `1a` **vs** `A0`（= E1@2000 复刻） | **`1a` 支配** A0，均值 **+0.0608**（落点不变口径）→ **有优势** | 最好 ckpt 0.1810 → **0.2406（+0.0596）** |
| **9600** | `w2_1a` / `p2_1a` **vs** `E1-full` / `p2_anchor` | **不支配**（W2 交叉 −0.0081；P2 交叉，判**不确定带**）→ **优势消失** | 组均值 0.1965 → **0.2016（+0.0051）**；最好 ckpt 0.2710 → 0.2535（−0.0175）→ **零改善** |

> ⚠ **同格同统计量**：9600 行两栏都按"组均值"与"最好 ckpt"分别列出。
> 锚点组只有 **2 个 ckpt**（本地只存了这两份 pv），`1a` 有 4 个 —— 但**噪声地板（0.10–0.15）
> 是待测效应（0.005–0.028）的 5 倍以上**，补齐锚点不会改变结论。

#### 三句话把"谁证明了什么"说清

1. **"显式监督更优"—— 由 2000 档的对照（`1a` vs `A0`）证明，且靠的是主判据（曲线口径）**，
   不是边界指标。曲线口径对落点不变，因此这条**本身是站得住的**（§5.1）。
2. **"这个优势在数据充足后不保留"—— 由 9600 档的对照（`1a` vs 锚点）证明**，同样靠主判据。
   两个尺度上都是**自带基线的受控对照**，故不受规划 §3.1"跨尺度不转移"那条警告的牵连。
3. **直接否定其声明机制的那一次检验，是 W3 的边界指标**：`1a` 装了显式 head，
   在**它自己声称要改善的那个量**上**零改善（+0.005）**—— 而"改善边界定位"正是它的机制假设。

#### 为什么解释成"被数据量抹平"

无 head 的基线**自己**在两个尺度上的边界 F1（最好 ckpt）是 **0.1810 → 0.2710**，
即**光靠数据量就涨了 +0.09**，比加 head 在 2000 上的收益（+0.06）还大。

> ⚠ **但这个跨尺度读数本身是"两个噪声带内的数"相减**：边界指标在 9600 上实测的噪声地板是
> **0.10–0.15**（§2.4），0.06 与 0.09 都小于它；2000 档的 band 未实测。
> → **"抹平"是解释，不是已证结论。** 能确证的是第 2、3 句（优势消失 + 机制零改善）。

→ **机制解释（假设）**：数据充足后主 CE 已**隐式**学出足够好的边界表示；
此时再挂一个**正类率仅 1.77%** 的辅助头，其梯度**反过来扰动**已学好的表示
—— 显式监督从"补短板"变成"添噪声"。
（辅助任务的实际稀疏性比规划预估严重约 10 倍：**85% 以上的窗口完全不含切换点**。）

> 这正是规划 §9 风险 **R2 预登记**的失败模式（当时列为"中"概率）：
> 本阶段把"**收益没兑现**"从猜测变成了实测；至于"**是被隐式学走了**"这一机制归因，
> 仍是**有数据支持的解释**，不是被直接验证的因果。

#### ⚠ "2000 上优势更大" 不能读成 "显式监督更适合小数据"

观测本身**是真的**（2000 支配 +0.0608 / 9600 不支配），且用的是**落点不变**的曲线口径，
**不是噪声**。但**不能**据此推出"更适合小数据"，两条理由：

1. **另一种读法同样吻合**：不是"head 喜欢小数据"，而是"**head 是根拐杖 —— 数据够了，
   主损失自己就学会了**"。两句话描述的是同一个观测，但对**别的任务**预测相反：
   前者说"数据少时该用它"；后者说"它的价值上限 = 主损失学该子技能有多难"（与数据量无固定关系）。
2. **机制探针说它从没改善过它声称要改善的东西** —— 9600 上边界指标零改善（见上「三句话」第 3 句）。
   即 2000 上那点优势落在**主判据（fall 轴）**上，**不是边界定位**：
   **"它有效"与"它的机制假设成立"是两回事。**

> （附注：每臂也只有一次 run、效应量无 **run 间**误差棒 —— 但这是**本项目全局通例**（§3.5 附注），
> 不作理由。）

→ 要真回答"小数据是不是更该用它"，需要**数据量梯度对照**
（如 500 / 1000 / 2000 / 4000 各跑 `1a` vs 同档基线，**每档 ≥2 个 seed**）。
**本阶段没有**；而且本阶段自己的纪律（W1 只是止损闸门、§5.6 的秩反转实测）正是
**不给 2000 档的择优背书** —— 所以这里只能停在"2000 上有优势、9600 上没有"这个观测层面。

### 5.6 `@2000 → @9600` **不转移**，且两次都是"秩反转"

| 次 | @2000 / @6000 | @9600 |
|---|---|---|
| 历史（Phase 9） | `fallen_prec` 与 `event_f1` 在 6000 见顶 | 9600 回落 |
| **本阶段（W1→W2）** | `1a` fall 轴 +0.0608 > `4` +0.0455，判别不可分辨 | **只有 `4` 转移**，`1a` 被锚点支配 |

→ **小数据档只能做"止损筛除"，不能做"择优"。**
配套：因此 **W1 的臂数必须收缩**（只留机制最有依据的），择优搬到全量。

### 5.7 选点信号的**效度可以被实测**；而事件轴是**目标错配**

- 同一个模型池，**旧 val 的排序与 test 几乎无关**（ρ = −0.14），
  **重建 val 后升到 +0.955** → **"这个 val 能不能用来选点"是可测的，不必靠感觉**。
- 但新 val 与**事件级**指标基本无关、个别强负相关（`mean_fallen_as_fall_rate` **−0.750**），
  而 §7.3 有两项是逐视频口径 —— **这不是噪声问题，是目标错配**：
  **帧级的 val（乃至帧级的 test 指标）根本挑不出事件级更好的 ckpt**。
- **一条配套结论（原规划 §6.2 的"扩大并配平 val 集"）**：实测表明**必要性被高估** ——
  `val.csv` 全量**本身就是配平的**（与 test 的帧级三元分布差 ≤0.63 pp），
  旧 150 那个 fallen 密度 1.63× 是**抽样噪声**而非池级失调。
  → 要做的是**换用全量 val**，不是"造一个配平的 val"。

### 5.8 新指标必须**过两道验收**才可采用，且**已知缺陷随它一起声明**

**规则**（CLAUDE.md 强制）：① **GT 自检** —— 真值当预测喂入须得满分（非事件样本应**排除**而非记 0）；
② **负对照** —— 故意注入错误（全漏 / 平移 / 抖动）须**单调劣化**。两者都要**跑出数**并写进文档。

**本阶段建了两次，两次都兑现了这条规则的用处**：

1. **边界指标**（§2.4）采用前跑出：GT 自检 τ=1/3/5 全满分；全漏 → 0；真值平移容差内保真、
   超容差坍缩；抖动精确率单调劣化。**并声明了四条已知缺陷** ——
   其中第 3 条（噪声门槛 0.03）**在 W3 被实测修正为 0.10–0.15**。
   **这正是"随指标一起声明"的用处**：缺陷被写下来，才会被后人回头检验并修正。
2. **§7.3 五项**（附录 B.1）此前被当作"现成读数"直接使用、**从未验收**；
   2026-10-09 首次对着真数据跑时，它在一个**静默**缺陷上暴露
   （读错键名 → 两项恒"缺"、通过数上限被压到 3/5）。补做的两道验收通过，
   但**也如实声明了它的能力边界**：**它抓不到"类索引串号"**（若把 `fall_prec` 误读成 fallen 类，
   GT 喂入时**所有类都满分**，自检依旧 5/5）—— 那类错误仍需**人工核对字段语义**。

> ⚠ **一条与它配套的元规则**：负对照的"期望行为"要**先对指标语义推导清楚，再写断言**。
> 本阶段曾把边界指标对"整体固定延迟"的**阶跃**响应误判为实现 bug（实测超容差后残留匹配
> 稳定在 0.016~0.033，并非单调降到 0）；若当时按模糊印象改实现去迁就那个错误期望，
> 就会**把一个正确的指标改坏**。

> ⚠ **还有一条**：判读脚本**必须落盘**，否则结论无法作为一手产物引用（本阶段两个脚本只 print，
> 见 B.5 遗留）—— "脚本跑完" ≠ "产物正确"，也 ≠ "结论可被复核"。

## 附录 A：长任务运维（CLAUDE.md 四件套的实操）

### A.1 四件套的落实与三个实操坑

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | **看门狗判型滞后最多 10 分钟**，期间外部监控 CPU/GPU/显存/内存**全为 0**（像挂起） | `while alive; do sleep 600; …; done; wait $PID` —— **一个轮询循环同时扛"等结束→接评测"与"查停滞"** | **解耦**：`wait $PID` 零延迟切换；停滞检查放后台子 shell。⚠ 实测判型时刻**精确等于**各 watchdog 启动后第 98 个 600 s tick（算术可验） |
| 2 | 归档核对**永久假阳性**：`pack.log` 哈希不符 + "清单外多出" | ① 打包日志**自指** ② **`md5sum *` 匹配不到隐藏文件** | 工具状态/日志一律放**产物目录外**；清单改用 `find -type f` 枚举 |
| 3 | 工具**静默失败**：9/9 全 `rc=1` 无产物 | `UnicodeEncodeError`（Windows GBK 控制台编不了 `✅`） | 脚本内 `export PYTHONIOENCODING=utf-8`；**先校验产物再报完成**（"脚本跑完"≠"产物正确"） |

### A.2 "新开一路输入/输出"必须**三处都接上**：训练侧 / val 侧 / 评测侧

`4`（pose）曾因 `val_check` 与 runner 评测命令各漏传一次 `--pose_npz`，
**连崩两次、各赔一轮 8.8 h**。

**为什么冒烟没拦住**：① `val_every=600` 而冒烟只跑 20 步 → **失败路径从未被执行**；
② 该通路做过"负对照：不给 `--pose_npz` → RuntimeError"，**负对照做了、正例没做**
—— 验证了"不给会报错"，**却从没验证 runner 到底给没给**。

**解法**：冒烟须用 `--val_every 1` 强制触发；runner 用独立 `EVAL_EXTRA`（不能透传 `$EXTRA`）。

### A.3 其它已固化纪律

- **启动前跑预检** `bash experiments/p11_preflight.sh`（本地/远端哈希比对，忽略行尾符）。
  ⚠ 其 per-file 清单**漏过三次**（`models/phase9_e1_model.py` → `preprocessing/` → `experiments/lora.py`），
  每次都只在"真的跑到那一步"才报错，**而那是起跑之后** → 已改为**整目录 tar 同步 + 目录级联合哈希**。
- **启动后必须等到日志出现 `step ` 行**才算"已启动"。崩溃常发生在模型加载后的首个前向（约 5 分钟），
  8 秒的进程检查抓不到 —— 本阶段曾因此宣布"已启动"而实际早已崩溃。
- **取子集必须随机**（`--limit_videos` + `--subset_seed`）。test.csv 按路径排序、`fall/` 打头：
  **前 300 个的 fall 帧占比 26.79% vs 全集 6.78%（偏差 +20 pp）**。
  ⚠ 同型教训本阶段出现三次：**按文件自然顺序取前缀，在按路径排序的数据上必然有偏**；
  且引用比例类数字前必须写清 macro 还是 micro。
- **判活用 `/proc/<pid>/stat` 第 3 字段是否为 `Z`**，不能只 `kill -0`（僵尸进程仍返回成功）。
- **`pkill -f <pattern>` 会自匹配**自己的远程 shell → 杀前先 `pgrep -af` 核对，或用字符类技巧。
- **scp 长回传会随机卡死/掉速** → 改"远端 `tar czf` 打包 → 浏览器下载 → 本地展开 → 逐文件 md5"。
  ⚠ 两侧 `md5sum` 格式不同（本地 `hash *name`、远端 `hash  name`，本地带 `\r`）→ **比对前必须归一化**。
- **归档硬规则**：远程任务一结束立即回传并**逐文件核对**（文件数 + md5），
  **核对通过才可说"完成"或"可关机"**。本阶段 P2 的 I4 因收工最早先行关机，
  留下 **7 份小文件未逐项校验**，事后靠 autodl **「无卡开机」**补验完毕（7/7 OK）——
  **这正是"先验后关"约定存在的理由**。
