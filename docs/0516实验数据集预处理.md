**数据集预处理**

simplexsigil2/omnifall数据集

数据集地址：https://huggingface.co/datasets/simplexsigil2/omnifall

面向 staged-to-wild 的时间线分割式跌倒检测

OmniFall 的优势：它不仅提供 fall / non-fall，而且提供统一的时间线标注体系，用来支持 classification 和 timeline segmentation，并且强调 fallen 状态对真实医疗/养老报警更关键。

1.数据读取：

读取 of-syn 数据把 OmniFall 里的 OF-Synthetic 合成视频数据加载出来。 

这一阶段的目标不是训练模型，而是确认：数据能读出来，视频路径存在，标签能看懂。

2.视频切分到 clip 级，建立标签序列：

先把同一个视频的所有时间段标注整理成完整时间线，然后将视频按照固定长度切分成连续 clip，并记录每个 clip 的起止时间或中心时间，最后根据 clip 所在的时间区间，将 OmniFall 原有的动作标签自动分配给对应 clip。

这样就可以把原始的“时间段级标注”转换为模型训练所需的“clip 级标签序列”。

例如将一个视频转换成 standing → standing → fall → fallen → fallen。

整个过程不需要重新人工标注，后续的 fall_labels 和 fallen_labels 也可以直接由这些 clip 级动作标签自动生成。

3.由 clip 级动作标签生成 fall / fallen 双分支标签：

这一步的输入是第 2 步得到的 labels_16，也就是每个 clip 对应的 16 类动作标签序列

例如：输入标签序列**standing → standing → fall → fallen → fallen**，输出两组二分类标签：**fall_labels / fallen_labels**。

其中，**fall_labels** 只在当前 clip 的标签为 fall 时置为 1，其余为 0，也就是说，输出**0 → 0 → 1 → 0 → 0**；**fallen_labels** 只在当前 clip 的标签为 fallen 时置为 1，其余为 0，即输出**0 → 0 → 0 → 1 → 1**。

这样就可以在保留原始 16 类时间线分割标签的基础上，额外为模型提供专门学习“跌倒发生过程”和“跌倒后倒地状态”的监督信号。

4.对每个 clip 提取特征，并形成视频级时序特征序列：

这一步的输入是切分得到的所有视频片段，即 clips = [clip_1, clip_2, ..., clip_T]，其中每个 clip 通常包含固定帧数的视频片段，例如 16 帧；

输出是对应的特征序列 features = [feature_1, feature_2, ..., feature_T]，每个 feature_i 表示一个 clip 的视觉特征向量。

最快跑通版本可以先使用 ResNet18 等预训练图像模型对 clip 内每一帧提取特征，再对该 clip 内所有帧特征取平均，得到一个 clip-level 特征。

5.完成预处理：

经过上述过程，单个视频会被转换成一组形如 features [T, 512] 的时序特征矩阵，其中 T 表示该视频切出的 clip 数量，512 表示每个 clip 的特征维度。

这样后续模型就不需要直接处理原始视频，而是直接输入这个时序特征序列进行时间线分割。

最终归总输出到一个npz文件字典：要有原数据集的个视频经过预处理的clips, clips_times, label_16, fall_labels, fallen_labels, feature, video_path信息作为键和键值。
