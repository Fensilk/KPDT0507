# 第九阶段 E3 总结：帧级 LoRA 微调 DINOv2——分解假设证实

## 一、阶段概览

**目标**：微调 DINOv2（ViT-g），让帧特征学会区分"两个难区分"——静态 lying vs fallen（因果）与动态 lie_down vs fall（受控性）。第八阶段已证明任何低层增补特征（加速度/光流/姿态）都无效，唯一出路是微调特征提取器本身。

**数据侧前奏**：先尝试了剔除"无前因躺卧"视频的数据清洗方向（P9/P9b），两种变体均被证伪（fallen_prec 不升反降），确认瓶颈在模型能力而非标签噪声——进一步强化了微调必要性。

**设计决策链**（详见 `docs/0831实验第九阶段规划.md`）：
- **基座**：`facebook/dinov2-giant` 预训练权重（"从冻结特征反推权重"不可行，已论证）。
- **方法**：LoRA 低秩适配——显存可行（1.1B 主干 + 仅 7.86M 可训练）、任务性质匹配（对强预训练特征做低维修正）、防灾难性遗忘、探索成本低。
- **顺序**：**先 E3（两阶段帧级）后 E1（端到端）**——E3 不是 go/no-go，而是把瓶颈拆成两条轴分别验证的**分解诊断**。

## 二、核心框架：两条可学性不同的轴

| 难区分 | 信息在哪 | 帧级可学吗 |
|--------|---------|:---:|
| 动态 lie_down vs fall | 受控性——在运动过程本身（姿态、速度、肢体失控） | ✅ 单帧可能可学 |
| 静态 lying vs fallen | 因果——在前因动作（倒地前发生了什么） | ❌ 单帧无此信息 |

E3 的帧级目标恰好把两条轴分开测，结果按诊断矩阵读，而非"有效/无效"二值。

## 三、E3 实验设计（两阶段帧级 LoRA）

```
Stage1: 帧级 LoRA 微调
    ViT-g(facebook/dinov2-giant, fp16) + 手写 LoRA(q/k/v/o, rank16, 7.86M 可训练)
    + Linear(1536→3) 分类头；逐帧三元 CE + 类权重（fall 1.31 / fallen 1.55 / normal 0.13）
    数据：2,000 训练视频 × 10 帧 = 20,000 帧（按类打散采样，seed 42）
    训练：batch 16（autodl 显存限制），5 epochs，lr 1e-4

Stage2: 重抽 + 时序训练
    用微调 ViT-g 重抽 12,000 视频逐帧 CLS 特征 → 新 NPZ
    → 现有 train_phase6.py（ViT-g 特征 + Δdiff + Transformer, 与 baseline p7d_delta 同配置）
```

## 四、环境挑战与修复（重要经验）

| 问题 | 现象 | 修复 |
|------|------|------|
| **AV1 解码** | autodl 的 cv2 解不了 OmniFall AV1（"Missing Sequence Header"），解码失败**零填充**不报错 → 帧准备/重抽产出垃圾特征 | **PyAV**（`pip install av`，自带完整 AV1 解码）；`preprocessing/av_decode.py`（PyAV 优先 + cv2 兜底）；帧均值验证（>20）排查垃圾帧 |
| **显存** | autodl 是 torch 2.1.2 + transformers 4.44，比本地吃内存 3 倍——batch 16 需 ~19GB，batch 32 必 OOM | 只能 batch 16 |
| **HF 访问** | autodl 连不上 huggingface.co | `HF_ENDPOINT=https://hf-mirror.com` 下载模型；`HF_HUB_OFFLINE=1` 强制离线用缓存 |
| **残留进程** | 训练挂掉后 nohup 可能留残进程占显存 | 跑前 `nvidia-smi` 检查 |

## 五、实验结果（诊断矩阵，真实帧数据）

测试集：全量 test（1,200 视频），与 baseline p7d_delta 同评估口径。

| 指标 | baseline | E3 微调 | Δ |
|------|----------|---------|-----|
| fall_precision | 0.5918 | 0.5939 | +0.0021 |
| **fall_recall** | 0.7923 | **0.8418** | **+0.0495** |
| fall_f1 | 0.6775 | 0.6964 | +0.0189 |
| **fallen_precision** | 0.6272 | 0.6194 | **-0.0078** |
| fallen_recall | 0.6984 | 0.7013 | +0.0029 |
| fallen_f1 | 0.6609 | 0.6578 | -0.0031 |
| avg_f1 | 0.7641 | 0.7689 | +0.0048 |
| ternary_acc | 0.9079 | 0.9070 | -0.0009 |

**诊断矩阵观察**：
- **动态轴改善**：fall_rec 0.792→**0.842**（+0.050），fall_prec 持平 → 受控性帧级可学，微调特征学会区分"跌倒的失控下降"与"主动躺下的受控下降"。
- **静态轴不变**：fallen_prec -0.008、fallen_rec +0.003（噪声级）→ 单帧"人在地面"无前因信息，帧级微调学不出 lying vs fallen 的因果。

## 六、核心结论

**分解假设被精确证实**：

1. **受控性（动态轴）帧级可学** ✅：帧级 LoRA 微调让 fall_rec +0.05，微调 DINOv2 确实能学会编码"是否失控"。
2. **因果（静态轴）帧级不可学** ❌：单帧无前因信息，帧级微调无法区分 lying vs fallen。
3. **端到端（E1）是唯一出路**：静态 lying-vs-fallen 必须靠时序模型利用前因上下文，端到端联合训练（让时序头反向驱动特征编码因果）是唯一途径。E3 把微调有效的范围锁定在动态轴，把静态轴瓶颈精确定位到"时序整合"。
