# E3 全量运行说明（autodl 3090）

两阶段帧级 LoRA 微调 DINOv2（E3）的完整流程。本地管线已冒烟验证通过。

## 流程概览

```
Stage1（帧级 LoRA 微调 ViT-g）
  → 重抽 12,000 视频特征（新 NPZ）
  → Stage2（时序模型，与 baseline 同配置）
  → 对比 baseline（eval_p9e3.py）
```

## autodl 步骤

### 0. 前置
```bash
cd <仓库根目录>
conda activate py310
git pull                      # 拉最新代码（含所有 E3 脚本）

# 视频必须在（Stage1 帧准备与重抽都需要）
ls DATASET-omnifall/data_files/extracted/fall/ | head
```

### 1. 帧缓存（二选一）
```bash
# 方案 A：本地已生成 data/p9_frames（4GB），上传到 <仓库根目录>/data/p9_frames/
# 方案 B：在服务器上重新生成（~30 分钟，需视频在位）
python experiments/prep_p9_frames.py --n_videos 2000 --frames_per_video 10
```

### 2. Stage1：帧级 LoRA 微调（~40 分钟 @3090）
```bash
bash experiments/run_p9e3_stage1.sh
# 产出: logs/phase9/e3_stage1/finetuned_lora.pt
```

### 3. 重抽全量特征（~30-60 分钟 @3090）
```bash
bash experiments/run_p9e3_extract.sh
# 产出: data/omnifall_dinov2_finetuned_frame.npz
```

### 4. Stage2：时序训练（~20-40 分钟）
```bash
bash experiments/run_p9e3_stage2.sh
# 产出: logs/phase9/e3_stage2/test_results.json
```

### 5. 评估对比
```bash
python experiments/eval_p9e3.py
# 输出 baseline vs E3 主指标 + 诊断矩阵观察
```

## 判断标准（诊断矩阵）

| 观察 | 结论 |
|------|------|
| 动态轴（fall_rec/fall_prec）改善，静态轴（fallen_prec）不改善 | 证实"受控性帧级可学、因果需时序"→ 端到端 E1 必要性 |
| 两轴都不改善 | ViT-g 微调在此合成域难学到东西，E1 预期下调 |
| 静态轴也改善 | 微调特征确实有用，E1 起点更好 |

## 注意

- Stage1 在 4060 上 ~10s/步太慢，**全量必须在 3090 上跑**
- 重抽是全量 12,000 视频（新 NPZ 约 2.6GB）；本地只做过 --limit 10 冒烟
- Stage2 用 `--frame_npz data/omnifall_dinov2_finetuned_frame.npz`，与 baseline 同配置可比
