### Exp-0a 三类 + T=32 + 双向（补 P4→P6 对照缺口）— 2026-09-28

**结论：不必重跑。** 既有产物已提供该臂，并额外允许把草案那个"纠缠的缺口"**分解开**。

**发现**：`logs/phase6/` 下已存在 `p6_T32_bridge`。与 `p6_bridge` 逐项比对保存的配置后确认
**唯一差异是 `window_size`**：

| 键 | `p6_T32_bridge` | `p6_bridge` |
|---|---|---|
| **`window_size`** | **32** | **64** |
| `stride` | 8 | 8 |
| `decoder_type` | transformer | transformer |
| `causal` | **False（双向）** | **False（双向）** |
| `bridge`（= CE，无 focal） | True | True |
| `hidden_dim` / `num_layers` / `num_heads` | 384 / 1 / 6 | 同 |
| `batch_size` / `lr` | 32 / 1e-3 | 同 |

**分解结果**（`fall_f1`，同一 test 集 1200 视频）：

| 类别设计 | 窗口 | `fall_f1` | 来源 | `avg_f1` 口径 |
|---|---|---|---|---|
| 16 类 | T=32 | 0.6571 | `logs/phase4/p4d_vitg` | 两类均值 0.6515 |
| 16 类 | T=16 | 0.6178 | `logs/phase4/p4d_T16` | 两类均值 0.5934 |
| 三元 | T=32 | 0.6037 | `logs/phase6/p6_T32_bridge` | 三类均值 0.7122 |
| 三元 | T=64 | 0.6836 | `logs/phase6/p6_bridge` | 三类均值 0.7532 |

**两轴的完整分解**

| 轴 | 16类T32 → 三元T32（**类别效应**） | 三元T32 → 三元T64（**窗口效应**） | 合计 | 与报告实测一致？ |
|---|---|---|---|---|
| `fall_f1` | **−0.053**（0.6571→0.6037） | **+0.080**（0.6037→0.6836） | +0.027 | ✓（报告记 +2.7pp） |
| `fallen_f1` | **−0.052**（0.6459→0.5941） | **+0.035**（0.5941→0.6294） | −0.017 | ✓（报告记 −1.7pp） |

- **窗口效应（干净，单变量）**：三元固定、同脚本同实现，T=32 → T=64 → `fall_f1` **+0.080**、`fallen_f1` +0.035、`avg_f1` +0.041
- **类别设计效应（有混淆，待验证）**：T=32 固定，16 类 → 三元 → `fall_f1` **−0.053**、`fallen_f1` **−0.052**
- 两项之和恰等于报告记录的总变化（+0.027 / −0.017）→ **分解自洽**

**⚠ 本分解与原始报告的归因相反，且报告内部自相矛盾**

`docs/0717实验第六阶段报告.md` §2.5 原文（**这是该说法的原始出处**；202609 汇报 §五 是转载，
非汇报自行编造）：

> | fall_f1 | 0.657 | **0.684** | **+2.7pp** |
> | fallen_f1 | 0.646 | 0.629 | −1.7pp |
>
> 三分类重构确认有效……fallen_f1 微降主要来自 **T=64 窗口扩大**导致样本数下降（84K→36K）……

**同一张表、同一次比对，却给了相反的归因**：`fall_f1` 的上升归给"三分类重构"，
`fallen_f1` 的下降归给"T=64 窗口扩大"——**把同一个混杂因子按结果好坏拆给了两个不同的原因**。
实测分解显示：**窗口效应在两轴上都是正的（+0.080 / +0.035），两轴的下降都来自类别重构**
（−0.053 / −0.052）。即报告在两个轴上都把归因弄反了。

**⚠ 该分解的混淆（不得直接当结论引用）**

1. **跨模型实现**：`MultimodalFeatureTransformer`（Phase 4）vs `Phase6TernaryModel`（Phase 6）——
   结构参数一致（1 层 / 384 / 6 头 / dropout 0.3 / Pre-LN / 正弦位置编码），但不是同一份代码
2. **训练预算不同**：`p4d_vitg` 为 `epochs_run=32, best_epoch=17`，远长于 bridge 组
3. **无法直接重跑**：Phase 4 的训练脚本**已不在仓库**（`experiments/` 下只剩 `confusion_matrix_p4.py`），
   且 `train_phase6.py` 仅支持三元、**无 16 类路径**
4. **已排除的混淆**（有利于该分解可信）：两者**均无 causal mask**
   （`models/transformer_model.py` 全文 0 处 `mask`，即双向）✓；
   均 `use_diff=False`、`input_dim=1536`（同一 ViT-g NPZ）✓；
   评测实例数同为 268,800（T=32 / stride 8）✓

**判定**：对应规划 §4.0a。**干净的那一半（窗口效应 +0.080）已达成**；
"类别设计效应"需新建 16 类训练路径才能验证 —— 是否投入预算见 §4 待办。

**发现 / 意外**：草案与汇报都默认"三分类是主要提升来源"，实测分解指向相反结论。
**这不影响 Phase 11 主线**（本阶段不做架构考古），但影响论文 §五 性能轨迹表的表述，
**建议在总结文档里如实改正**。
