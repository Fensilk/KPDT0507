# 改进一（数据角度）实验总结

## 实验目的

按照0607规划中"改进一（数据角度）"的要求，将 TCN 输入序列长度 T 从 5 提升到 16 或 32，并引入滑窗机制扩充训练数据。与 Phase 1 基线（T=5，clip 级不重叠切分）对比，验证更长序列和更多数据是否能提升跌倒检测性能。

## 实验设置

- **数据集**: OF-Syn 12,000 合成视频，每视频 80 帧，16 FPS，16 个动作类别
- **特征**: ResNet18 提取帧级 512 维特征（Phase 1 使用 clip 级池化特征）
- **模型**: TCN（因果膨胀卷积，多任务 16 类 + fall + fallen），膨胀系数根据窗口大小自适应
  - T=5: dilations=[1,2], RF=7, 923K 参数
  - T=16: dilations=[1,2,4,8], RF=31, 1.71M 参数
  - T=32: dilations=[1,2,4,8,16], RF=63, 2.10M 参数
- **训练**: AdamW (lr=1e-3, wd=1e-4), ReduceLROnPlateau, early stopping patience=15, WeightedRandomSampler
- **损失**: L_total = L_cls + 0.5 × L_fall + 0.5 × L_fallen
- **滑窗公式**: 每视频窗口数 = (80 − T) / stride + 1

## 核心发现

### 1. 所有滑窗实验均未达到基线水平

最好的滑窗配置（T=16 s=8, avg_f1=0.423）仍比基线低 24%。滑窗思路本身没有带来收益，无论 T 和 stride 如何组合。

### 2. 全部实验存在严重过拟合

所有 9 组滑窗实验的 train_loss 持续下降但 val_loss 持续上升，最佳 epoch 均在前 5 轮内（多数在 epoch 1-2），之后持续退化。过拟合是普遍现象，不是个别参数选择问题。

以 T=16 s=1 为例：
```
Epoch  1: train=0.526, val=5.16, fall_f1=0.292 ←
Epoch  2: train=0.236, val=6.07, fall_f1=0.343  ← 最佳
Epoch  3: train=0.169, val=6.00, fall_f1=0.321
  ...
Epoch 10: train=0.049, val=11.5, fall_f1=0.322
```

### 3. stride 增大有微弱改善，但不能扭转格局

| T | stride=1 avg_f1 | stride=4 avg_f1 | stride=8 avg_f1 | 趋势 |
|:--:|:----:|:----:|:----:|------|
| 5 | 0.401 | 0.400 | 0.412 | 基本持平 |
| 16 | 0.374 | 0.420 | 0.423 | 缓慢上升 |
| 32 | 0.415 | 0.388 | 0.372 | 反而下降 |

仅在 T=16 上 stride 增大带来了 13% 的相对改善，但依然远低于基线。

### 4. T=5 小模型对滑窗冗余不敏感

T=5 三组 stride（1/4/8）的 avg_f1 都在 0.40-0.41 的窄区间内。小模型（923K 参数，RF=7）容量有限，无法充分拟合冗余数据中的噪声模式，因此对滑窗重叠度变化不敏感。

### 5. T=32 大模型数据不足时性能坍塌

T=32 s=8 只有 67K 训练窗口，却需要训练 2.1M 参数的大模型，数据量不足导致性能在全矩阵中最差（avg_f1=0.372）。T=32 在所有 stride 配置下都不如 T=16，说明更长的序列窗口没有带来预期的上下文收益。

## 根因分析

滑窗与因果 TCN 之间存在结构性矛盾。因果 TCN 的预测依赖于输入在窗口内的位置——同一物理帧出现在不同窗口中时，处于窗口内的不同位置，TCN 看到的上下文（历史帧数）完全不同，因此对同一帧产生不同的输出。但训练标签与窗口位置无关，同一帧在所有窗口中有相同的标签。

具体而言：
```
物理帧 30 在 stride=1, T=16 的滑窗中:

  窗口 15: 帧30 在窗口内位置 15 → TCN 看到前 15 帧（物理帧 15-29） → 预测 P₁₅
  窗口 20: 帧30 在窗口内位置 10 → TCN 看到前 10 帧（物理帧 20-29） → 预测 P₁₀
  窗口 25: 帧30 在窗口内位置  5 → TCN 看到前  5 帧（物理帧 25-29） → 预测 P₅
  窗口 30: 帧30 在窗口内位置  0 → TCN 看到前  0 帧                 → 预测 P₀

  但 Ground Truth 对所有窗口相同 → P₁₅, P₁₀, P₅, P₀ 不可能同时正确
```

模型被迫学习一个不可能的函数：同一个物理输入帧在不同的上下文窗口中要有不同的输出。窗口重叠度越高（stride 越小），同一帧被不同上下文覆盖的次数越多，矛盾越严重。这就是所有滑窗配置都过拟合的根本原因。

相比之下，Phase 1 基线的 clip 级设计避免了这一问题：每段 16 帧独立池化为一个特征向量，5 个 clip 之间完全不重叠，每个样本有唯一确定的时间上下文，不存在"同一帧在多个窗口位置"的矛盾。

## 结论

**滑窗扩充数据不能提升 OMNI-FALL 跌倒检测的 TCN 模型性能。**

帧级滑窗与因果 TCN 的架构存在根本冲突——滑窗使同一帧在多个上下文窗口中出现，而因果 TCN 对窗口位置敏感，导致模型面临不可调和的训练信号矛盾。调整窗口大小 T（5/16/32）和滑窗步长 stride（1/4/8）可以改变退化程度，但无法逆转趋势。最优配置 T=16 s=8（avg_f1=0.423）仍比 Phase 1 基线（avg_f1=0.556）低 24%。

Phase 1 基线采用的 clip 级不重叠设计（每 clip 16 帧均值池化为一个特征向量）既通过池化获得了降噪效果，又避免了窗口位置敏感性问题，在当前任务场景下是更优的时域建模方案。
