首先是当前的情况分析：

Phase 10 已经把方向筛得比较清楚了：真正有效的变化主要来自把原来的 16 类多任务改成直接的 fall / fallen / normal 三分类，而 LSTM、Temporal Transformer、因果注意力以及 Focal Loss 参数调整都没有带来明显收益。尤其是因果注意力后 fall_f1 从 0.684 降到 0.615，说明 fall 这种短暂的过渡状态非常依赖前后文信息，因此后续应该继续保留双向注意力。另外目前 p4 到 p6 同时改变了类别设计和 T=32→64，严格来说还需要补一个 3类 + T32 + bidir 的对照，确认三分类本身到底贡献了多少提升。整体来看，当前瓶颈已经不太像“时序模型不够强”，而更像是 fall 与 normal/fallen 之间的状态边界难判断，以及现有视觉特征对真实运动变化表达不足。

接下来是接下来工作的优先级

强化 fall 状态边界的学习。 

我建议先保持当前三分类、T=64、双向 Transformer 不变，在时序特征后额外增加一个很轻量的 Boundary Head，用来判断当前帧是否位于 normal→fall 或 fall→fallen 的状态切换附近，训练时采用 三分类 loss + boundary loss。同时可以配合改变采样方式，让训练 batch 更多地包含跌倒开始、跌倒结束附近的窗口，以及快速坐下、蹲下、弯腰、主动躺下等 hard negative。这样优化的是模型目前最明显的弱点——知道人是什么状态不难，但准确找到“什么时候开始跌、什么时候已经倒地”比较难。

这个方向改动小，也最适合作为下一阶段的第一组实验。

第二优先级：补充真正的运动信息和多尺度时序特征。

fall 是一个很短的动态过程，而 fallen 更像一个持续的静态状态，统一使用 T=64 的一个时序分支未必最合适，可以尝试 Local 8/16 帧 + Global 64 帧 两个时间尺度：短窗口负责捕捉快速姿态变化，长窗口负责判断倒地后的持续状态。同时不要再对 ViT embedding 做一阶、二阶差分，因为它反映的是语义空间变化而不是真实速度；更值得加入的是 bbox、人体关键点或姿态相关的运动量，例如身体中心纵向位移、bbox 高宽比变化、躯干角度、髋部下降速度等。

这样才能真正给模型补上区分“快速跌倒”和“正常躺下/蹲下”的动态信息。
