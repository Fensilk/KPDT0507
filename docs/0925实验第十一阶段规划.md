## 0. 一句话目标与本阶段边界

**目标**：在主攻轴 = **fall 轴边界**（fall onset / fall→fallen 切换的定位）上取得可复现的显著提升，
**且不拆掉静态轴与事件稳定性**。

两个手段 + 一个了结：

| | 内容 | 来源 |
|---|---|---|
| 手段 1a | **Boundary Head**（切换邻域辅助监督） | 初稿第一优先级 |
| 手段 1b | **采样改造**（切换邻域窗口 + 难例负样本） | 初稿第一优先级（"同时可以配合…"） |
| 手段 2 | **多尺度时序**（Local 8/16 帧 + Global 64 帧） | 初稿第二优先级前半 |
| 了结 | 运动特征（bbox/关键点/姿态量）的 **Go/No-Go 单实验** | 初稿第二优先级后半，与 Phase 8 结论冲突，见 §1.4 |

手段 1a 与 1b 在初稿里是**一起提的**，但本阶段把它们**拆成两个独立实验**：
二者作用机制不同（1a 改**监督信号**，1b 改**数据分布**），合在一起跑无法归因是哪一项在起作用，
且违反了本阶段"唯一变量"的硬纪律（Phase 9 教训）。**先各自单独测，都通过再合体。**

**本阶段明确不做**（避免重蹈"方向已关闭又重开"）：

- ❌ 时序架构搜索（Transformer / Bi-LSTM / Mamba / 因果注意力）—— Phase 6 已关闭（三种解码器差 <0.2pp）
- ❌ 损失权重搜索（Focal γ、类别权重）—— Phase 5 已关闭（19 组无一超越默认）
- ❌ 特征层增补矩阵（5 特征 × 4 集成）—— Phase 8 已关闭，本阶段只留一个 Go/No-Go 重试
- ❌ 数据侧清洗 —— Phase 9 两个变体（P9 / P9b）一致否定
- ❌ 容量侧扩充（全参数微调）—— 秩截断已证不损指标（r16→r4 变化 ≤±0.042）
- ❌ 追 E1@6000 的 `fallen_prec 0.795` 纪录 —— 本阶段主攻轴是 fall 轴，静态轴只要求"不退化"
- ❌ **修 val 的 stride** —— 见 §6.2，实测收益 ≤0.02，不值得 3× 开销

## 1. 为什么是这两件事（诊断依据）

### 1.1 主攻轴为什么定 fall 轴

锚点 E1-full 的 fall 轴自身就是"低精度"结构：

| fall 轴 | 值 | 对照：fallen 轴 |
|---|---|---|
| precision | **0.6951** | 0.7551 |
| recall | 0.8305 | 0.7538 |
| 差（rec − prec） | **+0.135** | −0.001 |

即 **fall 轴的亏空几乎全在误报**（把 normal/fallen 报成 fall），而 fallen 轴 prec/rec 基本平衡。
Boundary Head 直接监督"是否在切换邻域"，正是针对这个亏空。

**但必须先认清一处硬约束**（202607/202609 汇报 §七.4）：**prec/rec 前沿极陡**。
延长训练可把 fall 召回推到 **0.8939**（历史最高），但 fallen 召回同时崩到 **0.5609**。
**单一检查点无法兼顾，必须先确定目标轴**——本阶段已定为 fall 轴，因此 §7 的判据把
"不许压召回换精度"写成了硬否决条件。

### 1.2 边界为什么是薄弱点（四组证据）

1. **逐视频 fallen_f1 = 0.6989，150 个含 fallen 的视频里有 27 个 F1 = 0**（全漏或全误报）
2. **fallen 平均检测延迟 4.48 帧**（中位 2 帧），且 `fallen_as_fall_rate = 0.161` —— 从 fall 切到 fallen 后，
   模型平均要多花 4.5 帧才承认"已经倒地"
3. **fall 轴误报亏空**（§1.1）
4. **因果注意力使 fall_f1 从 0.684 掉到 0.615** —— fall 这种短暂过渡态高度依赖前后文；
   双向注意力继续保留（应用场景为事后告警，无需"只能看过去"）

### 1.3 为什么剩下的杠杆只有"监督信号"和"时间尺度"

| 方向 | 状态 | 关闭依据 |
|---|---|---|
| 时序解码器 | 已关闭 | 三种解码器差距 <0.2pp（Phase 6 全因子对比） |
| 损失权重 / Focal γ | 已关闭 | 19 组无一超越默认（Phase 5） |
| 特征层增补 | 已关闭 | 5 特征 × 4 集成全败（Phase 8） |
| 数据清洗 | 已关闭 | P9 / P9b 两变体一致否定 |
| 模型容量 | 已关闭 | 秩截断 r16→r4 指标不变甚至略升（数据受限，非容量受限） |
| **监督信号** | **未动过** | —— 本阶段手段 1 |
| **时间尺度** | **未动过** | —— 本阶段手段 2 |

前五条都在"**用什么特征 / 用什么解码器**"上打转，而 §0 的两个手段动的是
"**监督什么**"与"**看多长的上下文**"——这是两个从未被触碰的维度，也是本阶段立项的核心理由。

### 1.4 ⚠ 与初稿的重大分歧：运动特征（Phase 8 冲突，必须显式记账）

初稿第二优先级后半写：

> "更值得加入的是 bbox、人体关键点或姿态相关的运动量，
> 例如身体中心纵向位移、bbox 高宽比变化、躯干角度、髋部下降速度等。"

**这一串几乎逐条是 Phase 8 已系统证伪的东西**，必须对照清楚：

| 初稿想加的 | Phase 8 的对应实验 | 结果 |
|---|---|---|
| bbox 高宽比变化 | `bbox_aspect` —— 已在 `omnifall_pose_semantic.npz` 的 4 base 维里 | E2b `avg_f1 0.7413`，❌ 误报最重 |
| 躯干角度 | `torso_angle` —— 同表 4 base 维 | 冗余探针：ViT-g 对躯干角 **R²≈0** |
| 髋部下降速度 | 姿态速度维 / `pose_semantic_accel` 12d 的真加速度 | E2c `avg_f1 0.7544`，❌ 只帮动态轴 |
| 身体中心纵向位移 | 姿态位置维（99d / 8d） | E2 / E2b 均低于 baseline |

Phase 8 总结的原话是：

> "姿态（位置/速度）都是**低层运动学信号**，只在'动静'轴有用，够不到 lying vs fallen 需要的
> **语义属性（因果/受控性）**……不是'冗余'（已证伪），也不是'机制太弱'（已给最强机制，
> cross-attention），而是**信号本身不分辨难点**。"

**唯一可为重试开脱的差异条件**：Phase 8 全部实验跑在**冻结** ViT-g 特征上；
本阶段的主干是**微调**过的。202609 汇报 §五记录了一条跨阶段规律——
"**特征工程的有效性依赖于主干质量**"（同一个 Δframe，在 ViT-L 上使 fall_f1 −2.6pp，
在 ViT-g 上却 +1.4pp）。**这是重试的唯一理由，但它只对动态轴有过先例**，
而 fall 轴的边界判定恰好是动态轴的一部分，所以这个重试**不是无理由重做**。

**即便如此，本阶段仍将其降级为单个 Go/No-Go 实验（Exp-4）**，理由：

1. Phase 8 的否定是**信息层**的（信号本身不含受控性），换主干不改变信号的信息量
2. 特征文件**都在本地磁盘**（见 §4.4），重试**几乎零提取成本**，但完整重开 5×4 矩阵成本极高
3. 若重试仍失败，则该方向**永久关闭**，为论文的"否定性结论"补上"已在新主干上复核"这一条

## 4. 实验详细设计

> 通用纪律：**所有 W1 变体共用完全相同的配方**，唯一变量是待测项。
> 这是针对 Phase 9 教训（配方不同 → 不是单变量对照，见 202609 汇报 §七.2）的硬约束。

### 4.0a Exp-0a：三类 + T=32 + 双向（补对照缺口）

**动机**：P4→P6 同时改了**类别设计**（16 类 → 三元）与**窗口长度**（T=32 → 64），两者纠缠。
严格来说需要"三类 + T=32 + 双向"的对照，才能确认三分类本身贡献了多少。**这是 202607 汇报遗留、
至今未补的缺口。**

- 配置：冻结 ViT-g 特征 NPZ + `train_phase6.py --bridge --window_size 32 --no_causal`
- 对照：P6 的"三类 + T=64 + 双向"（`avg_f1 0.753`，`fall_f1 0.684`）
- **成本极低**（冻结特征，无主干前向），本地 4060 即可跑，**不占 3090 预算**
- **产出**：论文 §五 性能轨迹表补一行；把"口径断点"那段论证从"推理"升级为"实测"

### 4.0b Exp-0b：Wave 1 配方锚点（**必须跑，否则 W1 无法归因**）

**动机**：W1 全在 2000 数据上做，需要一个**同配方、同数据、无任何改动**的锚点。
现有 `logs/phase9/e1_5ep`（E1@2000）**配方不同**（5 ep / best=step6000 / 早停史），
直接对比会重犯 Phase 9 的"配方不同 → 不是单变量对照"错误。

- 配置：E1 端到端 + 2000 视频（seed42 打散 train 前 2000，即 E1@2000 的同一子集）+ 3 ep
  + window 64 / 训练 stride 16 / 评测 stride 8 + lr 1e-4 + batch 2 + compile 关
- 记作 **A0**，作为 §7.2 判据的参照
- 同时**复用为 W1 各臂的数据加载与随机种子基准**，保证除待测项外完全一致

### 4.1 Exp-1a：Boundary Head（主线）

**假设**：显式监督"当前帧是否在状态切换邻域"，能把边界判断从"隐式涌现"变成"显式优化"，
从而同时改善 fall 轴的误报（少把 normal 报成 fall）与 fallen 的切入延迟。

**设计**：

- 插入位置：`models/phase6_model.py` 的 `self.decoder(x)` 之后（44x 行，x 为 `(B,T,384)`），
  加 `self.boundary_head = nn.Linear(384, 1)`；forward 改为返回 `(logits, boundary_logits)`。
  **先例**：`models/phase7_model.py:71` 的 `P7EventGateModel` 用 `Linear(384,1)` 做事件门控，
  forward 返回三元组；本阶段沿用同一形状。
  ⚠ 这会破坏 `experiments/train_phase6.py` 的单返回值解包（177 / 186 / 219 行），需同步改。
- 损失：`L = L_CE(三元, 逆频权重) + λ · L_BCE(boundary)`，`λ` 为待定超参
- **boundary 标签定义**（必须在实现前冻结）：

  ```
  对每帧 t，设 y 为该视频的逐帧三元标签（0=fall, 1=fallen, 2=normal）
  切换点集合 S = { t* : y[t*] ≠ y[t*−1] }        （在整段视频上算，不只在窗口内）
  boundary 标签 b[t] = 1  当且仅当  ∃ t* ∈ S 使 |t − t*| ≤ k
  k = 3（帧）默认，另报 k=2 / k=5 的敏感性
  ```

  正类率估计：窗口 64 帧内通常 1–2 个切换点，`k=3` 时约 7–14 帧为正 → **正类率 ~11–22%**，
  不算极端不平衡；BCE 用 `pos_weight` 微调即可。
- **λ 网格**：`{0.1, 0.3, 1.0}` 三档（W1 的 3 个变体）。选点在 2000 上做，**用 §6.3 的选点规则**。
- **对照组**：Exp-0b 的 A0（λ=0 即退化为 A0，故无需单独跑）

**预期与失败解读**：
- 若 fall_prec 升而 fall_rec 稳 → 方向成立，进 W2
- 若 fall_prec 升但 fall_rec 跌破 A0 − 0.03 → **重演 Phase 8 的"压召回换精度"，判失败**
- 若 λ 三档都不动指标 → 说明"边界信息已被三分类 loss 隐式学走"，**该方向关闭**，
  但这是一个有价值的否定结论（与 Phase 6"时序架构已耗尽"同构）

### 4.1b Exp-1b：采样改造（切换邻域窗口 + 难例负样本）

**假设**：当前训练集的分布对"边界帧"是欠采样的 —— 窗口中心帧的逆频采样
（`models/dataset.py:556-588` 的 `_get_longseq_sample_weights_ternary`）只按**中心帧类别**配权，
完全不看窗口内是否含切换点。而切换帧只占全体的极少部分（1200 视频里共 249 个切换点），
模型见到"边界正在发生"的窗口比例远低于其重要性。

**设计**：

- **新权重函数 / Sampler**（`models/dataset.py` 现无此逻辑，需新写并在
  `create_longseq_dataloaders`（591-703 行）加开关）：
  - **切换邻域加权**：窗口内若含切换点 `t*`（`y[t*] ≠ y[t*−1]`）且 `t*` 落在窗口中心 ± w 内，
    权重 ×(1+α)；`w`、`α` 为参数（建议 `w=8`、`α=2.0` 起步）
  - **难例负样本**：快速坐下 / 蹲下 / 弯腰 / 主动躺下（16 类中的 `sit_down`、`squat` 类、
    `lie_down` 等）。这些类别的窗口权重额外上调
  - **必须防退化**：加权后要检查实际采样分布，避免把 normal 的多样性挤掉
    （Phase 9 的 P9 实验正是"移除保守先验 → fallen_prec 崩"的反面教材）
- **唯一变量**：仅采样权重；模型、损失、轮数、数据量与 Exp-0b 完全相同
- **成本**：仅改数据侧，**不增加前向成本** → 单跑 ~9 h（与 A0 同）

**预期与失败解读**：
- 若 fall 轴提升且 **`fall_prec` 与 `fall_rec` 同向改善** → 方向成立
- 若只是 `fallen_prec` 抖动 → 采样动的是边界帧，不该主要影响静态轴，需查实现
- 若整体退化 → 说明逆频采样已经是更好的折中（与 Phase 5"权重方向已关闭"同构）

### 4.2 Exp-2：多尺度时序（主线）

**假设**：fall 是短动态过程、fallen 是长静态状态，单一 T=64 分支不是两者的最优感受野。

**两种实现（W1 各跑一个，先跑便宜的）**：

| 变体 | 实现 | 成本 | 说明 |
|---|---|---|---|
| **2a 单窗双分支**（先跑） | 主干特征共享，Global 用现有 Transformer，Local 用**深度可分离 1D 卷积栈（k=8 与 k=16 并联）**在 384d 上做局部算子；两者输出 concat → Linear → 三元头 | **几乎零增量**（主干前向共用，只多几层卷积） | 推荐首选 |
| **2b 双窗双分支** | Local 分支用 8/16 帧短窗、Global 用 64 帧长窗，两次窗口采样后按帧对齐融合 | 高（需两次窗口采样/前向） | 仅在 2a 失败后考虑 |

**关键成本论据**：E1 是端到端，主干前向是绝对成本大头。2a 的 Local 分支**复用同一批逐帧 CLS 特征**，
不增加任何主干前向 → **多尺度几乎是免费的**。这是 2a 优先的核心理由。

**注意**：本阶段**不动 Δdiff**。初稿写"停止对 ViT embedding 做一阶、二阶差分"，
但当前最优模型的输入**恰恰是 `CLS + Δdiff`（3072d）**，且 P7 已实测 Δframe 在 ViT-g 上
带来 `avg_f1 +1.4pp`。照字面移除 Δdiff = 拆当前最优配置的零件，属**未经验证的破坏性改动**。
**本阶段对该句的解释是**："不再**新增**二阶/语义差分作为增补特征"（P8 已就此证伪），
**保留**现有 Δdiff。若确要验证 Δdiff 的必要性，作为独立消融单独报告（W3 可选）。

## 5. 新指标：边界定位指标的定义与验收

> **CLAUDE.md 强制**：任何指标首次提出必须写明**分子、分母（适用人群）、统计口径、单位**。
> 本项目 2026-09 已因 `event_f1` 名实不符（逐帧二值 F1 却叫"事件级"）付出代价，
> 该指标已废除并降级为历史对照。**本次新增指标按新规执行。**

### 5.1 定义

**边界定位指标（边界级，单位 = 帧）**

| 项 | 定义 |
|---|---|
| **真值边界集合** | `B_gt = { t : y[t] ≠ y[t−1], t ∈ [1, 79] }`，在整段视频上算；按切换类型分列（`normal→fall`、`fall→fallen`，另计 `fall→normal` 等恢复类） |
| **预测边界集合** | `B_pred`，由预测序列派生，**必须先过与评测一致的后处理**（多窗多数投票 + 最小事件长度），否则预测抖动会把 `\|B_pred\|` 打爆 |
| **匹配规则** | 贪心一对一匹配（按时间序），命中条件 `\|b_pred − b_gt\| ≤ τ`；一个 `b_gt` 最多配一个 `b_pred` |
| **容差 τ** | 默认 **3 帧**；另报 τ=1 / τ=5 做敏感性，**三档并列报告，禁止只报对自己有利的那档** |
| **边界精确率** | 分子 = 匹配上的 `b_pred` 数；分母 = `\|B_pred\|`（模型报出的全部边界数） |
| **边界召回率** | 分子 = 匹配上的 `b_gt` 数；分母 = `\|B_gt\|`（真值边界数） |
| **边界 F1** | `2PR/(P+R)`；无量纲 |
| **适用人群** | 全部视频；**不含任何边界的视频（标签恒定）排除，而非记 0** |

### 5.2 两道验收（**必须先跑出数，才可采用**）

- **① GT 自检**：GT 当预测喂入 → 要求 `P = R = F1 = 1.0000`（必须满分）。
  关键在"非事件视频排除而非记 0"——若记 0 则永远达不到满分，自检本身会暴露这个实现错误。
- **② 负对照**（须**单调劣化**，且要跑出具体数）：
  - 全漏（不报任何边界）→ `R = 0, F1 = 0`
  - 真值平移 3 / 10 帧 → F1 单调下降，且检测延迟被准确读出 3 / 10
  - 随机抖动（注入 k 个假边界）→ 精确率随 k 单调下降

### 5.3 已知缺陷（**随指标一起声明，否则后人复用必踩坑**）

1. **τ 的选择影响可比性** —— 不同 τ 下模型排序可能变化；故 τ 必须三档并列报告。
2. **抖动惩罚偏重精确率** —— 预测序列的抖动会膨胀 `|B_pred|`，直接压低精确率。
   缓解手段是固定后处理（与评测口径一致），但该后处理本身成为一个可调项，须记录。
3. **样本量小** —— 1200 个视频里只有 249 个切换点（尾部 16 帧仅占 19 个），
   故边界指标的置信区间较宽，**跨配置的小幅差异（<0.03）不可当真**。
   （切换点计数来自本次实测，见 `logs/phase9/val_truncation_bias.json`）

## 6. 评估协议与选点规则

### 6.1 主口径

- **评测集**：官方 `test.csv` 的 1200 视频（held-out，全程不参与训练与选点）
- **帧级**：instance（230,400 帧实例，与 Phase 9 同口径，保持与 E1-full 可比）
  **并**报 merged_raw（去重 96,000 帧，与 Phase 10 通用基线口径一致）
- **事件级**：`utils/timeline_metrics.py`（覆盖率 / 误报率 / 逐视频 F1 / 翻转 / 延迟 / order_correct）
- **边界级**：§5 新增指标
- **三口径并列报告，禁止只挑对己有利的一个**（`metric-event-f1-deprecated` 约定）

### 6.2 ⚠ val 协议勘误（**本阶段必须纠正的一条既有归因**）

既有文档与记忆把 val→test 的落差归因于"val 只看每视频前 64 帧"。**2026-09-27 实测推翻了该归因**：

`analysis/verify_val_truncation_bias.py`（产物 `logs/phase9/val_truncation_bias.log` / `.json`）——
固定同一批 E1-full 的 1200 视频逐视频预测，只把评测窗口从 0–79 截到 0–63：

| 口径 | Δ(截断 − 全帧) |
|---|---|
| instance `fallen_prec` | **+0.0166** |
| instance `fall_prec` | +0.0082 |
| instance `avg_f1` | +0.0029 |
| 逐视频 `fallen_f1` | +0.0237 |
| 逐视频 `avg_f1` | +0.0024 |
| `pass_rate` | +0.0385 |

**截断只解释落差（best ckpt 的 `fallen_prec` 落差 = 0.147）的约 11%**，且方向是让 val 更好。
标签层同样支持"尾部无关紧要"：尾部 16 帧只含 **7.63%** 的状态切换，
**0 个**视频的首个 fall 落在 ≥64（onset 信息全在 0–63 内）——虽然它含 **25.92%** 的 fallen 帧。

**真正的主因**：
1. **val 监控集与 test 集类分布不同**：`data/p9e1_frames_val` 的 150 视频中 29 个含 fallen（19.3%），
   test 是 150/1200（12.5%）；帧级 fallen 密度（0–63）**11.57% vs 7.12% = 1.62×**。
   分母里正类多，同样误报率算出的精度天然更高。
2. **150 视频小样本 + 选型偏差**：val 只有 29 个含 fallen 的视频；`monitor.json` 中
   `val_fallen_prec` 全程在 **0.6679 ~ 0.9689** 间跳（中位 0.8900，48 次检查），而 best 又按 val 挑。

**因此本阶段撤下"val_check 改 stride 8"这条修法**（≤0.02 收益 / 3× 开销），改为：

- **`val` 恢复本职**：只画趋势曲线，**不用于静态轴选型**
- **扩大并配平 val 集**：视频数提到 300+，且**按类构成配平**（含 fallen 的比例对齐 test 的 12.5%）
- **选点规则见 §6.3**

### 6.3 选点规则（本阶段新规）

1. **选型不取单次 val 极值** —— 用 val 的**平滑值或末 k 次均值**（k=3）
2. **top-k ckpt 走全量 test**：对 val 排序前 3 的 ckpt 各跑一次 test，
   **在选择规则事先写明的条件下**选最终模型，并在文档中标注"test 集选择偏差"
3. **`avg_f1` 是唯一可跨 ckpt 比较的 val 指标**（gap 稳定 ~0.085–0.11 可外推）；
   **`fallen_prec` 绝不跨 ckpt 比较**（gap 按 ckpt 剧烈波动）
4. **最终报告一律用 test**，val 数字只作趋势叙述

## 8. 长任务运行约定（**强制**，CLAUDE.md 四件套）

W1 单跑 ~9 h、W2/W3 单跑 ~42 h，均为长任务。**每一项都必须配齐**：

1. **启动前先写终止预案**（预估总时长 → 提前决定异常时自动做什么，固化成可执行命令）：
   - 总时长：2000 数据 3 ep ≈ 8.8 h；9600 数据 3 ep ≈ 42.3 h
   - **早停触发** → 自动以 `--early_stop_patience 0`（跑满轮）重跑（E1 首轮 patience=2 在 1.5ep 被掐，
     test `fallen_prec` 仅 0.506 的废数字，是既有教训）
   - **loss = nan / 发散** → 立即停、诊断（降 lr / 查数据）后重启，**绝不带病跑完污染下游**
   - **OOM** → 降 batch 重跑
2. **进程级退出监视，而非只盯里程碑**：
   - 以进程消失（`pgrep`）为信号，进程一退立即判型并执行预案
   - ⚠ **判活用 `/proc/<pid>/stat` 第 3 字段是否为 `Z`**，不可用 `kill -0`（子进程退出后变僵尸，
     `kill -0` 仍返回成功 → 循环永不退出，E1-full 首跑即卡死于此）
   - ⚠ `pkill -f <pattern>` 会**匹配到自己的远程 shell** → 用字符类技巧
     （`pkill -f "train_p9e1_dua[l]"`），杀前先 `pgrep -af` 核对
   - ⚠ 让 **runner 自己在末尾写完成标记**（如 `ALL_DONE`）；watchdog 判型只作补充
     （实例在轮询窗口内被关机时判型会永久丢失）
3. **定时进度检查**：不得只依赖"会话内 + 仅 REPL 空闲才触发"的机制（会话 cron 会因会话忙/关而失效）；
   须由服务器端 cron / 启动脚本自带 watchdog / 或显式把"几点出结果、跑完自动执行 X"交接给用户
4. **结束/异常即时可见**：每个运行给出日志路径 + 现成 tail 命令（Git Bash 与 PowerShell 双版本）
   + 本地日志镜像；进程退出即汇报

**已踩过的坑（直接沿用结论）**：`torch.compile` 与 transformers DINOv2 + 梯度 checkpointing 不兼容
（首个前向即 `TypeError: layer_norm(): argument 'input' must be Tensor, not NoneType`）；
本项目端到端训练**保持 compile OFF**（=E1@6000/E1-full 已验证配方），冒烟 10 分钟即可判死。

**产物归档（硬规则）**：远程任务一结束立即 `scp` 回本地 `logs/phase11/<exp>/`，
逐项核对（文件数 + 字节数/校验和），**核对通过才可说"完成"或"可关机"**。

## 附录 B：原规划草案（2026-09-25，保留原文）

> 保留初稿原文以便对照"哪些被采纳、哪些被修正"。修正处已在正文标注。

> 首先是当前的情况分析：
>
> Phase 10 已经把方向筛得比较清楚了：真正有效的变化主要来自把原来的 16 类多任务改成直接的
> fall / fallen / normal 三分类，而 LSTM、Temporal Transformer、因果注意力以及 Focal Loss
> 参数调整都没有带来明显收益。尤其是因果注意力后 fall_f1 从 0.684 降到 0.615，说明 fall 这种
> 短暂的过渡状态非常依赖前后文信息，因此后续应该继续保留双向注意力。
>
> 另外目前 p4 到 p6 同时改变了类别设计和 T=32→64，严格来说还需要补一个 3类 + T32 + bidir 的
> 对照，确认三分类本身到底贡献了多少提升。
>
> 整体来看，当前瓶颈已经不太像"时序模型不够强"，而更像是 fall 与 normal/fallen 之间的状态
> 边界难判断，以及现有视觉特征对真实运动变化表达不足。
>
> 接下来是接下来工作的优先级
>
> 强化 fall 状态边界的学习。
>
> 我建议先保持当前三分类、T=64、双向 Transformer 不变，在时序特征后额外增加一个很轻量的
> Boundary Head，用来判断当前帧是否位于 normal→fall 或 fall→fallen 的状态切换附近，训练时采用
> 三分类 loss + boundary loss。
>
> 同时可以配合改变采样方式，让训练 batch 更多地包含跌倒开始、跌倒结束附近的窗口，以及快速坐下、
> 蹲下、弯腰、主动躺下等 hard negative。
>
> 这样优化的是模型目前最明显的弱点——知道人是什么状态不难，但准确找到"什么时候开始跌、
> 什么时候已经倒地"比较难。
>
> 这个方向改动小，也最适合作为下一阶段的第一组实验。
>
> 第二优先级：补充真正的运动信息和多尺度时序特征。
>
> fall 是一个很短的动态过程，而 fallen 更像一个持续的静态状态，统一使用 T=64 的一个时序分支
> 未必最合适，可以尝试 Local 8/16 帧 + Global 64 帧 两个时间尺度：短窗口负责捕捉快速姿态变化，
> 长窗口负责判断倒地后的持续状态。同时不要再对 ViT embedding 做一阶、二阶差分，因为它反映的是
> 语义空间变化而不是真实速度；更值得加入的是 bbox、人体关键点或姿态相关的运动量，例如身体中心
> 纵向位移、bbox 高宽比变化、躯干角度、髋部下降速度等。
>
> 这样才能真正给模型补上区分"快速跌倒"和"正常躺下/蹲下"的动态信息。

**对初稿的处置一览**：

| 初稿条目 | 处置 |
|---|---|
| 保留双向注意力 | ✅ 采纳（§1.2 证据 4），并升级为"应用场景决定"的论证 |
| 补 三类+T32+双向 对照 | ✅ 采纳 → Exp-0a |
| 瓶颈判断（状态边界 + 运动表达不足） | ⚠ 部分采纳：边界难判 ✅ 立为主线；"运动表达不足"降级（Phase 8 已证伪，见 A2） |
| Boundary Head + boundary loss | ✅ 采纳 → Exp-1（补齐标签定义、λ 网格、失败判据） |
| 采样改造（难例 + 切换邻域窗口） | ✅ 采纳 → Exp-1b；但与 1a 拆开单独测（见 §0 说明） |
| 多尺度 Local 8/16 + Global 64 | ✅ 采纳 → Exp-2，并补两种实现与成本论据 |
| 停止对 ViT embedding 做差分 | ❌ 修正（见 A3）：保留 Δdiff |
| 加 bbox / 关键点 / 姿态运动量 | ⚠ 降级为 Exp-4 单次 Go/No-Go（见 §1.4） |
