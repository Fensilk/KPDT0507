## 1. 统一协议（所有模型共用）

| 项 | 约定 |
|---|---|
| 数据 | 全画面抽帧（整帧 squash，不裁剪视野）：12,000 视频 × 80 帧 × 256² |
| 划分 | `DATASET-omnifall/splits/syn/random`：train 9,600 / val 1,200 / test 1,200 |
| 任务 | 帧级三元：0=fall、1=fallen、2=normal（映射同 `models/dataset.py`） |
| 参考模型形式 | 片段分类器：输入 T 帧窗口，标签取**窗口中心帧**的三元标签 |
| 评测集 | 同一 **96,000 帧**（1,200 test 视频 × 80 帧），与 E1-full 同帧集重算 |
| 指标 | **instance**：acc / avg_f1 / 各类 P·R·F1；**timeline**：逐视频 F1、覆盖率、误报率、翻转/视频 |
| 投入上限 | 每个参考模型只跑**一套官方/默认配方**，不做逐模型调优（阶段目标是横向参照，不是刷基线） |
| 预算原则 | 见规划文档 **§4.4.1 模型预算判定原则**：唯一的对标对象是 E1-full，基线之间不要求同预算；每个模型的预算由证据选出（B=5 探针 → 看 val 峰值位置 → 必要时用 2,000 视频子集对比 B=5/B=10 → 胜者跑全量），并记录在 §3 汇总表 |

## 2. 模型实验

### 2.1 TSM（已完成）

#### 做法

| 项 | 取值 |
|---|---|
| 模型 | 官方 TSN/TSM：ResNet50 + `shift_div=8` + `shift_place=blockres`，8 帧，23.5 M 参数 |
| 输入 | 全画面 256² → 训练随机裁剪 224²（scale 0.7–1.0）+ 水平翻转；测试中心裁剪 224² |
| 采样 | 每视频 **73 个 8 帧窗口**（stride 1），标签 = 窗口中心帧三元标签 |
| 初始化 | Kinetics-400 TSM（8 帧）权重 |
| 训练 | SGD，lr 0.010（backbone lr/10），wd 5e-4，动量 0.9，逐窗口 CE + 逆频类权重，AMP fp16，梯度裁剪 5，batch 32；上限 5 epoch + early stop patience 2（实际 4 epoch 停） |
| 硬件 | Autodl RTX 3090，145.8 min/epoch |
| 评测 | stride 1 稠密滑窗，clip 预测写回窗口内所有帧并跨窗口平均 → 逐帧三元预测 |

#### 结果（同一 96,000 帧 / 1,200 视频）

| 指标 | TSM | E1-full | 差 |
|---|---|---|---|
| ternary_acc | 0.9017 | 0.9370 | −0.035 |
| avg_f1 | 0.7352 | 0.8296 | **−0.094** |
| fall P / R / F1 | 0.614 / 0.716 / 0.6609 | — / — / 0.7689 | −0.108 |
| fallen P / R / F1 | 0.611 / 0.580 / 0.5954 | — / — / 0.7510 | **−0.156** |
| 逐视频 fall_f1 | 0.6953 | 0.7827 | −0.087 |
| 逐视频 fallen_f1 | 0.5485 | 0.6989 | −0.150 |
| 覆盖率 fall / fallen | 0.957 / 0.713 | 0.962 / 0.833 | −0.005 / **−0.120** |
| 误报率 fall / fallen | 0.058 / 0.064 | 0.026 / 0.035 | +0.032 / +0.029 |
| 翻转 / 视频 | 0.64 | 0.63 | +0.01 |

#### 结论

1. TSM 全面低于 E1-full，且**差距集中在静态轴**：fallen_f1 −0.156、fallen 覆盖率 −0.120。
2. 误报率是 E1 的 2 倍左右（0.058/0.064 vs 0.026/0.035），即"把正常躺卧误报成跌倒/倒地"更频繁。
3. 结论在把数据与训练条件都对齐后依然成立（对比见附录 A.4），
   即差距来自**模型范式**（片段分类 vs 事件级时序建模），不是我们没给够条件。

### 2.2 SlowFast-R50（已完成）

#### 做法

| 项 | 取值 |
|---|---|
| 模型 | `pytorchvideo` SlowFast-R50，**33.65 M 参数**，Kinetics-400 预训练（`SLOWFAST_8x8_R50.pyth`） |
| 输入 | 单条 32 帧片段拆成两路：fast = 全部 32 帧，slow = 每 4 帧取 1（8 帧）；224² |
| 采样 | 每视频 **7 个 32 帧窗口**（stride 8），标签 = 窗口中心帧三元标签 |
| 训练 | SGD lr 0.01、wd 5e-4、动量 0.9，余弦 **T_max=5**，5 epoch，batch 32，AMP fp16，逐窗口 CE + 逆频类权重 |
| 耗时 | 28.3 min/epoch × 5 = **141 min**（2.4 h）；GPU 峰值 21.5 GB |
| 评测 | stride 1 稠密滑窗（58,800 片段）→ 逐帧合并 → instance + timeline，与 E1-full 同帧集 |

#### 结果（同一 96,000 帧 / 1,200 视频）

| 指标 | SlowFast-R50 | E1-full | 差 |
|---|---|---|---|
| ternary_acc | 0.9118 | 0.9370 | −0.025 |
| avg_f1 | **0.7612** | 0.8296 | −0.068 |
| fall_f1 | 0.7008 | 0.7689 | −0.068 |
| fallen_f1 | 0.6260 | 0.7510 | **−0.125** |
| 逐视频 fall_f1 / fallen_f1 | 0.5894 / 0.5527 | 0.7827 / 0.6989 | **−0.193** / −0.146 |
| 覆盖率 fall / fallen | **0.801** / 0.693 | 0.962 / 0.833 | **−0.161** / −0.140 |
| 误报率 fall / fallen | 0.027 / 0.049 | 0.026 / 0.035 | ≈0 / +0.014 |
| 翻转 / 视频 | **0.30** | 0.63 | −0.33 |

#### 结论

1. **SlowFast 是目前最强的基线**（instance avg_f1 0.7612、acc 0.9118，离 E1 最近），
   差距仍集中在静态轴 fallen（−0.125）。
2. 但它在**事件级出现明显短板**：逐视频 fall_f1 只有 0.5894（比它自己的 instance fall_f1 0.7008 低 0.11），
   **fall 事件覆盖率仅 0.801**——约 20% 的跌倒视频它一次都没报出来（E1 为 0.962）。
   即"逐帧看着还行，但整段事件会漏"。
3. 它的时间线最稳（翻转 0.30，误报率也低），属于"少说少错"型；
   与 X3D-S（保守但 fall 覆盖好）、TSM（覆盖好但误报多）形成三种不同的失败模式，
   而 E1 在两类指标上同时更好。
4. 预算判定（按 §4.4.1）：val 峰值在 **ep4**（0.7985），ep5 持平（0.7983）→ **B=5 合适**，无需补探针。

### 2.3 X3D-S（已完成）

#### 做法

| 项 | 取值 |
|---|---|
| 模型 | `pytorchvideo` X3D-S，**2.98 M 参数**（官方 X3D 家族最小档） |
| 输入 | 16 帧 × 224²（全画面 256² → 随机裁剪/中心裁剪），Kinetics-400 预训练 |
| 采样 | 每视频 **9 个 16 帧窗口**（stride 8），标签 = 窗口中心帧三元标签 |
| 训练 | SGD lr 0.01、wd 5e-4、动量 0.9，余弦退火 **T_max=5**，固定 5 epoch，batch 32；AMP fp16；逐窗口 CE + 逆频类权重 |
| 实现 | `experiments/train_p10_video.py`（与 TSM 共用同一片段数据集与评测代码；分类头替换为 3 类线性头并去掉原头的 Softmax） |
| 评测 | 同 TSM：stride 1 稠密滑窗 → 逐帧合并 → instance + timeline，与 E1-full 同帧集 |

#### 结果（同一 96,000 帧 / 1,200 视频）

| 指标 | X3D-S | E1-full | 差 |
|---|---|---|---|
| ternary_acc | 0.8994 | 0.9370 | −0.038 |
| avg_f1 | 0.7303 | 0.8296 | **−0.099** |
| fall_f1 | 0.6806 | 0.7689 | −0.088 |
| fallen_f1 | 0.5608 | 0.7510 | **−0.190** |
| 逐视频 fall_f1 / fallen_f1 | 0.7198 / 0.5046 | 0.7827 / 0.6989 | −0.063 / **−0.194** |
| 覆盖率 fall / fallen | 0.957 / 0.673 | 0.962 / 0.833 | −0.005 / **−0.160** |
| 误报率 fall / fallen | 0.068 / 0.046 | 0.026 / 0.035 | +0.042 / +0.011 |
| 翻转 / 视频 | **0.46** | 0.63 | −0.17 |
| 顺序正确率 | 1.000 | — | — |

#### 结论

1. 与 TSM 呈现**同一模式**：整体落后 E1-full（avg_f1 −0.099），且**差距集中在静态轴**
   （fallen_f1 −0.190、fallen 覆盖率 −0.160）。
2. X3D-S 的特点是"**保守**"：时间线最稳（翻转 0.46、顺序正确率 1.000、fallen 误报率仅 0.046），
   但它**几乎不报 fallen**（覆盖率 0.673）——即"漏报"而非"误报"。
   这与 TSM 恰好相反（TSM fallen 覆盖率 0.713 但误报 0.064），两者从不同方向偏离 E1。
3. 预算敏感性（方法学，见附录 A.6）：同一模型换成长调度（T_max=15 + 早停 3）后 best val 反而更低
   （0.7282 vs 0.7474）——**报告的数值强烈依赖调度形状**，因此本阶段所有模型统一固定 5 轮余弦。

### 2.4 TimeSformer（已完成）

#### 做法

| 项 | 取值 |
|---|---|
| 模型 | HuggingFace `transformers` 版 TimeSformer（官方 `facebook/timesformer-base-finetuned-k400` 权重），**121.26 M 参数**；分类头换为 3 类（加载时 missing=2、head re-init=2） |
| 输入 | **8 帧 × 224²**，channel-last `(B, T, C, H, W)`（与 pytorchvideo 的 channel-first 相反，无需 permute）；wrapper 先把数据集归一化反解回 [0,1]，再套用该 checkpoint 自己的 `image_mean/std` |
| 采样 | 每视频 **10 个 8 帧窗口**（stride 8），标签 = 窗口中心帧三元标签 |
| 训练 | SGD lr 0.005、wd 5e-4、动量 0.9，余弦退火 **T_max=5**，batch 16，AMP fp16，逐窗口 CE + 逆频类权重，梯度裁剪 5；上限 5 epoch + early stop patience 2（**实际 4 epoch 停**） |
| 耗时 | 58.6–59.2 min/epoch（末段 28.1 clips/s，显存约 19 GB）× 4 = **235.4 min**（3.9 h） |
| 评测 | stride 1 稠密滑窗（87,600 片段 → 96,000 帧）→ 逐帧合并 → instance + timeline，与 E1-full 同帧集 |

#### 结果（同一 96,000 帧 / 1,200 视频）

| 指标 | TimeSformer | E1-full | 差 |
|---|---|---|---|
| ternary_acc | 0.8978 | 0.9370 | −0.039 |
| avg_f1 | 0.7140 | 0.8296 | **−0.116** |
| fall P / R / F1 | 0.631 / 0.634 / 0.6324 | — / — / 0.7689 | −0.137（F1） |
| fallen P / R / F1 | 0.608 / 0.524 / 0.5630 | — / — / 0.7510 | **−0.188（F1）** |
| 逐视频 fall_f1 / fallen_f1 | 0.6630 / 0.4817 | 0.7827 / 0.6989 | −0.120 / **−0.217** |
| 覆盖率 fall / fallen | 0.919 / **0.640** | 0.962 / 0.833 | −0.043 / −0.193 |
| 误报率 fall / fallen | 0.066 / 0.055 | 0.026 / 0.035 | **+0.040** / +0.020 |
| 翻转 / 视频 | 0.58 | 0.63 | −0.05 |
| 顺序正确率 | 0.986 | — | — |

#### 结论

1. TimeSformer 在已完成的参考模型里**居中偏下**（instance avg_f1 0.7140：低于 SlowFast 0.7612、TSM 0.7352、
   X3D-S 0.7303，高于 C3D 0.5996），差距同样集中在**静态轴**：fallen_f1 −0.188、逐视频 fallen_f1 −0.217、
   fallen 覆盖率仅 0.640（E1 为 0.833）。
2. 它的失败模式是"**覆盖和误报同时变差**"：fallen 覆盖率 0.640 属保守型漏报（接近 X3D-S 的 0.673），
   同时两轴误报率 0.066 / 0.055 分别是 E1 的 2.5 / 1.6 倍（fall 误报率与 X3D-S 的 0.068 相当）。
   事件级 timeline avg_f1 0.5881 是已完成基线中最低的——即"逐帧不占优、事件级更差"。
3. 预算判定（按 §4.4.1）：val 峰值在 **ep2（0.7145）**，ep3 回落到 0.6980、ep4 回到 0.7141（未超峰值），
   patience 2 在第 4 轮停止 → **B=5 合适**（峰值落在预算内）。但 best checkpoint 落在**调度中段**
   （ep2 时 LR≈3.3e-3，余弦抛光段还没发生），按 A.6 的教训该数值对调度形状仍敏感；ep3 的回落也说明
   它在 5 轮余弦预算下不稳定（train_loss 从 ep1 的 0.516 一路降到 ep4 的 0.233，而 val 自 ep2 起不再改善）。
4. 与全阶段结论一致：同为视频预训练 Transformer，TimeSformer 并没有因全局注意力而在 fallen 上占优，
   instance/timeline 双口径都落后于 3D CNN 系的 SlowFast。本阶段只跑统一单配方，
   不进一步分离"预训练数据 / 输入帧数 / 优化器"等因素（差异清单见 A.5）。

### 2.5 I3D-R50（已完成）

> 命名按规划文档 §3 的要求区分：这里的 **I3D-R50 是 `pytorchvideo` 的 R50 移植版 + Kinetics-400 权重**，
> **不是** DeepMind 的 Inception-I3D（论文原始版，64 帧、TensorFlow 1 实现）。

#### 做法

| 项 | 取值 |
|---|---|
| 模型 | `pytorchvideo` I3D-R50（`I3D_8x8_R50.pyth`），**27.23 M 参数**，Kinetics-400 预训练；分类头换为 3 类 |
| 输入 | **8 帧 × 224²**（该 checkpoint 的官方 "8x8 setting"：8 帧、时间采样步长 8），全画面 256² → 训练随机裁剪 / 测试中心裁剪 224² |
| 采样 | 每视频 **10 个 8 帧窗口**（stride 8），标签 = 窗口中心帧三元标签（96,000 训练片段 / 12,000 验证片段） |
| 训练 | SGD lr 0.01、wd 5e-4、动量 0.9，余弦退火 **T_max=5**，batch 32，AMP fp16，逐窗口 CE + 逆频类权重，梯度裁剪 5；上限 5 epoch + early stop patience 2（**实际 4 epoch 停**） |
| 耗时 | 13.3 min/epoch × 4 = **53.1 min**（0.9 h），Autodl RTX 3090；吞吐约 125 clips/s，显存约 11 GB |
| 评测 | stride 1 稠密滑窗（87,600 片段 → 96,000 帧）→ 逐帧合并 → instance + timeline，与 E1-full 同帧集 |

#### 结果（同一 96,000 帧 / 1,200 视频）

| 指标 | I3D-R50 | E1-full | 差 |
|---|---|---|---|
| ternary_acc | 0.8696 | 0.9370 | **−0.067** |
| avg_f1 | 0.7076 | 0.8296 | **−0.122** |
| fall P / R / F1 | 0.522 / 0.768 / 0.6213 | — / — / 0.7689 | −0.148（F1） |
| fallen P / R / F1 | 0.490 / 0.692 / 0.5735 | — / — / 0.7510 | **−0.178（F1）** |
| 逐视频 fall_f1 / fallen_f1 | 0.7526 / 0.6377 | 0.7827 / 0.6989 | −0.030 / −0.061 |
| **逐视频 avg_f1（timeline 主指标）** | **0.7103** | 0.7413 | **−0.031** |
| 覆盖率 fall / fallen | 0.972 / 0.793 | 0.962 / 0.833 | +0.009 / −0.040 |
| 误报率 fall / fallen | 0.123 / 0.119 | 0.026 / 0.035 | **+0.097 / +0.084** |
| 翻转 / 视频 | 0.79 | 0.63 | +0.16 |
| 顺序正确率 | 0.993 | 1.000 | — |

#### 结论

1. **帧级是"高召回、低精度"**：fall recall 0.768 / fallen recall 0.692 都不低，但 precision 只有 0.522 / 0.490，
   于是 fall/fallen F1 分别比 E1 低 0.148 / 0.178。混淆矩阵里 **4,853 个 normal 帧被判成 fallen、3,885 个被判成 fall**。
   失败模式与 C3D 同类（"多报"），只是幅度约为其一半（C3D 误报率 0.217/0.201，I3D-R50 为 0.123/0.119）。
2. **事件级却是所有参考模型里最接近 E1 的**：逐视频 avg_f1 **0.7103**（E1 0.7413，只低 0.031），
   高于 C3D 0.6590、X3D-S 0.6489、TSM 0.6421、SlowFast 0.5949、TimeSformer 0.5881；
   fall 事件覆盖率 0.972 甚至略高于 E1（0.962）。代价是误报率 0.123/0.119（E1 的 4.7 / 3.4 倍）与
   翻转 0.79/视频（已完成基线里最高）。即它用"**高覆盖 + 高误报**"换来了事件级定位分数，
   这与帧级低精度是同一枚硬币的两面——写论文时应把它作为"事件级排名与帧级排名可以不一致"的例证。
3. 预算判定（按 §4.4.1）：val 峰值在 **ep2（0.7288）**，ep3/ep4 为 0.7219/0.7232，patience 2 在第 4 轮停止
   → **B=5 合适**。值得注意的是 **val_acc 持续上升（0.858→0.895）而 avg_f1 在 ep2 后停滞**：
   准确率被 normal 类主导，这再次印证"静态轴（fallen）才是瓶颈"，也说明只看 acc 会误判收敛位置。
4. 迁移强度上，I3D-R50 的**事件级**结果说明 K400 的 3D CNN 预训练在 OmniFall 上并非没有价值，
   但这种价值体现在"把事件位置大体框住"，而不是"把 fall/fallen/normal 分清"——后者仍需本方法的
   事件级时序建模与后处理才能达到 E1 的水平。

### 2.6 C3D（已完成）

#### 做法

| 项 | 取值 |
|---|---|
| 模型 | 自研 PyTorch C3D（`experiments/c3d_model.py`），**78.01 M 参数**，参数量对齐论文；因官方仓库没有可用权重，**从零训练** |
| 输入 | 全画面 256² → 训练随机裁剪/测试中心裁剪 224² → 再缩放为 **16×112²** |
| 采样 | 每视频 **9 个 16 帧窗口**（stride 8），标签 = 窗口中心帧三元标签 |
| 训练 | SGD lr 0.005、wd 5e-4、动量 0.9，余弦退火 **T_max=5**，上限 5 epoch + early stop patience 2；batch 32，AMP fp16，逐窗口 CE + 逆频类权重 |
| 耗时 | 约 **44.5 min**（0.74 h），Autodl RTX 3090；训练末段约 170 clips/s |
| 评测 | stride 1 稠密滑窗（78,000 片段）→ 逐帧合并 → instance + timeline，与 E1-full 同帧集 |

#### 结果（同一 96,000 帧 / 1,200 视频）

| 指标 | C3D | E1-full | 差 |
|---|---|---|---|
| ternary_acc | 0.7796 | 0.9370 | **−0.157** |
| avg_f1 | 0.5996 | 0.8296 | **−0.230** |
| fall P / R / F1 | 0.392 / 0.750 / 0.5145 | — / — / 0.7689 | −0.254（F1） |
| fallen P / R / F1 | 0.310 / 0.636 / 0.4170 | — / — / 0.7510 | **−0.334（F1）** |
| 逐视频 fall_f1 / fallen_f1 | 0.7037 / 0.5974 | 0.7827 / 0.6989 | −0.079 / −0.102 |
| 覆盖率 fall / fallen | 0.957 / 0.760 | 0.962 / 0.833 | −0.005 / −0.073 |
| 误报率 fall / fallen | 0.217 / 0.201 | 0.026 / 0.035 | **+0.191 / +0.166** |
| 翻转 / 视频 | 0.84 | 0.63 | +0.21 |
| 顺序正确率 | 0.993 | — | — |

#### 结论

1. C3D 是当前**帧级最弱、且落后幅度最大**的参考模型：instance avg_f1 0.5996，比 E1-full 低 0.230；
   fall/fallen F1 分别低 0.254/0.334。它并非“只漏不报”，而是**高召回、低精度**：fall recall 0.750
   但 precision 仅 0.392，fallen recall 0.636 但 precision 仅 0.310；混淆矩阵中 10,148 个 normal 帧被报成 fallen。
2. 事件级结果看似更接近其他基线（timeline avg_f1 0.6590，甚至略高于 TSM/X3D-S），
   原因是它的事件覆盖率不低（fall/fallen = 0.957/0.760）；但这些覆盖主要靠**大量误报**换来，
    fall/fallen 误报率高达 0.217/0.201，是 E1-full 的约 8.3/5.7 倍。因此其失败模式应概括为“多报”，
   而不是事件定位能力强。
3. 预算判定（按 §4.4.1）：val 峰值在 **ep3**（0.6085），ep5 为 0.6072，未超过峰值，
   patience 2 正常停止 → **B=5 合适**。该结果同时受“无 K400 预训练、16×112² 输入、旧式 3D 卷积”
   影响；本次只跑统一单配方，不进一步分离这些因素。

### A.4 TSM 的公平性对照（仅作说明，不入主表）

早期一版曾用"短边 256 + 中心裁剪"的帧（**只保留 56% 画面宽度**）、stride 8 采样且未调 lr，
其 avg_f1 为 0.7083。改用全画面 + stride 1 + 筛选后的 lr 后升到 0.7352
（+0.027，误报率近乎腰斩），但相对 E1-full 的差距仍然存在（−0.094）。
说明**已排除"条件给不够"的解释**，差距来自模型范式本身。

### A.5 已知残留差异（写进论文 limitations）

- 逐帧合并规则不完全一致：E1 用 3 窗口多数投票，参考模型用概率平均；实测影响 ≤0.003（模型差距是 0.09–0.16）。
- 参考模型只跑一套官方配方，未做逐模型调优；本方法经过多阶段迭代。
- 标签实例数对齐时相邻片段高度重叠，对齐的是"标签数"而非"信息量"。

### A.6 学习率调度的敏感性（方法学记录，值得写进论文）

同一模型（X3D-S）在两种预算下的表现**方向相反**：

| epoch | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| T_max=5（固定 5 轮） | 0.703 | 0.720 | 0.736 | 0.743 | **0.747** | — |
| T_max=15（+patience 3） | 0.703 | 0.695 | **0.728** | 0.684 | 0.712 | 0.712（早停） |

机制：余弦调度的长度决定"退火抛光段"落在第几轮——T_max=5 时第 5 轮 LR 已≈0（充分抛光）；
T_max=15 时第 6 轮 LR 仍有 0.0075（是短调度同期的 8.7 倍），模型停在高 LR 的过拟合区就被早停掐断，
**其退火段根本没发生**。因此三点教训：

1. 不能靠"val 还在涨"判断该加轮数——那多半是退火效应，不是没学完；
2. 跨不同调度预算比较模型是不公平的；
3. 若目标是让每个模型各自最优，正确工具是 `ReduceLROnPlateau`（由 val 停滞驱动降 LR），
   但这会让各模型跑不同预算、削弱横向可比性，本阶段不采用。

本阶段执行：**所有参考模型固定 5 epoch + 余弦 T_max=5 + 取 val 最优 checkpoint**。
