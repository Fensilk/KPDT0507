## 0. 为什么有这份增补

两件事在第十一阶段收尾时被发现：

**① §6.3 的选点规则从未被执行，而且它按构造就不完整。**
规划 §6.3 第 2 条原文是「对 val 排序前 3 的 ckpt 各跑一次 test，**在选择规则事先写明的条件下**
选最终模型」——它登记了**流程**，却把**判据内容**推给"以后再写"，而"以后再写"从未发生。
（全文检索：`择一` / `事先写明` 在 `docs/` 内只出现在这句和它的两处转述里。）

**② W2 的判定用的是被 §6.3 明文禁止的口径。**
W2 报出的数字取自 `best_model.pt` = **val 单点极大值**，而 §6.3 第 1 条写的是
「**选型不取单次 val 极值**」。
→ 因此 W2 的判定（`1a` 硬否决 / `4` 强通过但 §7.3 2/5）**不是**符合规划的阶段性判定，
而是**违规执行下的阶段性观察**。它**降级为诊断**（数字完整保留、可查），
**不再作为本阶段的权威判定**。

**③ 实测证据表明这个偏差真的吃掉了结论。** 用 W2 已有的 8 个 ckpt 重算（曲线口径）：

| 臂 | val 选出的 `best` | val 未选中的 `ep1`/`ep2` | 锚点 |
|---|---|---|---|
| `4` | 逐视频 `fall_f1` **0.7325** / `avg_f1` **0.6873**（低于锚点） | ep1 0.8062/0.7684 ｜ **ep2 0.7909/0.7737**（高于锚点） | 0.7827/0.7415 |
| `1a` | 0.7560 / 0.7127（低于锚点） | **ep2 0.8014/0.7635**（高于锚点） | 同上 |

**两条臂上，按 val 选出的那个 ckpt 恰恰是唯一跌破锚点的事件级 ckpt。** 选点噪声不是假说。

| F4 | **排序量** | `val_avg_f1`（沿用规划 §6.3 第 3 条"唯一可跨 ckpt 比较的 val 指标"）；`fallen_prec` 明文**不用于跨 ckpt 比较** |
| F5 | **平滑定义** | **末 k=3 次 val 检查的均值**。§6.3 原文"平滑值**或**末 k 次均值"含糊，此处**只取后者**。<br>⚠ 已实测该定义会出问题：`w2_4` 的平滑极大落在 step 15000，而该点原始 `val_avg_f1` 仅 **0.8578**（原始极大 0.9104 在 13800）——k=3 的窗口横跨了一次崩溃。**该现象如实登记，不改定义**（改了就是事后挪球门） |
| F6 | **候选池** | 每个 run **已存的全部 ckpt**：`best` / `epoch_1..3` / `last`（`last`≡`epoch_3`，去重） |
| F7 | **择一** | 池内平滑值最大者为该 run 的**代表**；并列取 step 更小者 |
| F8 | **对照物** | 锚点 E1-full 的代表由 **F6+F7 同一规则**在其池上选出。**若结果不是它已发表的 `best_model.pt`，如实报告并暂停**，不得擅自替换——那会波及 §7.3 的五个冻结阈值（`fall_prec > 0.6951`、`fall_rec ≥ 0.8205`、逐视频 `fall_f1 > 0.7827`、`fallen_prec ≥ 0.7351`、逐视频 `avg_f1 ≥ 0.7213`） |

### 1.1 F5 的适用性澄清（**补写于作业已启动、第 1 个 ckpt 落盘之时**）

**F5 在新 val 上原本没有定义。** F5 写"末 k=3 次 val 检查的均值"，F7 写"池内**平滑值**最大者"，
这套写法隐含前提是 **val 分数按"检查点"逐点得到**（`monitor.json` 的 48 个点）。
而 step 1 的新 val 是**逐个 ckpt 评**的：池内每个成员只有**一个**新 val 分数，
**不存在"末 3 次检查"可平均**。

**裁定：以 A 为准。**「既然只有一个 val，自然就应该取它」——
即**直接按该 ckpt 的新 val 分数在池内取最大**，不做跨成员平滑。

理由：F5 的平滑当初是为"150 视频 × 逐检查曲线"的噪声设计的；新 val 已把噪声降下来，
且池成员相隔 **9600 步**，跨成员平滑没有物理含义。

**同时并列报告读法 C**（完全按 F5 字面，用**旧 val** 的末 3 次均值择一）**作为对照**——
两种读法都打印，**谁都不用挑**。这样即便两者选出不同的 ckpt，也是如实并列，
而不是"看到谁赢再定规则"。

> **可核查的时间线（记录完整性的一部分）**：本条澄清补写时，作业已完成 **1/12**，
> 落盘的是**锚点 `best_model.pt`**（新 val `val_avg_f1` = 0.8552，旧 val 同 ckpt = 0.9125）。
> 此刻**锚点池内只有 1 个成员有分数**，任何 run 的选点都还**不可能发生**——
> 即本条澄清写在"能看到任何选择结果"之前。
> 另：§4 的 Q1/Q2 因作业已启动，**按默认值冻结**（见 §4）。

显然的池 → 规则给出显然答案（`{a:0.50, b:0.70, c:0.60}` → `b`）。

### 6.2 ② 选点试算与负对照

| run | 读法 A（新 val 取最大，**主判据**） | 读法 C（旧 val 末 k=3 平滑，对照） |

> → 旧 val 不只是"信号弱"，它**系统性地选偏**。这独立地印证了"以 A 为准"是对的。

### 6.4 ④ 剂量-响应 / ④b 覆盖效应

| n（视频数） | 150 | 300 | 600 | 1200 |
|---|---|---|---|---|
| ρ | +0.700 | +0.573 | +0.964 | +0.955 |

**非单调**（300 < 150），且 n=11 中同臂内高度相关 → 这条曲线**只能读方向**：
≥600 明显优，150/300 明显劣，**拐点定不下来**。

| n=1200 的帧覆盖 | ρ |
|---|---|
| 只帧 0–63（模拟旧 val 覆盖） | +0.927 |
| 全帧 0–79 | +0.955 |

**④b：覆盖尾部 16 帧几乎不贡献（+0.028）。** 改善来自**视频数与类配平**，不是覆盖。
这实测复现了本阶段自己的 A1 勘误（"截断只占 ≈11%"）。

### 6.5 结论一：**收束**（不换基准、不重跑）

冻结文档 §2.5 的两个条件同时满足：**ρ 明显转正**（+0.955 vs −0.14）
**且三个 run 在 A 下都仍选各自的 `best_model.pt`**。

→ **对照物不动、§7.3 五个冻结阈值不动、跨阶段对照数字不动、第二步重跑取消。**

**这条正面回答了 W2 遗留的疑问**：选点噪声确实存在（旧 val ρ=−0.14，且它选出的 ckpt
恰好是事件级唯一跌破锚点的那个），**但换成可用的 val 后，选出来还是原来那批 ckpt**。
⇒ **W2 的判定（`1a` §7.3 1/5、`4` 2/5、无一全过）不是"选错点"造成的，结论站得住。**

### 6.6 结论二：**事件轴上仍没有可用的选点信号**（新发现，进 limitations）

新 val 与**帧级** test 几乎完美同序，但与**事件级**指标基本无关、个别还强负相关：

| 逐视频指标 | ρ(新 val, ·) |
|---|---|
| `mean_fallen_as_fall_rate` | **−0.750** |
| `median_fallen_delay` | −0.583 |
| `fallen_detection_rate` | +0.450 |
| `pass_rate` | +0.383 |
| 翻转数（fall / fallen / total） | +0.150 / +0.017 / +0.033 |

而 §7.3 的五项里有**两项是逐视频口径**（③a `fall_f1`、③c `avg_f1`）。

→ 正确表述不是"val 不可靠"，而是：**"帧级 val 挑不出事件级更好的 ckpt"是一个目标错配**，
且它**不是噪声问题**——**事件轴上根本还没有可用的选点信号**。
这比"val 是坏信号"更准，也直接指出下一步该往哪走。
